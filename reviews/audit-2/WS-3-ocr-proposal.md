## 2. Архитектурная реальность → модуль из двух частей

**Ключ:** в Cowork «OCR-движок» = **vision (Read tool агента) по отрендеренным PNG**. Python из скрипта vision вызвать не может. Значит `shared/ocr` — это **две согласованные части**:

1. **Детерминированная Python-нога** — `scripts/extract_text.py` (доработанный): программное извлечение, **детект мусорного слоя**, рендер страниц в PNG (downscale, в песочницу `outputs/`), чтение/запись кэша по `content_hash`, опциональная tesseract-спот-сверка (если вендоренные данные есть). Vision **не делает** — вместо этого **выдаёт директиву** агенту (`needs_vision: true`, какие страницы, почему).
2. **Протокол агентской стороны** — новый `shared/ocr.md`: дерево решений (когда программно достаточно vs когда эскалировать на vision), как Haiku-субагент прогоняет vision по PNG, правила пер-полевого confidence, структурный режим для длинных сканов, семантика кэша. **Все скиллы-потребители ссылаются на этот документ** вместо дублирования прозы.

Это повторяет существующий паттерн `mirror-template.md` (общий документ-контракт) и **закрывает висящую ссылку** conventions:671 на «раздел OCR-модуля».

## 3. Контракт модуля

**Вход:** путь к файлу (PDF / изображение / DOCX / TXT) + `content_hash` (уже посчитан скиллом при ingest).

**Выход (JSON от Python-ноги + директива агенту):**

```
{
  "text": "...",                      # извлечённый текст (если программно)
  "extraction_method": "pdf-text | vision | docx-parse | text-read | structural | cached",
  "confidence": "high | medium | low",
  "pages": N,
  "needs_vision": true | false,       # директива агенту: нужен vision
  "vision_pages": [3, 7, 8],          # какие страницы рендерить (или "all")
  "vision_reason": "no-text-layer | garbage-layer | image | cropped-render",
  "structural_mode": true | false,    # длинный скан → структурное зеркало (F3.4)
  "low_confidence_fields": [],        # заполняется на vision-стороне (F3.5)
  "cache_hit": true | false,          # content_hash совпал → переиспользуем (F3.2)
  "warnings": ["cropped_render: стр. 4 обрезана справа", ...]
}
```

**Агентская сторона (`shared/ocr.md`)** дочитывает директиву: если `needs_vision` — рендерит указанные страницы и прогоняет vision; собирает зеркало; проставляет пер-полевой confidence; пишет кэш.

## 4. Дерево решений извлечения (сердце модуля)

Для каждого файла:

1. **Проверка кэша (F3.2).** Если существует зеркало с тем же `content_hash` и `vision_done: true` → вернуть его текст, `method: cached`. **OCR один раз.** Кэш = само зеркало (отдельного хранилища не вводим).
2. **Ветвление по типу:**
   - **PDF с чистым текстовым слоем** → программно (pymupdf). `needs_vision: false`.
   - **PDF без текстового слоя** (скан) → `needs_vision: true`, `reason: no-text-layer`.
   - **PDF с мусорным текстовым слоем (F3.3)** → детект (см. ниже) → `needs_vision: true`, `reason: garbage-layer`. **Мусор как авторитетный текст не возвращаем.**
   - **Изображение** → `needs_vision: true`, `reason: image`. **Vision основной, не tesseract.**
   - **DOCX / TXT** → программно (без изменений).
3. **Детектор мусорного слоя (F3.3)** — эвристики, которые Python считает на извлечённом тексте, по странице:
   - доля кириллицы среди буквенных символов аномально низкая для русского документа (ориентир < 0.15);
   - высокая доля `�` / управляющих символов / изолированных комбинирующих знаков;
   - «словесная каша»: крайне малая средняя длина токена или абсурдная доля пробелов;
   - на странице есть текст, но `len(stripped)` мизерный при крупных image-XObject (текстовый слой — тонкий OCR-артефакт поверх скана).
   → превышение порога → пометить страницу (или документ) `needs_vision`.
4. **Vision-нога (F3.1, агентская сторона).** Для `needs_vision`-страниц Haiku-субагент: рендерит каждую страницу в downscale-PNG в `outputs/` песочницы (`pdftoppm`/`pdftocairo`, ~1200–1700 px по ширине, **постранично** — правило 4 Cowork-robustness), Read PNG, транскрибирует. **Это основной OCR-путь** — заменяет мёртвый tesseract-rus.
5. **Tesseract спот-сверка (F3.1, вторая нога — ОПЦИОНАЛЬНА, см. §7).** Только для **одного критичного low-dpi поля**, где vision пометил неуверенность (цифра в ИНН/сумме/дате). Кроп региона → маленький PNG → tesseract по кропу (обходит таймаут на целой странице) → сверка с чтением vision: совпало → confidence вверх, разошлось → флаг. Требует вендоренный `rus.traineddata`.
6. **Авто-флаг обрезанного рендера (F3.5).** Render-helper сверяет аспект отрендеренного PNG с аспектом страницы (`page.rect` из pymupdf). Расхождение > допуска → `warnings += cropped_render`, confidence вниз, флаг. Ловит класс «pdftoppm unsafe location → частичный/клиппированный рендер» (F2.11/conventions:706).

## 5. Пять фиксов поимённо

### F3.1 — vision основной (P0)
- Python-нога перестаёт считать tesseract-rus основным путём; вместо тупика выдаёт `needs_vision` с причиной.
- Vision-протокол в `shared/ocr.md` — канонический OCR-путь (рендер → Read → транскрипт).
- **conventions:595** правится: «нет tesseract → vision», а не «нет tesseract → `needs_manual_review`».
- **conventions:575** (таблица зависимостей): tesseract/ocrmypdf переезжают из «OCR сканов» в «**опциональная** спот-сверка», vision помечается основным.

### F3.2 — кэш по `content_hash` (P1)
- Зеркало = кэш. В frontmatter зеркала добавляются `content_hash:` (хэш, с которого извлекали) и `vision_done: true|false`.
- На любом повторе (update-index пересоздаёт зеркало; повторный ingest): если `content_hash` совпал и зеркало не `mirror_stale` → **переиспользовать, не гнать vision заново**. Re-extract только при смене хэша. Vision замораживается на первом извлечении → детерминизм для повторяемости.
- Аддитивно к схеме (поле frontmatter зеркала).

### F3.3 — детект мусорного слоя → авто-vision (P1)
- Детектор §4.3 в Python-ноге. Заменяет бинарный `has_text` на «есть_ли_осмысленный_текст».
- Срабатывание → `needs_vision: true, reason: garbage-layer` (не молчит в `needs_manual_review`).

### F3.4 — структурный режим для длинных сканов (P2)
- Новый санкционированный режим зеркала: для длинного **скана** (`needs_vision` + страниц больше порога, ориентир > 15 скан-страниц) вместо невозможного «полного текста» — **структурное зеркало**: тип документа, стороны, ключевые даты/суммы, скелет заголовков/разделов, наличие подписи/печати, число страниц.
- **Citability сохраняется для головы:** полный текст первых N + подписной страницы; структурный скелет — для массива приложений. `extraction_method: structural`, `completeness: partial`, `needs_manual_review: true` (из структурного зеркала дословно цитировать нельзя).
- `mirror-template.md` получает явный «структурный режим» — чтобы это не было нарушением правила «полный текст». Правило 7 (>50 стр.) переписывается со ссылкой на структурный протокол вместо тупого «первые 10».
- Тип-исключения: документы, которые **обязаны** цитироваться дословно (договор/иск/решение), не уходят в структурный режим целиком — агент полнотекстит ключевые страницы.

### F3.5 — пер-полевой confidence + авто-флаг обрезанного рендера (P2)
- Vision-субагент при транскрипции помечает **критичные реквизиты**, в которых не уверен: ИНН, ОГРН, КПП, суммы, даты, № дела, № документа. Механизм: инлайн-маркер в тексте зеркала (`7707083893[!conf:low]`) + список `low_confidence_fields:` во frontmatter.
- Правило: любой критичный реквизит на низком confidence → `needs_manual_review: true`, и именно этот реквизит получает флаг verify-before-assert (а не «зануляем весь документ»).
- **Разводка дрейфа схемы:** определение `quality` в intake (строки 136) переписывается — убираем фиктивный «OCR confidence ≥ 0.95» (vision чисел не даёт); новый критерий: `extraction_method` + число `[Нечитаемо]` + число low-conf критичных полей. Каноническое определение переезжает в `shared/ocr.md`, intake на него ссылается.
- Авто-флаг обрезанного рендера — §4.6.

## 7. ОТКРЫТОЕ РЕШЕНИЕ — вендоренный `rus.traineddata` (форк)

D8 закрепил «vision + вендоренный tesseract». На реализации всплывает цена: коммит ~5–15 МБ бинарного блоба в git-репо + риск, что в песочнице блоб не выкачать. Три ветки:

- **A (рекомендую) — vision-first MVP, tesseract как опциональный drop-in.** Строим vision-основной + детект-мусора + кэш + структурный + пер-полевой confidence **сейчас** (закрывает F3.1 P0 через vision, F3.2–F3.5). Tesseract-спот-сверка **кодируется, но спящая**: модуль ищет `rus.traineddata` по вендоренному пути `scripts/tessdata/rus.traineddata` ИЛИ по `$VASSAL_TESSDATA`; нет файла → спот-сверка пропускается (vision-only). Инструкция Сюзерену «положить файл позже» — одна строка. **Блоб сейчас не коммитим.** Плюсы: нет распухания репо и проблемы «не скачать в песочнице»; спот-сверка — узкое улучшение, не P0. Архитектура D8 сохранена (нога есть, vision основной), включается автоматически при появлении файла.
- **B — вендорить блоб сейчас.** Закоммитить `tessdata_fast/rus.traineddata` в репо, спот-сверка работает из коробки. Нужен источник: Сюзерен даёт локально ИЛИ я тяну с GitHub `tessdata_fast` (если сеть в песочнице позволит). Тяжелее всего, но сразу закрывает «второе независимое чтение».
- **C — убрать tesseract совсем.** Только vision, ноги спот-сверки нет вовсе. Простейшее; теряем независимую кросс-сверку критичных low-dpi полей. Ревизует D8.

**Моя рекомендация: A** — сохраняет архитектуру D8 без коммита блоба и без блокировки на скачивании; Сюзерен вендорит файл, когда удобно, и нога загорается сама.

## 8. Зоны сверки (для ревью после драфтов)

1. **Реальность vision-пути:** протокол `shared/ocr.md` не предполагает, что Python делает vision; рендер строго постранично в `outputs/` (не в синкаемые папки).
2. **Кэш не ломает обновление:** update-index при **смене** `content_hash` обязан re-vision (иначе застрянет старый текст); при неизменном — переиспользовать.
3. **Структурный режим не режет citability:** договор/иск/решение не уходят в структурное зеркало целиком.
4. **Пер-полевой флаг гранулярен:** один low-conf реквизит не зануляет весь документ, но блокирует дословную цитату именно этого реквизита (стыковка с verify-before-assert conventions:692).
5. **DRY соблюдён:** ни в одном скилле не осталось прозы OCR-пайплайна — только ссылка на `shared/ocr.md`.
6. **Forward-ref закрыт:** conventions:671 теперь указывает на реальный раздел.
