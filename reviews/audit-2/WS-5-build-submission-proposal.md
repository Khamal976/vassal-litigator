**Три дыры (реестр §6 трекера):**

- **F5.1 (P1):** комплект «на подачу» собирается вручную; на реальной сборке всплыли 2 пропущенных приложения (заявлены в перечне — физически отсутствуют). Никто не сверяет перечень с тем, что реально лежит.
- **F5.2:** нет скилла, который читает просительную + перечень приложений → собирает нумерованный комплект → опись → кросс-проверки (файл есть; тип совпадает; суммы бьются; нет осиротевших).
- **F5.3 (P2):** папки «На подачу/» нет ни в одном игнор-списке — без правки её копии всплывут как «новые файлы» в Phase 0 / `update-index` (ложный рассинхрон, риск повторной индексации дублей).

**Ключевой факт контракта:** перечень «Приложения» в **подаваемом** документе (`.docx`) — tag-free (F4.12), а двойные ссылки `[doc-NNN]` живут в **рабочих** артефактах (сводный `.md` в корне / `.vassal/hearings/{дата}-prep.md`). Значит резолвер «пункт перечня → doc-NNN» работает по рабочей версии; где ссылки нет — добор по индексу (заголовок/дата/реквизиты) с подтверждением в Preview.

## 2. Назначение и граница скилла

**Делает:** берёт готовый процессуальный документ (продукт `prepare-hearing` / `appeal` / `cassation` / `settlement`) → разбирает его просительную и перечень приложений → **сверяет «заявлено vs вложено»** (вбирает F4.2) → собирает физический нумерованный комплект в «На подачу/{дата} {сторона} - {действие}/» → генерирует **опись** (`.md` + `.docx`) → помечает приложения-участники в индексе (`filing_status`).

**НЕ делает (граница):**
- Не пишет текст процессуального документа и не считает госпошлину/суммы требований — это `prepare-hearing`/`appeal`/`cassation`/`settlement`. build-submission только **сверяет**, что заявленное обеспечено вложенным.
- Не перепроверяет право (D3).
- Не подаёт в суд (нет интеграции «Мой арбитр»); финальная подача — рукой Сюзерена.
- Не правит перечень приложений в самом документе — при расхождении **флагует**, возврат в `prepare-hearing`/`appeal`/`cassation`.

## 3. Контракт скилла

**Вход:**
- Целевой процессуальный документ — путь в `$ARGUMENTS` **или** автодетект последнего процессуального продукта в корне дела (по таблице «Продукты плагина») **или** переспрос, если кандидатов несколько.
- `.vassal/index.yaml` + зеркала (резолв `[doc-NNN]` → файл, тип, `pages`, `content_hash`, реквизиты).
- Рабочий артефакт с тегами (сводный `.md` / `{дата}-prep.md`) — для резолва перечня в `doc-NNN`.

**Выход:**
- `На подачу/{ГГГГ-ММ-ДД} {Сторона} - {действие}/` — нумерованный комплект с **самоописывающими именами** `NN Наименование от ГГГГ-ММ-ДД Nл.ext`:
  - `00 {тип документа} {N}л.docx` — само подаваемое заявление (tag-free; копия готового продукта),
  - `01 …`, `02 …` — приложения в порядке перечня (`NN` ↔ приложение №NN).
  - Отдельного файла-описи **нет** — папка с такими именами и есть опись (решение Сюзерена, §5).
- `.vassal/submissions/{ГГГГ-ММ-ДД}-{действие}.md` — машинно-читаемый манифест комплекта (`main_doc` + `refs:[doc-NNN]` приложений + результат кросс-проверок). **Источник истины о составе подачи** (двухуровневое сохранение). Папка `.vassal/submissions/` создаётся build-submission лениво.
- (Опционально, B5) `index.yaml`: **главному документу** — `filing_status: draft`. Приложения в индексе **не** помечаем: одно приложение входит в много подач — членство держим в манифесте, не в скалярном поле дока.
- Запись в `.vassal/history.md`.

### 3.1 Многократная подача и жизненный цикл (ответ на вопрос Сюзерена)

За время дела подаётся **много** документов (даже в одной инстанции: отзыв → ходатайства → дополнения → …). Дизайн держит это так:

- **«На подачу/» — контейнер, не одна папка.** Каждая подача = свой датированный подкаталог `{ГГГГ-ММ-ДД} {Сторона} - {действие}/` (зеркалит [conventions.md:40](../../shared/conventions.md)). Несколько подач → несколько подкаталогов, хронологически; смена инстанции видна по датам, отдельной вложенности по инстанциям не вводим.
- **Это staging, а не архив.** «На подачу/» держит комплекты, **готовые-но-ещё-не-поданные**. Канонический экземпляр поданного документа остаётся в деле (продукт в корне + последующий intake входящего судебного акта). После фактической подачи подкаталог «отработан» → чистится вручную (как «На удаление/»), не копится бесконечно.
- **Общие приложения.** Одна доверенность/платёжка прикладывается к разным подачам → один `doc-NNN` входит в несколько комплектов. Поэтому членство — в **манифестах** `.vassal/submissions/…` (join-таблица), а не в скалярном `filing_folder` дока.
- **Жизненный цикл `filing_status`:** `draft` (собран build-submission) → `submitted` (Сюзерен подал) → `filed` (принят / в деле). build-submission ставит только `draft` и только главному документу (если он в индексе); продвижение — вручную/будущим шагом. `update-index` уже защищает `submitted\|filed` от удаления.

## 4. Алгоритм по фазам

### Фаза 0 — Консистентность ФС ↔ индекс
Переиспользуем общий Phase 0 ([conventions.md:633-678](../../shared/conventions.md)). **Правка F5.3:** «На подачу/» добавляется в игнор-список Phase 0, иначе ранее собранные комплекты всплывут как `new_files`.

### Фаза 1 — Определение целевого документа и загрузка контекста
1. Определи подаваемый документ: `$ARGUMENTS` → иначе последний процессуальный продукт в корне (`{дата} {тип}.md`/`.docx`) → иначе спроси (список кандидатов).
2. Прочитай `case.yaml` (профиль, сторона-клиент, номер дела), `index.yaml`.
3. Прочитай рабочую версию документа (с `[doc-NNN]`, если есть — сводный `.md` / prep-артефакт) **и** подаваемую (`.docx`/tag-free `.md`) — первая для резолва, вторая как источник «что заявлено».

### Фаза 2 — Разбор перечня и резолв в `doc-NNN`
4. Извлеки из блока «Приложения» структурированный список: `{ № п/п, наименование, дата, реквизиты (№ для платёжек), кол-во экз./листов если указано }`.
5. Реши каждый пункт в `doc-NNN`:
   - есть `[doc-NNN]` в рабочей версии → берём напрямую;
   - нет → добор по индексу (Haiku-субагент: совпадение по типу+дате+реквизитам/заголовку) → кандидат с пометкой «требует подтверждения».
6. Из просительной части извлеки заявленные **итоги и единицы** (суммы; «N платёжных поручений на сумму X») — вход для F4.2.

### Фаза 3 — Кросс-проверки полноты (реализация F4.2 + правило 5 conventions:712)
Для каждого пункта перечня и для пакета в целом:

| Проверка | Что сверяется | Расхождение → |
|---|---|---|
| **Наличие файла** | каждый пункт перечня имеет резолв в `doc-NNN` и **файл существует на диске** | ⚠ «приложение заявлено, файл не найден» |
| **Соответствие типа** | `type`/`title` зеркала соответствует наименованию в перечне | ⚠ «тип не совпадает» |
| **Число единиц** | заявлено «N платёжек» — фактически N файлов/записей | ⚠ + точное расхождение (как в F4.2: «заявлено 10, вложено 9») |
| **Суммы (пересчёт)** | сумма реквизитов единиц (из зеркал) = заявленный итог в просительной | ⚠ «суммы не бьются: Σ единиц = A, заявлено B» |
| **Осиротевшие** | `[doc-NNN]`, упомянутые в теле, но **не** попавшие в перечень приложений; и наоборот | ⚠ «упомянут в тексте, нет в приложениях» |
| **Блокировка качества** | ни один участник не имеет `needs_manual_review: true` без OCR-сверки (правило 4 conventions:711) | ⚠ «зеркало не сверено — не подавать как источник реквизитов» |

**Семантика (B7, решено):** расхождение → `needs_manual_review` на комплекте + явный флаг Сюзерену; **комплект всё равно собирается** (пометки `⚠`, блокировки нет). Это прямое следствие боевого F4.2 (выдуманный платёж, неверное число ПП).

### Фаза 4 — Preview
7. Покажи Сюзерену:
   - целевой документ + куда соберём (путь папки);
   - таблицу комплекта (№, имя файла как ляжет, `doc-NNN`, статус ✓/⚠);
   - **итог кросс-проверок** (число пройдено/флагов; сумма-сверка; осиротевшие);
   - манифест подачи + (опц. B5) `filing_status: draft` главному документу.
8. **Нет приложений** → собрать комплект из одного документа по подтверждению (не ошибка). Расхождения не блокируют (B7) — только флаги в отчёте.
9. Дождись подтверждения.

### Фаза 5 — Apply (под backup)
10. **Backup индекса** — только если включена запись `filing_status` (B5); техника как [update-index/SKILL.md:73-86](../../skills/update-index/SKILL.md) (`.vassal/index.yaml.bak.{таймстамп}`, ротация 5). Без записи в индекс backup не нужен — комплект и манифест в индекс не пишут.
11. Создай `На подачу/{ГГГГ-ММ-ДД} {Сторона} - {действие}/`. Идемпотентность: если папка есть — старую версию `mv` в «На удаление/» (не перезапись).
12. Скопируй файлы (`cp`) с **самоописывающими именами** `NN Наименование от ГГГГ-ММ-ДД Nл.ext` (§5); `00 {тип} {N}л.docx` — само заявление. Перед массовым `cp` — `df` (F2.13), после — read-back размера (правило 1 robustness). `cp` в новый файл «На подачу/» (не занят); занят может быть только **исходный** продукт-`.docx` — ретрай чтения, при неустранимом собрать `00` из `.md`. Отдельной описи не генерируем — имена файлов её заменяют.
13. Сохрани манифест `.vassal/submissions/{дата}-{действие}.md` (frontmatter `type: submission`, `main_doc`, `refs: [doc-NNN…]`, `related_summary`, результат проверок) — **источник истины о составе**. Опционально (B5): главному документу в индексе — `filing_status: draft` (приложения не помечаем — см. §3.1).
14. Запись в `.vassal/history.md`.

### Фаза 5.5 — Rollback при сбое
Восстановить индекс из backup; частично собранную папку `mv` в «На удаление/»; сообщить.

### Фаза 6 — Постусловия (верификация после apply)
- Каждый пункт перечня приложений имеет файл в папке; нумерация сплошная (`00`=документ, далее `01..NN`), без дыр.
- Имена файлов самоописывающие; где листаж неизвестен — без `Nл` + пометка в манифесте.
- `index.yaml` — валидный YAML по схеме; нет дублей; `filing_folder` указывает на существующую папку.
- Манифест `.vassal/submissions/…` создан; backup существует.

## 5. Наименование файлов в комплекте (решение Сюзерена 2026-06-16)

Отдельный документ-опись **не создаётся** — комплект самоописывается именами файлов: папка с такими именами и есть опись. (Сюзерен: «если о наименовании файлов — имя должно опознавать документ и число страниц», образец `Накладная 245 от 02032009 3л.pdf`.)

Шаблон: **`NN Наименование от ГГГГ-ММ-ДД Nл.ext`**
- `NN` — порядковый номер: `00` = сам документ, `01..NN` = приложения в порядке перечня «Приложения» (сверка 1:1).
- `Наименование` — тип + № если есть («Платёжное поручение №47», «Доверенность»).
- `от ГГГГ-ММ-ДД` — дата документа, формат **как везде в плагине** (решение Сюзерена); нет даты → опустить.
- `Nл` — листаж из `pages` зеркала; неизвестно (структурное/нет зеркала) → опустить `Nл` + пометить в манифесте.

Пример: `02 Платёжное поручение №47 от 2026-05-12 1л.pdf`.

Почтовая опись вложения (Форма 107) — **не делаем** (решение Сюзерена). Перечень приложений внутри самого документа (только наименования) — зона `prepare-hearing`/`appeal`/`cassation`, не build-submission.

## 8. Решения под approve

> Паттерн «детальная структура → approve → реализация». Где есть рекомендация — она первой.

- **B1. Физический комплект vs манифест.** ▶ *Рекоменд.:* физические нумерованные копии в «На подачу/» (F5.2 прямо требует «нумерованный комплект»). Папка — намеренный deliverable, в игнор-списках, чистится Сюзереном вручную. Альтернатива: только опись+указатели (легче по диску, но юрист не получает готовую папку).
- **B2. Структура папки.** ✅ `На подачу/{ГГГГ-ММ-ДД} {Сторона} - {действие}/` с `00 {тип} Nл.docx` + `01..NN` (самоописывающие имена, §5). Без отдельного файла-описи. (Зеркалит процфолдеры conventions:40.)
- **B3. Источник целевого документа.** ▶ автодетект последнего процессуального продукта + подтверждение; `$ARGUMENTS` — override; переспрос при неоднозначности.
- **B4. Опись → имена файлов.** ✅ *Решено (Сюзерен 2026-06-16):* отдельной описи нет; файлы самоописываются `NN Наименование от ГГГГ-ММ-ДД Nл.ext` (с номером; дата как в плагине; нет листажа → пометка). Почтовая опись (Форма 107) не нужна. Зависимость `arbitrum-docx` из скилла уходит (docx не генерируем).
- **B5. Где источник истины о составе подачи.** ▶ *Рекоменд.* (уточнено после вопроса о многократной подаче, §3.1): **манифест `.vassal/submissions/…`** — держит `main_doc` + `refs:[doc-NNN]` + результат проверок. Приложения в индексе **не** помечаем (одно приложение → много подач, скаляр `filing_folder` ломается). `filing_status: draft` — опционально и только главному документу, если он индексирован (часто N/A: продукт ещё не в индексе). Так не плодим churn индекса и решаем общие приложения. Альтернатива: `filing_folder` как список на доке (сложнее, дублирует манифест).
- **B6. Создание «На подачу/».** ▶ *Рекоменд.:* лениво самим build-submission (как процфолдеры), но в игнор-списки — проактивно. Альтернатива: пре-создавать в `init-case` (видимость папки с порога).
- **B7. Поведение при расхождении «заявлено vs вложено».** ✅ *Решено (Сюзерен 2026-06-16):* комплект **всегда собирается**; расхождения только помечаются (`⚠` + `needs_manual_review`), отчёт Preview перечисляет все флаги. Блокировки нет — решение за Сюзереном.
- **B8. Надёжность копирования.** ▶ `cp` + `df` до + read-back после. Цель — новый файл в «На подачу/» (не занят); занят может быть только исходный продукт — ретрай чтения, при неустранимом собрать `00` из `.md`.
- **B9. Версия/доки.** ▶ bump `0.7.0` + CHANGELOG в составе WS-5; счётчик скиллов в README/ARCHITECTURE — оставить WS-7 (F7.1).
