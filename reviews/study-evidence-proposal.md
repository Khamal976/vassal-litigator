## Назначение
Глубокое чтение и сверка **фактуры доказательств** → кэшируемое «фактологическое досье», которое читают нижестоящие скиллы. Заполняет разрыв между `intake` (приём/OCR/каталог) и `legal-review`/`build-position` (право, стратегия). Прямо закрывает E.3: сейчас позиции бывают поверхностными, ссылки на доказательства отсутствуют — досье даёт фактуру со ссылкой на лист/документ.

## Место в пайплайне
`intake` → **`study-evidence`** → `legal-review` / `build-position` / `prepare-hearing` / `appeal` / `cassation` / `settlement` / `draft-judgment` / карта доводов (E.11).
Опциональный хук: нижестоящий скилл запускается без досье → предложить прогнать `study-evidence`.

## Категория / протокол
Аналитический (категория 2 по `conventions.md`). `preview → apply`. Двухуровневое сохранение (человеку — сводный md, агенту — машинные секции). `verify-before-assert` как ядро.

## Триггеры / анти-триггеры
- **Триггеры:** «изучи/разбери/исследуй доказательства», «собери фактуру», «что в документах по делу», «проверь факты по делу».
- **Анти-триггеры:** НЕ приём файлов (`intake`), НЕ право/сроки/подсудность (`legal-review`), НЕ стратегия/аргументация (`build-position`). Кредо — **факты и их достоверность**, не право и не тактика.

## Вход
`case.yaml` (стороны, суммы, стадия), `index.yaml` + зеркала, оригиналы ключевых документов.

## Фазы
0. **Pre-flight:** есть `.vassal/`, индекс не пуст.
1. **Авто-определение ядра + подтверждение Сюзереном** [Q2]: скилл сам предлагает ядро спора (по типу документа — договор / иск / жалоба / решение / первичка — + сумма + связи), показывает список «читаю полнотекстно: … ; остальное по зеркалу», Сюзерен правит/подтверждает (elicitation-форма).
2. **Глубокое чтение ядра:** полнотекст (не summary); транскрипт-дисциплина E.13 (дословно; скан → vision по `ocr.md`; флаг `completeness`); извлечение фактов **со ссылкой на лист/страницу**.
3. **Кросс-сверка** (`verify-before-assert`): суммы (пересчёт + контрольная сумма E.13), реквизиты (ИНН / даты / номера across документов), роли (кто есть кто), хронология; расхождения → флаги. Практику НЕ трогаем (это `legal-review`/`build-position`).
4. **Подъём «зарытых» фактов** из глубины больших документов (решающий факт со стр. 193, который сводки пропускают).
5. **Preview** досье.
6. **Apply:** сохранение + `history` + кэш/дельта.

## Формат досье [Q3 — человекочитаемая проза по документам]
Основа — **проза по каждому ключевому доказательству**:

> ### [doc-NNN] «Название» (тип, дата) — л. X–Y
> **Что нашёл:** факты, суммы, даты, роли, обязательства — каждый с (л. N).
> **Оговорки:** качество / `needs_manual_review` / что нечитаемо.

Затем — **сводная сверка по узлам спора** + **список расхождений/флагов** (реквизиты / суммы / роли / даты).
Опционально — **машинный `frontmatter`** (`facts[]`, `discrepancies[]`, `sources[]`) для нижестоящих скиллов; но человеческая проза первична (Сюзерен читает per-document, что найдено).
Файл: `.vassal/analysis/evidence-dossier.md` (+ машинные секции по образцу двухуровневого сохранения).

## Кэш и инвалидация [Q4]
- Досье фиксирует по каждому источнику `doc-NNN` его `content_hash` (индекс уже хранит).
- Повторный прогон: сверить текущий `content_hash` каждого источника с записанным → изменился (док перезалит/правлен) → перечитать только его; не изменился → взять кэш. Детерминированно, дёшево.
- Новые доказательства (intake добавил `doc-NNN`, нет в досье) → прочитать только новые, дельта-аппенд (supersedes-цепочка как в `build-position`).
- `--refresh` — форс полного перечтения.
- Стык с **E.2**: при обратном распространении правок (`revise-position`) досье — один из analysis-файлов, помечаемых устаревшими; глубже — в рамках E.2.

## Схема [Q5 — файл-по-конвенции, без миграции]
MVP: **без нового обязательного поля** `case-schema`. Досье — файл по конвенции `.vassal/analysis/evidence-dossier.md`; нижестоящие ищут по конвенции (как прочие analysis-файлы); статус — во `frontmatter` самого досье. Так обходим трение schema-миграций (видно в тестах: `production_type` рассинхрон SKILL↔схема).
Опционально позже: `case.evidence_studied` (дата + версия досье + снимок хешей источников) — если понадобится статус-трекинг.

## Границы
Не принимает файлы (`intake`), не квалифицирует право (`legal-review`), не строит стратегию (`build-position`). Только факты + их достоверность. Для банкротных убытков/субсидиарки фактура-состав — ядро выхода ([[feedback_bankruptcy_docs_delta]]).
