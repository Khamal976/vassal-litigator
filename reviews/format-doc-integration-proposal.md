# E.1 ч.2 — Интеграция `format-doc` в пайплайн (locked design)

**Дата:** 2026-07-05 · **Статус:** approved Сюзереном, в реализации · **Версия:** 0.10.0 → **0.11.0**
**Родитель:** OPEN-ITEMS §E **E.1**. Первая фаза (standalone `format-doc`) закрыта v0.10.0; это **вторая фаза** — подключение готового скилла к пайплайну взамен feature-detection `arbitrum-docx`.

---

## Локнутые решения (из диалога approve)

1. **Late-binding `.docx` (Вариант 1).** `.docx` рождается **только в двух точках**: `prepare-hearing` (документ к заседанию) и `build-submission` (сборка на подачу, **из финального подаваемого `.md`**). До них — только `.md`. Причина: убирает риск подать **устаревший** `.docx` (прямо закрывает боль E.2 «правки не доходят до памяти дела» и E.4 «build-submission собрал старый набор»). `.docx`, напечатанный в момент сборки, не может отстать от правок.

2. **`appeal` / `cassation` / `settlement`** — выдают **только подаваемый `.md`** (tag-free, по якорному контракту `format-doc`). Их фаза «Оформление в .docx» → «документ готов в `.md`; `.docx` печатается на `build-submission` (или вручную `/format-doc`)». **Без вызова движка** в самом скилле.

3. **`build-submission` — основной хост `format-doc`.** В слоте `00` (само подаваемое заявление): если подаваемый документ пришёл как `.md` (нет `.docx`) → **печать `.docx` через `format-doc`** из финального `.md` (заменяет нынешний отбой «оформление делается в скилле-генераторе», `build-submission/SKILL.md` строка 147). Если `.docx` уже есть (напр. от `prepare-hearing`) → копия как сейчас.

4. **`prepare-hearing`** — **остаётся хостом**: печатает `.docx` через `format-doc` (замена блока feature-detection `arbitrum-docx` в Фазе 6). Это документ, который юрист берёт на заседание и читает заранее.

5. **`analyze-hearing` → «замечания на протокол»** — **включены** (Тип 1, процессуальный с шапкой, ПРОШУ; критичный 5-дневный срок ст. 155 АПК / 231 ГПК). Скилл эмитит `.md`; `.docx` печатается на `build-submission` или вручную `/format-doc`. Новый `--type замечания-на-протокол` в `format-doc` + структура в `style-spec.md §2`. **«Отчёт клиенту»** (Тип 2, аналитический, не судебный документ) — **вне `format-doc`**, прежний путь (arbitrum-docx опц. / `.md`).

6. **`settlement` / мировое соглашение** — двусторонний документ на подпись; `format-doc` не покрывает **даже на `build-submission`**. При сборке слот `00` для мирового → `.md` + предупреждение (arbitrum-docx опц.). Ходатайство об утверждении / отказ / признание — обычные процессуальные, печатаются на подаче штатно.

7. **`draft-judgment`** — отложен (проект судебного акта: вводная/описательная/мотивировочная/резолютивная — иная структура). Пометка в OPEN-ITEMS.

8. **Порядок движков (DRY, `conventions.md` → «Внешние зависимости и fallback»):** `format-doc` (проверка `python-docx`) — **основной** → `arbitrum-docx` — **опциональная** альтернатива (если установлен и Сюзерен предпочитает) → `.md`-only — **терминальный** fallback. Шаблон предупреждения теперь про отсутствие `python-docx`, а не `arbitrum-docx`.

## `--type` маппинг (язык `arbitrum-docx` «Тип N» → `format-doc --type`)

| Скилл | Документ | `--type` |
|---|---|---|
| prepare-hearing | отзыв / ходатайство / заявление / возражение / пояснения | по документу |
| appeal | апелляционная жалоба | `жалоба` |
| cassation | кассационная жалоба (вкл. на определение) | `жалоба` |
| settlement | ходатайство об утверждении мирового | `ходатайство` |
| settlement | отказ от иска / признание иска | `заявление` |
| settlement | **мировое соглашение** | — (двусторонний, вне format-doc) |
| analyze-hearing | замечания на протокол | `замечания-на-протокол` (новый) |
| analyze-hearing | отчёт клиенту | — (Тип 2, вне format-doc) |

## Зоны сверки для ревью Сюзерена

- **A.** `.docx` рождается **только** на `prepare-hearing` и `build-submission`; `appeal`/`cassation`/`settlement` отдают `.md`.
- **B.** `build-submission` печатает слот `00` из **финального** `.md` (не копирует старьё); мировое — исключение (`.md` + предупреждение).
- **C.** Порядок fallback (`format-doc` → arbitrum-docx опц. → `.md`) идентичен в `conventions.md` и во всех хостах.
- **D.** `--type` маппинг верен; мировое не уходит в `format-doc`; замечания на протокол = новый `--type`.
- **E.** Постусловия/`history`-поля движко-нейтральны; не осталось «arbitrum-docx как основной путь».
- **F.** Правовой слой не тронут (нормы/сроки/структуры документов — как были).
