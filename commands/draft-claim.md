# draft-claim -- Досудебная претензия / ответ на претензию

Когда пользователь запускает эту команду с "$ARGUMENTS":

1. Прочитай скилл `skills/draft-claim/SKILL.md` и следуй его инструкциям.
2. Если `$ARGUMENTS` содержит данные о режиме (претензия / ответ на претензию), адресате, существе нарушения, сумме, сроке для добровольного исполнения, пути к входящей претензии, особых указаниях — извлеки их и используй как стартовые ответы на фазу «Входные данные» (не переспрашивай уже данное).
3. Если аргументов нет или данные неполные — собери недостающее (см. SKILL.md → «Входные данные от Сюзерена»: `mode`, существо нарушения, адресат(ы), срок для добровольного исполнения, особые указания).
4. Выполни полный pipeline из SKILL.md: фаза 0 pre-flight (Phase 0 ФС↔индекс, резолв `$VASSAL_GLOBAL_DIR`, проверка ранее направленной претензии, сигналы «банкротство» и «финансовые услуги») → фаза 1 загрузка контекста → фаза 2 правовая квалификация (Opus) → фаза 3 расчёт суммы → фаза 4 red team отдельным Opus-субагентом → фаза 5 генерация текста → фаза 6 оформление через `format-doc --type претензия` → фаза 7 обновление `case.pretrial` и сводка.
5. **Не проставляй `pretrial_date` автоматически.** Дата фактического направления вносится отдельным микро-шагом, когда отправка состоялась, — из сообщения Сюзерена либо из квитанции / описи / отчёта об отслеживании, принятых во «Входящие документы/».
6. Если из "$ARGUMENTS" следует, что претензия **уже направлена** (Сюзерен называет дату отправки, трек-номер, прикладывает квитанцию), — не запускай генерацию заново: выполни микро-шаг «претензия направлена» (SKILL.md → одноимённый раздел), рассчитай `claim_ready_date` и срок приостановления исковой давности, обнови `case.pretrial`.
