# Шаблон MD-зеркала

MD-зеркало — это полнотекстовое markdown-представление документа дела (или **структурное** — для длинных сканов, см. [`shared/ocr.md` §5](ocr.md)). Хранится в `.vassal/mirrors/{id}.md`. Это кэш извлечённого текста для экономии токенов, а не замена юридически значимого оригинала. Извлечение текста — по протоколу [`shared/ocr.md`](ocr.md) (vision основной; кэш по `content_hash`).

## Формат

```markdown
---
id: doc-001
source: "Материалы от клиента/Договоры/2025-06-01 ООО Ромашка Договор поставки №47.pdf"
type: договор
title: "Договор поставки №47"
date: 2025-06-01
pages: 12
extraction_method: pdf-text
extraction_model: haiku
extraction_date: 2026-03-26
confidence: high
content_hash: "sha256:3a1f…"     # хэш содержимого — ключ кэша OCR (vision один раз; shared/ocr.md §4)
vision_done: false                # true → vision выполнен для этого content_hash, переиспользовать
low_confidence_fields: []         # критичные реквизиты с низким confidence (shared/ocr.md §7)
completeness: full                # full | partial | fragment (shared/ocr.md §7)
quality: high                     # high | medium | low (shared/ocr.md §7)
needs_manual_review: false        # true при quality: low, структурном режиме, обрезанном рендере,
                                  #   low-conf критичном поле или расхождении двух чтений (F.18)
decisive: false                   # решающий документ — критичные поля читаются дважды (ocr.md §3.2)
verified_fields: []               # поля, РЕАЛЬНО прошедшие второе чтение; пусто при decisive: true
                                  #   = проверка не выполнялась, а не «выполнена и чисто»
---

# Договор поставки №47

## от 01 июня 2025 года

[Полный текст документа...]

---
<!-- EXTRACTION NOTES -->
<!-- Страница 7: таблица извлечена приблизительно -->
```

## Поля frontmatter

| Поле | Обязательное | Описание |
|------|-------------|----------|
| id | да | ID документа (doc-NNN), совпадает с index.yaml |
| source | да | Путь к оригиналу (от корня папки дела) |
| type | да | Тип документа (из таксономии) |
| title | да | Название документа |
| date | нет | Дата документа |
| pages | нет | Количество страниц |
| extraction_method | да | pdf-text, pdf-text+vision, vision, structural, table-structure, docx-parse, text-read, manual (см. [`shared/ocr.md`](ocr.md)) |
| extraction_model | нет | Модель, выполнившая извлечение: `haiku` / `sonnet` / `opus` — **фактическая** модель, не подменять (E.10; если извлекал Opus-агент напрямую — пиши `opus`, не `sonnet`) |
| extraction_date | да | Дата создания зеркала |
| confidence | да | high, medium, low |
| content_hash | да | `sha256:<hex>` содержимого — ключ кэша OCR (vision один раз; [`shared/ocr.md` §4](ocr.md)) |
| vision_done | нет | true → vision выполнен для этого `content_hash`; повтор переиспользует зеркало |
| low_confidence_fields | нет | список критичных реквизитов с низким confidence ([`shared/ocr.md` §7](ocr.md)) |
| completeness | нет | `full` / `partial` / `fragment` — критерий [`shared/ocr.md` §7](ocr.md) |
| quality | нет | `high` / `medium` / `low` — критерий [`shared/ocr.md` §7](ocr.md) |
| needs_manual_review | нет | `true` при `quality: low`, структурном режиме, обрезанном рендере, low-conf критичном поле или расхождении двух чтений (F.18) |
| decisive | нет | `true` → решающий документ: критичные поля перечитывает вторая, независимая голова ([`shared/ocr.md` §3.2](ocr.md)) |
| verified_fields | нет | поля, **реально** прошедшие второе чтение (+ вердикт). Пусто при `decisive: true` = проверка не выполнялась |

> **Почему эти поля перечислены здесь (F.18, смежная находка).** `shared/ocr.md` §5/§7 требует
> писать `completeness` / `quality` / `needs_manual_review` во frontmatter зеркала, а таблица
> шаблона их не называла — расхождение протокола и шаблона. Те же поля дублируются в записи
> `index.yaml` (`shared/index-schema.yaml`): зеркало — источник, индекс — реестр для поиска.

## Правила создания

1. **Полный текст** — весь текст переносится с сохранением структуры (заголовки, пункты, таблицы)
2. **Таблицы** → markdown-таблицы
3. **Изображения** → `[Изображение: описание]`
4. **Нечитаемые фрагменты** → `[Нечитаемо: описание проблемы]` — **не** реконструкция по смыслу (дисциплина дословности, [`shared/ocr.md` §3.1](ocr.md))
5. **HTML-комментарии** — только технические пометки о качестве извлечения
6. **Юридические выводы** — НЕ помещать в зеркало (место для них — `.vassal/analysis/` и позиции `{корень}/*позиция.md`). В частности (E.13, [`shared/ocr.md` §3.1](ocr.md)): не назначать правовые роли сторон (кто должник/кредитор/АУ — это `study-evidence`) и не добавлять ссылки на нормы/практику, которых нет в тексте документа
7. **Длинные документы / сканы** — для длинных **сканов** действует структурный режим (полнотекст головы + подписной страницы + структурный скелет; `extraction_method: structural`, `completeness: partial`, `needs_manual_review: true`) — см. [`shared/ocr.md` §5](ocr.md). Для длинных **текстовых** PDF (>50 стр.) — извлечь первые 10, пометить `[... документ содержит N страниц, извлечены первые 10 ...]`. **Опорные документы** (договор, иск, решение, постановление) полнотекстятся даже если длинные — в структурный режим целиком не уходят.
8. **Таблицы (`.xlsx`/`.xlsm`/крупный `.csv`)** — исключение из правила 1: полное тело в зеркало не переносится (в выписке бывает 12 000 строк). Идёт **структурная сводка** — `extraction_method: table-structure`, `completeness: partial`, `needs_manual_review: false`; см. [`shared/ocr.md` §5а](ocr.md). Правило 2 при этом действует в полную силу: сводка выводится **markdown-таблицами с номерами строк файла**, позиции колонок не сдвигаются (пустая ячейка — пустая колонка, иначе списание встанет на место прихода). Показанные значения точны и цитируемы; всё, чего в сводке нет, поднимает `study-evidence` через `analyze_table.py`, а не додумывает читатель.

## Методы извлечения (extraction_method)

- `pdf-text` — PDF с текстовым слоем, извлечён программно
- `vision` — скан / изображение / мусорный текстовый слой распознан через **vision** (Read tool по PNG); основной путь OCR (см. [`shared/ocr.md`](ocr.md))
- `pdf-text+vision` — гибрид: часть страниц программно, часть через vision
- `structural` — длинный скан: полнотекст головы + структурный скелет ([`shared/ocr.md` §5](ocr.md))
- `table-structure` — таблица (`.xlsx`/`.xlsm`/крупный `.csv`): скелет — листы, шапки с номерами строк, первые строки, итоговые строки, скрытые листы ([`shared/ocr.md` §5а](ocr.md)). **Неполно, но точно:** значения прочитаны машинно, поэтому, в отличие от `structural`, `needs_manual_review` не ставится, а показанные значения цитировать **можно**. Суммы по всему массиву — `study-evidence` (`analyze_table.py`)
- `docx-parse` — извлечён из .docx через python-docx или Read tool
- `text-read` — текстовый файл прочитан напрямую
- `manual` — текст введён вручную

> Старые методы `ocr` / `image-read` поглощены значением `vision` (vision и есть OCR в Cowork). Существующие зеркала с этими метками не переписываем — при перегенерации метод станет `vision`.

## Уровни уверенности (confidence)

- `high` — текст извлечён чисто, структура сохранена
- `medium` — есть мелкие артефакты, но текст читаем
- `low` — существенные проблемы, требуется ручная проверка (ставь `needs_manual_review: true` в индексе)

Это уверенность **документного уровня**. Пер-полевой confidence для критичных реквизитов
(ИНН, суммы, даты) и точные критерии поля `quality` — в [`shared/ocr.md` §7](ocr.md). Значение
`pending-vision` (из вывода `extract_text.py`) — техническое, переходное: финальный `confidence`
ставит агент **после** vision, в зеркало `pending-vision` не пишется.
