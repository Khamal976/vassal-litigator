# OCR-модуль `shared/ocr` (контракт + агентский протокол)

Единый источник правды по извлечению текста из документов дела. Все скиллы, создающие
md-зеркала (`intake`, `add-evidence`, `add-opponent`, `update-index`), извлекают текст
**только по этому протоколу** — прозу OCR-пайплайна в скиллах не дублируем.

## Принцип

В Cowork «OCR-движок» — это **vision (Read tool агента) по отрендеренным PNG**, а не
системный tesseract (рус. данных в песочнице нет; tesseract упирается в таймаут даже на
1 стр. 300 dpi). Поэтому модуль состоит из **двух согласованных частей**:

1. **Детерминированная Python-нога** — [`scripts/extract_text.py`](../scripts/extract_text.py).
   Делает программное извлечение, детект мусорного текстового слоя, рендер страниц в PNG,
   вычисление `content_hash`, опциональную tesseract спот-сверку одного поля. **Vision не
   выполняет** — выдаёт директиву агенту (`needs_vision`, какие страницы, почему).
2. **Агентская сторона (этот документ)** — Haiku-субагент дочитывает директиву: рендерит
   нужные страницы, читает их через Read tool (vision), транскрибирует, проставляет
   пер-полевой confidence, собирает зеркало, пишет кэш.

**Vision — основной путь OCR.** Tesseract — только опциональная спот-сверка одиночного
критичного поля (см. §6).

## §1. Контракт (выход Python-ноги)

`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/extract_text.py <файл> [--output-dir DIR]` → JSON:

| Поле | Значение |
|---|---|
| `text` | извлечённый текст; для vision-страниц — плейсхолдер `[[VISION_PAGE N: scan\|garbage]]` |
| `method` | `pdf-text` · `pdf-text+vision` · `vision` · `docx-parse` · `text-read` · `none` |
| `confidence` | `high` · `medium` · `low` · `pending-vision` (ставит агент после vision) |
| `pages` | число страниц |
| `page_statuses` | по странице: `text` · `garbage` · `scan` · `blank` (только PDF) |
| `needs_vision` | `true` → агент обязан прогнать vision |
| `vision_pages` | страницы под vision (1-based) |
| `vision_pages_suggested` | то же, но в структурном режиме — урезано до головы + подписной |
| `vision_reason` | `no-text-layer` · `garbage-layer` · `image` · `cropped-render` |
| `structural_recommended` | `true` → длинный скан, см. §5 |
| `composite_suspected` | `true` → в одном PDF склеены несколько документов (E.6.2); скилл приёма предлагает split в preview |
| `composite_reasons` | список причин детекта склейки (повтор заголовка-якоря по страницам, множественные ИНН) |
| `error_class` | причина отказа извлечения (E.14): `not_materialized` · `corrupt` · `empty`; иначе `null` |
| `retryable` | `true` → отказ **временный** (файл не материализован на маунте) → ретрай с паузой, **не** «битый» (E.14) |
| `content_hash` | `sha256:<hex>` — ключ кэша (§4) |
| `low_confidence_fields` | заполняет агент после vision (§7) |
| `warnings` | список предупреждений (мусор, обрезка, структурный режим) |

Доп. режимы: `--render <pdf> --page N --render-dir DIR` (рендер одной страницы),
`--spot-check <crop.png>` (tesseract по кропу одного поля, §6).

## §2. Дерево решений

```
для файла:
  1. КЭШ (§4): есть зеркало с тем же content_hash и vision_done:true и не mirror_stale?
       → переиспользовать, method=cached. OCR один раз.
  2. extract_text.py определяет тип и ветку:
       PDF, все страницы text          → method=pdf-text, needs_vision=false → готово
       PDF, есть scan/garbage страницы  → needs_vision=true → §3 (vision)
       Изображение                      → needs_vision=true, reason=image → §3
       DOCX / TXT                       → программно → готово
  3. needs_vision=true → §3 (vision-нога агента). structural_recommended → §5.
  4. Документ «решающий» (класс из списка ИЛИ пометка Сюзерена)? → §3.2:
       критичные поля перечитывает ВТОРАЯ, независимая голова + §6 (второй движок).
  5. После vision: §7 (пер-полевой confidence) → собрать зеркало → §4 (записать кэш).
```

**Мусорный текстовый слой (F3.3):** Python-нога не отдаёт мусор (mojibake / тонкий
OCR-артефакт поверх скана) как авторитетный текст — помечает страницу `garbage` и шлёт на
vision (`reason=garbage-layer`). Это заменяет прежний бинарный «есть любой текст → доверяем».

## §3. Агентский протокол vision (основной путь OCR)

Для документа с `needs_vision: true`:

1. Возьми `vision_pages` (или `vision_pages_suggested` в структурном режиме, §5).
2. Для каждой страницы — рендер в PNG **в песочницу `outputs/`, не в синкаемые папки дела**
   (правило 4 «Cowork-first robustness»):
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/scripts/extract_text.py --render "<файл.pdf>" --page N \
       --render-dir "outputs/renders" --width 1500
   ```
   Рендер идёт через pymupdf (надёжнее системного pdftoppm, который у файлового Read падает
   «unsafe location»). Если в выводе `cropped: true` — рендер обрезан (§7), перерендерь/флаг.
3. Прочитай PNG через **Read tool** (vision) и транскрибируй в текст с сохранением структуры
   (заголовки, пункты, таблицы → markdown; см. [`mirror-template.md`](mirror-template.md)).
4. Постранично — **постранично**, не пакетом (тяжёлые медиа порциями, иначе срыв по таймауту).
5. Собери зеркало по [`mirror-template.md`](mirror-template.md): `extraction_method: vision`,
   `extraction_model` = модель субагента, `confidence` по факту качества (§7).

**Делегирование:** массовый vision — Haiku-субагентам (`model: "haiku"`), как и всё создание
зеркал. Sonnet/Opus не тратим на транскрипцию.

## §3.1. Дисциплина достоверности транскрипции (E.13)

Зеркало — **дословный транскрипт**, а не пересказ. Vision-субагент переносит то, что физически
на странице; **интерпретация, реконструкция и домысливание — запрещены**. Это транскрипционный
аналог правила [`conventions.md`](conventions.md) → «verify-before-assert» (то правило — для
аналитических скиллов; здесь — для момента создания зеркала) и конкретизация
[`mirror-template.md`](mirror-template.md) правило 6 «юрвыводы не в зеркало». Действует для всех
скиллов, создающих зеркала (`intake`, `add-evidence`, `add-opponent`, `update-index`).

1. **Дословность.** Только текст со страницы. Перефразирование, «приглаживание», восстановление
   пропусков по смыслу — недопустимы. Нечитаемый фрагмент → маркер `[Нечитаемо: …]`
   ([`mirror-template.md`](mirror-template.md) правило 4), **а не** реконструкция по смыслу.
2. **Автофлаг реконструкции (пометить и вычистить).** Если субагент описывает содержание
   **своими словами вместо переноса текста** — это реконструкция. Тревожные маркеры — в
   **собственной речи субагента** (не в цитате из документа): «видны элементы…», «по-видимому»,
   «вероятно, речь о…», «предположительно», «текст неразборчив, но…», «документ содержит …» как
   пересказ. При таком → **заменить додуманное на `[Нечитаемо]`**, поставить
   `needs_manual_review: true`, отметить строкой в EXTRACTION NOTES. Флаг **гранулярный** — один
   реконструированный абзац не зануляет весь документ (как в E.6.4). Документ, **целиком**
   нечитаемый, флагом не лечится — ветка «битый/неоткрывающийся файл»
   ([`intake/SKILL.md`](../skills/intake/SKILL.md) → «Граничные случаи»): файл остаётся во «Входящие».
3. **Контрольная сумма (внутри одного документа).** Если документ содержит **разбивку + итог**
   (платёжное поручение, расчёт цены иска/неустойки, опись, смета, таблица платежей) — субагент
   сверяет: **сумма единиц = заявленный итог**. Совпало → перенести как есть; разошлось (боевой
   случай: сводка 2 305 200 при разбивке 3 390 000) → **строка-флаг в EXTRACTION NOTES +
   `needs_manual_review: true`**, перенести **оба числа как в документе**, не «сглаживать» в одно.
   Результат сверки субагент выносит в **финальный ответ** (см. [`intake/SKILL.md`](../skills/intake/SKILL.md)
   Фаза 2). Сверка **только внутридокументная**; кросс-документная (∑ платёжек = цена иска) — зона
   `study-evidence` / verify-before-assert правило 5, не OCR-слоя.
4. **Без интерпретации ролей и ссылок.** Транскрипт фиксирует **имена сторон ровно как напечатаны**
   и цитаты норм/практики **только если они буквально есть в документе**. Субагент **не назначает**
   правовые роли (кто должник / кредитор / арбитражный управляющий / истец / ответчик) и **не
   добавляет** ненапечатанные ссылки на нормы или практику (боевой случай: домысленные «ст. 269–272
   АПК», которых в акте нет; путаница банкрота и АУ) — это анализ, его ведёт `study-evidence`
   (Фаза 3, сверка «кто есть кто»), а не зеркало. Напечатанная, но нечитаемая/сомнительная ссылка →
   инлайн-маркер `[!conf:low]` + флаг «сверить» (§7).

## §3.2. Вторая голова для решающих документов (F.18)

**Зачем.** Правил эскалации «Haiku → Opus» в плагине не было ни одного: все назначения
модели статические и привязаны к фазе скилла, а не к свойству документа. Все три ступени
защиты (контрольная сумма §3.1 п.3, пер-полевой confidence §7, спот-сверка §6) исполнял или
инициировал **тот же Haiku**, который делал транскрипцию, — включая заполнение полей
`quality` / `needs_manual_review`. Петля самооценки замкнута: если субагент прочитал цифру
**уверенно и неверно**, а пары «разбивка + итог» в документе нет (её нет ни в выписке из
реестра акционеров, ни в бюллетене), `low_confidence_fields` пуст и флаг не поднимется.
Боевой случай: выписка прочитана как «100 %, единственный акционер» вместо 15 % —
переворачивало конструкцию корпоративного спора; спасла бдительность оркестратора, не плагин.

**Принцип: сверяют две независимые головы, а не одна себя.**

**Когда включается.** Документ — «решающий»: класс из закрытого списка ЛИБО пометка Сюзерена
на приёме. Определение, список классов и способ пометки — [`conventions.md`](conventions.md) →
«Решающие документы: вторая голова». Здесь — только протокол чтения.

**Критичные поля решающего документа** — те, на которых держится правовая конструкция, а не все
реквизиты подряд: доли и проценты участия, количество голосов / акций, кворум и итоги
голосования, суммы, ИНН/ОГРН сторон, даты, № дела. Для реестра акционеров это доли и количество
акций; для бюллетеня и протокола собрания — результаты голосования и кворум.

**Сначала — откуда взялась цифра.** Вторая голова нужна там, где реквизит прочитала **модель**:

| Метод извлечения | Что делаем |
|---|---|
| `pdf-text` · `docx-parse` · `text-read` | Вторая голова **не нужна**: цифра пришла из текстового слоя, а не из чтения. Достаточно **машинной сверки**: значение, попавшее в зеркало, обязано **буквально встречаться** в `text` из `extract_text.py`. Не встречается → его исказил тот, кто собирал зеркало → флаг по общим правилам |
| `vision` · `structural` | Полный протокол ниже: цифру прочитала модель, и проверить её может только независимое второе чтение |
| `pdf-text+vision` (гибрид) | **Постранично:** поле со страницы с текстовым слоем — машинная сверка; поле со скан-страницы — второе чтение. Как и `needs_manual_review`, флаг здесь гранулярный, а не «на весь документ» |

Это не оптимизация ради экономии: запускать Opus на текстовом слое значит **подменять** точную машинную сверку ещё одним модельным чтением — то есть ухудшать проверку, а не усиливать её.

**Протокол для vision-ветки (три ноги, две из них независимы от первой модели):**

1. **Первое чтение** — штатный vision-субагент (Haiku), §3 + §3.1. Он же перечисляет, какие
   критичные поля в документе есть, и их значения.
2. **Второе чтение — Opus-субагент** (`model: "opus"`, [`conventions.md`](conventions.md) →
   «Маршрутизация моделей»). Условия независимости, оба обязательны:
   - получает **тот же PNG** страницы и **список запрашиваемых полей**;
   - **не получает транскрипцию первого чтения** — иначе подтвердит прочитанное, и вторая
     голова превратится в ту же петлю, только дороже;
   - возвращает **только значения полей**, без пересказа документа и без правовых выводов
     (дисциплина §3.1 действует и здесь).
3. **Третья нога — второй движок** (§6, `--spot-check … --expect`): вердикт выносит **программа**,
   сравнением строк, а не модель. Независима от нейросети вовсе. Недоступна → пропускается тихо.

**Сверку выполняет оркестратор** — сопоставлением значений. Спрашивать модель «согласна ли ты
со вторым чтением?» запрещено: это удлиняет петлю самооценки, а не размыкает её.

**Итог по каждому полю:**

| Исход | Что делать |
|---|---|
| Оба чтения совпали (и `verdict: match`, если движок отработал) | Флага нет. Строка в EXTRACTION NOTES: «{поле}: сверено вторым чтением ({модель})[, tesseract: match]» — след проверки должен остаться в артефакте |
| **Расхождение** (vision ≠ второе чтение, либо `verdict: mismatch`) | Поле → `low_confidence_fields`; `needs_manual_review: true`; инлайн-маркер `[!conf:low]` у значения; в EXTRACTION NOTES — **оба прочтения как есть**; отдельная строка в Preview Сюзерену |
| `verdict: inconclusive` / движок или вторая голова недоступны | **Не флаг.** Строка в EXTRACTION NOTES: «вторая нога недоступна — {причина}». Отсутствие проверки не выдаём за проверку |

**Правило «не выбирать правильное».** При расхождении в зеркало идут **оба** прочтения — как в
контрольной сумме §3.1 п.3 (сводка 2 305 200 при разбивке 3 390 000: переносим оба числа).
Агент не решает, какое верно: он не знает, а решает Сюзерен по оригиналу.

**Гранулярность и цена.** Флаг — на поле, не на документ (как везде: E.6.4, §7). Вторая голова
запускается **только** для решающих документов и **только** по критичным полям — не «Opus на весь
приём». Обычный документ идёт прежним путём, Haiku, одним чтением.

## §4. Кэш по `content_hash` (F3.2) — «зеркало = кэш»

OCR/vision выполняется **один раз** на содержимое. Отдельного хранилища кэша нет — кэш это
само зеркало.

- В frontmatter зеркала: `content_hash:` (хэш, с которого извлекали) и `vision_done: true|false`.
- **Перед извлечением** любой скилл сверяет `content_hash` файла с зеркалом:
  - совпал, зеркало не `mirror_stale`, `vision_done: true` → **переиспользовать, vision не гонять**;
  - не совпал (файл изменился) → **обязательно** переизвлечь (иначе застрянет старый текст).
- `update-index` при пересоздании зеркала чтит это правило: re-vision только при смене хэша.

Это снимает недетерминизм vision (транскрипция замораживается на первом извлечении) и экономит
токены на повторных прогонах.

## §5. Структурный режим для длинных сканов (F3.4)

Правило зеркала «полный текст» для длинного скана невозможно и не нужно. При
`structural_recommended: true` (скан + страниц больше порога, ориентир > 15) —
**структурное зеркало** вместо полнотекстового:

- **Полнотекст головы + подписной страницы** (`vision_pages_suggested`: первые ~10 + последняя) —
  сохраняет citability реквизитов и подписной зоны.
- **Структурный скелет** для массива страниц: тип документа, стороны, ключевые даты/суммы,
  перечень разделов/заголовков, наличие подписи/печати, число страниц. Без дословного тела.
- Frontmatter: `extraction_method: structural`, `completeness: partial`, `needs_manual_review: true`
  (из структурного зеркала **дословно цитировать нельзя** — только ориентировка).
- В теле — маркер `[... документ содержит N страниц; полнотекст: стр. 1–10, 47; остальное — структурный обзор ...]`.

**Исключение по типу:** документы, которые **обязаны** цитироваться дословно (договор, иск,
решение, постановление), целиком в структурный режим не уходят — агент полнотекстит их ключевые
страницы, даже если документ длинный. Структурный режим — для длинных сканов-приложений (выписки,
реестры, переписка пачкой), а не для опорного документа позиции.

## §6. Tesseract спот-сверка критичного поля (вторая нога, немодельная)

**Не основной путь**, но и **не мёртвый код.** До F.18 вызов был описан только для случая, когда
vision *сам* признал неуверенность, а на вход требовался готовый кроп поля — которого вызывающему
негде было взять (геометрию реквизита vision не отдаёт). В итоге механизм существовал в коде и в
этом документе, но **ни один SKILL.md его не вызывал**. Оба препятствия сняты: вход — «PDF +
номер страницы», сверка — машинная.

**Когда запускать:**
- **штатно** — по критичным полям **решающего документа** (§3.2, третья нога);
- **дополнительно** — по любому реквизиту, который vision пометил `[!conf:low]` (§7), если цена
  ошибки высока.

```bash
# страница целиком (обычный случай — геометрия поля не нужна)
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/extract_text.py --spot-check "<файл.pdf>" \
    --page 3 --expect "3390000"

# сузить область, если страница целиком упирается в таймаут (доли страницы, 0..1)
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/extract_text.py --spot-check "<файл.pdf>" \
    --page 3 --region 0,0.10,1,0.35 --expect "15"

# готовый кроп PNG (если он уже есть) — одна строка
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/extract_text.py --spot-check "outputs/renders/crop.png" \
    --psm 7 --expect "7707083893"
```

**Выход и что с ним делать.** `--expect` — то, что прочитал агент; сравнение делает **программа**
(нормализует разряды и разделители: `3 390 000,00` = `3390000`; ведущие нули ИНН сохраняются):

| `verdict` | Смысл | Действие |
|---|---|---|
| `match` | движок прочитал то же | confidence реквизита вверх; строка-след в EXTRACTION NOTES |
| `mismatch` | движок прочитал **другое** | реквизит в `low_confidence_fields` + `needs_manual_review: true` + **оба прочтения** в EXTRACTION NOTES (§3.2) |
| `inconclusive` | движок ослеп на этой странице (пусто/каша) | **не флаг** — сверка не состоялась; пометить «вторая нога недоступна» |
| `null` при `available: false` | нет словаря / бинаря / таймаут | тихий пропуск, результат vision в силе (§9) |

Разведение `mismatch` и `inconclusive` — защита от шума: слепой tesseract иначе поднимал бы флаг
на каждом документе, и флаг перестал бы что-либо значить.

`rus.traineddata` вендорится в репо (`scripts/tessdata/`, `tessdata_fast`, ~3.7 МБ). Это
**независимое второе чтение** с иными режимами отказа, чем у vision, — в духе verify-before-assert.
Против самооценки модели ценно именно тем, что нейросетью не является вовсе.

**Если запускаешь tesseract сам, а не через `--spot-check` (F.5).** Прокидывание
`TESSDATA_PREFIX` зашито **только внутри** `extract_text.py --spot-check`. Любой прямой вызов
(`pytesseract`, `tesseract` из shell) вендоренный словарь **не увидит** и упадёт на «нет русского
языка» — ровно это и произошло в бою 16.07, где словарь искали вручную. Указывай папку явно:

```bash
export TESSDATA_PREFIX="${CLAUDE_PLUGIN_ROOT}/scripts/tessdata"
tesseract page.png stdout -l rus
```
```python
import os, pytesseract
os.environ["TESSDATA_PREFIX"] = os.path.join(os.environ["CLAUDE_PLUGIN_ROOT"], "scripts", "tessdata")
text = pytesseract.image_to_string(img, lang="rus")
```

Копировать словарь в `~/.tessdata` не нужно. Своего `eng.traineddata` в плагине нет — при
`-l rus+eng` нужен системный `eng`, иначе только `-l rus`.

## §7. Пер-полевой confidence и качество (F3.5)

Vision-субагент при транскрипции помечает **критичные реквизиты**, в которых не уверен:
ИНН, ОГРН, КПП, суммы, даты, № дела, № договора/документа.

- **Инлайн-маркер** в тексте зеркала: `7707083893[!conf:low]`.
- **Список** во frontmatter зеркала: `low_confidence_fields: ["ИНН контрагента", "сумма по п.3"]`.
- **Правило:** любой критичный реквизит на низком confidence → `needs_manual_review: true`, и
  именно этот реквизит блокируется для дословной цитаты (стыковка с verify-before-assert,
  [`conventions.md`](conventions.md) → «verify-before-assert» правило 4/5). **Один сомнительный
  реквизит не зануляет весь документ** — флаг гранулярный.
- **Решающий документ (F.18):** `low_confidence_fields` заполняется **не только** самооценкой
  vision, но и расхождением двух независимых чтений (§3.2) — это единственный вход в цепочку,
  не зависящий от того, насколько уверен в себе первый субагент. Во frontmatter зеркала при этом
  `decisive: true` и `verified_fields:` — перечень полей, **реально** прошедших второе чтение.
  Пустой `verified_fields` при `decisive: true` означает «проверка не выполнялась», а не
  «выполнена и чисто»: непроверенное не должно читаться как проверенное.

**Обрезанный рендер:** если `--render` вернул `cropped: true` (аспект PNG ≠ аспект страницы) —
рендер потерял край. Перерендерь; если повторяется — флаг `needs_manual_review: true` +
предупреждение Сюзерену (часть страницы могла не попасть в распознавание).

### Поля качества зеркала/индекса (юрисдикция `intake`/`add-evidence`/`add-opponent`)

| Поле | Критерий (по `shared/ocr`) |
|---|---|
| `quality: high` | `extraction_method ∈ {pdf-text, docx-parse, text-read}` ИЛИ чистый vision без `[Нечитаемо]` и без low-conf критичных полей |
| `quality: medium` | единичные `[Нечитаемо]` ИЛИ 1–2 критичных поля на низком confidence |
| `quality: low` | множественные `[Нечитаемо]` ИЛИ ≥3 критичных полей low-conf ИЛИ обрезанный рендер → одновременно `needs_manual_review: true` |
| `completeness` | `full` · `partial` (вкл. структурный режим) · `fragment` — как в [`intake/SKILL.md`](../skills/intake/SKILL.md) |
| `needs_manual_review` | `true` при `quality: low`, структурном режиме, обрезанном рендере или low-conf критичном поле |

> Критерий `quality` основан на **методе извлечения + числе `[Нечитаемо]`/low-conf полей**, а не
> на числовом «OCR confidence» — vision числовой метрики не выдаёт. (Снят прежний дрейф, где
> `quality` ссылался на несуществующий «OCR confidence ≥ 0.95».)

> **Текстовый слой ≠ «скан на ручную сверку» (E.6.2/E.6.4).** Если `extract_text.py` вернул
> `method ∈ {pdf-text, docx-parse, text-read}`, в `page_statuses` нет `scan`/`garbage` и
> `low_confidence_fields` пуст — `needs_manual_review` **обязан быть `false`**. Документ с
> полноценным текстовым слоем извлечён программно без OCR — помечать его «скан без сверки»
> нельзя (иначе `verify-before-assert` правило 4 напрасно блокирует цитирование годного
> реквизита). Для **гибрида** (`method: pdf-text+vision`) nmr ставится по скан-части, а не на
> весь документ (флаг гранулярный). Решение о nmr скилл приёма ведёт от **машинного сигнала**
> `method`/`page_statuses`, а не от догадки «похоже на скан».

## §8. Как скиллу вызвать модуль (один абзац для потребителей)

> **Извлечение текста — по протоколу [`shared/ocr.md`](../shared/ocr.md).** Кэш по `content_hash`
> (vision один раз); PDF с текстовым слоем → программно; скан/изображение/мусорный слой →
> vision (Read tool по PNG из `outputs/`); длинный скан → структурный режим; критичные реквизиты
> с low confidence → `needs_manual_review` + флаг. **Транскрипция дословная (§3.1):** без
> реконструкции/домысливания норм (маркеры пересказа → `[Нечитаемо]` + `needs_manual_review`);
> контрольная сумма «разбивка = итог» внутри документа; роли/непечатные ссылки не выдумывать.
> **Решающий документ (§3.2)** — класс из списка или пометка Сюзерена: критичные поля перечитывает
> вторая, независимая голова (Opus, без транскрипции первой) + спот-сверка вторым движком (§6);
> расхождение → оба прочтения в зеркало + `needs_manual_review`, «правильное» не выбираем.

## §9. Деградация и среда

- **pymupdf недоступен** → `method: none`, предупреждение; зеркало `needs_manual_review: true`,
  fallback по [`conventions.md`](conventions.md) → «Внешние зависимости и fallback».
- **vision (Read) не материализует страницу** (cloud-only / `outside connected folders`) → ретрай
  с паузой (правило 2 «Cowork-first robustness»); при повторе — `needs_manual_review` + флаг.
- **tesseract/`rus.traineddata` отсутствуют, либо таймаут на странице** → спот-сверка (§6) тихо
  пропускается (`available: false`, причина в `warnings`), vision-результат остаётся в силе — не
  блокирует. Таймаут лечится сужением области (`--region`), но и без него приём не останавливается.
  В зеркале это фиксируется как «вторая нога недоступна», **не** как успешная сверка.
- **Вторая голова (§3.2) недоступна** (Opus-субагент не запустился, страница не отрендерилась) →
  `decisive: true` остаётся, `verified_fields` пуст + строка в EXTRACTION NOTES и в Preview:
  «критичные поля решающего документа не прошли второе чтение — сверить по оригиналу». Молча
  продолжать с одним чтением нельзя: цена ошибки здесь и была причиной правила.
- **Не материализован (cloud-only OneDrive)** (`error_class: not_materialized`, `retryable: true`) →
  **не** «битый файл» (E.14а): ретрай с паузой (сначала Read материализует файл, правило 2 «Cowork-first
  robustness»); не поднялся после 1–2 попыток → оставить во «Входящие» + флаг «дождаться синка / открыть
  через Read», а не отбраковка.
- **Реально битый файл** (`error_class: corrupt`: pymupdf не открывает — нет EOF-маркера, битое дерево
  страниц, мусорные байты) → не индексировать, оставить во «Входящие», сообщить Сюзерену (см.
  [`intake/SKILL.md`](../skills/intake/SKILL.md) → «Граничные случаи»). `error_class: empty` (0-байт) → пропуск.
