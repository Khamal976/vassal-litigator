# add-evidence -- Прием дополнительных доказательств

Прием и систематизация дополнительных документов от клиента по уже инициализированному делу. Работает по принципу **preview -> apply**. Отличие от intake: дело уже содержит материалы, индекс заполнен, контекст дела известен.

## Предварительные условия

- Дело инициализировано: `.vassal/case.yaml` существует. Если нет -- предложи `/vassal-litigator:init-case`.
- Intake уже выполнен (есть записи в `index.yaml`). Если нет -- предложи сначала `/vassal-litigator:intake`.
- Папка `Входящие документы/` существует.

## Алгоритм

### Фаза 1 -- Сохранение и обработка

1. Прочитай `.vassal/case.yaml` и `.vassal/index.yaml` -- тебе нужен контекст дела, стороны, уже известные документы.
2. **Источник файлов -- `Входящие документы/`**. **Папка пуста** → отработай единую последовательность из [shared/conventions.md](../../shared/conventions.md) → «Папка „Входящие документы/"» → «Папка пуста — единое поведение трёх приёмников (F.15)». Твой прежний шаг (проверка `.vassal/history.md`: не приобщил ли файлы другой скилл — `prepare-hearing` / `analyze-hearing` — и не очистил ли входящие) — **второй** пункт этой последовательности и остаётся в силе; к нему добавляются взгляд наружу (корень дела и принесённые папки) и предложение `update-index` для дела, разложенного вручную.
   - **Область (опция, E.5):** если в `$ARGUMENTS` задана подпапка «Входящие документы/{…}/» или список файлов -- бери только их (`shared/conventions.md` → «Маршрутизация приёма по источнику» → «Область»); без аргумента -- вся папка + триаж (после шага 6).
3. Для каждого файла вычисли `content_hash` (sha256 от содержимого). **Байтовую копию в `raw/` не делай** — client-режим манифеста (см. `shared/conventions.md` → «Cowork-first robustness»).
4. Зафиксируй **манифест** в записи индекса: `origin.name` (исходное имя), дату получения, пакет (`origin.intake_batch = evidence-{дата}`), `content_hash`, `source: client`, `raw_pristine: false`.
5. **Извлечение текста — по протоколу `shared/ocr.md`** (как в intake): vision основной; кэш по `content_hash`; `${CLAUDE_PLUGIN_ROOT}/scripts/extract_text.py <файл>` → `text`/`needs_vision`/`vision_pages`/`content_hash`; при `needs_vision` — vision по PNG из `outputs/` (§3); скан/изображение/мусорный слой → vision; длинный скан → структурный режим; low-conf критичные реквизиты → `needs_manual_review` + флаг.
6. **Категоризация** с учетом контекста дела:
   - Тип документа (из таксономии -- см. `shared/conventions.md`)
   - Дата, стороны
   - Назначение: для приобщения к делу? информационный?

**Триаж по источнику (E.5, перед Preview).** Примени `shared/conventions.md` → «Маршрутизация приёма по источнику»: классифицируй каждый файл (`client` / `opponent` / `court` / `unclear`), сверяя отправителя/подписанта с `case.yaml.parties[]`. `add-evidence` -- владелец **`client`** (как `intake`). Файлы `opponent`/`court` **не обрабатывай** (порча дела и chain of custody); `unclear` -- уточни у Сюзерена. При заданной области триаж всё равно прогоняется.

**Сверка принадлежности документа делу (F.19, вместе с триажем).** Сверь № дела / ИНН / стороны / суд из текста с `case.yaml` — `shared/conventions.md` → «Вторая ось: принадлежность документа делу». Флаг поднимает **только положительное противоречие**; отсутствие реквизитов — не сигнал. Найдено → отдельный блок в Preview + вопрос (обработать · оставить · другое дело), **файл не двигать и не отбраковывать**. **Файлы `source: own-work` (собственная аналитика юриста) под сверку не попадают вовсе** (канон, там же): у памятки, справки, черновика реквизитов не бывает по природе — именно на этом сгорели две аналитические справки, которые боевой прогон выбросил как «чужие», а они вскрыли ошибку по подсудности. Для клиентского приёмника это основной жанр риска. Флаг `composite_suspected` из `extract_text.py` **обрабатывай** (раньше `add-evidence` его молча игнорировал): предложи split в Preview, затем сверь принадлежность каждой части отдельно. Развёрнутый разбор — [intake/SKILL.md](../intake/SKILL.md), фаза 2.

**Решающие документы (F.18).** Класс из закрытого списка или пометка Сюзерена (`shared/conventions.md` → «Решающие документы: вторая голова») → критичные поля перечитывает **вторая, независимая голова** (Opus, без транскрипции первой) + спот-сверка вторым движком; протокол — `shared/ocr.md` §3.2/§6. Расхождение → оба прочтения в зеркало, поле в `low_confidence_fields`, `needs_manual_review: true`, строка в Preview. В записи индекса — `decisive` / `decisive_reason` / `verified_fields`.

### Фаза 2 -- Preview

7. Определи целевое расположение каждого файла:
   - Процессуальный документ для приобщения -> `{ГГГГ-ММ-ДД} {Сторона} - {действие}/`
   - Дополнительное доказательство к существующей категории -> `Материалы от клиента/{подпапка}/`
   - Назначение неясно -> `Материалы от клиента/Иное/` (с пометкой в preview)
8. Покажи Сюзерену план:

```
Пакет: evidence-2026-04-05 (3 файла)

Материалы от клиента/Платёжные документы/
  выписка.pdf -> 2026-01-15 Банк Выписка по счету за декабрь 2025.pdf

Материалы от клиента/Переписка/
  письмо.pdf -> 2026-03-20 ООО Ромашка Письмо-требование об оплате.pdf

ТРЕБУЮТ ПРОВЕРКИ:
  фото.jpg -> 0000-00-00 Неизвестный Документ.jpg (не удалось определить)

Связь с существующими документами:
  - Выписка может подтвердить/опровергнуть факт оплаты по Спецификации №2

После обработки файлы из «Входящие документы/» -> «На удаление/»
(оригинал сохранён: рабочая копия в «Материалы» + манифест origin+content_hash в индексе)
```

9. Дождись подтверждения. Если Сюзерен корректирует -- внеси правки.

**Чужие файлы в Preview (E.5, offer-handoff).** Если триаж нашёл `opponent`/`court`-файлы -- покажи их отдельным блоком и предложи: «N файлов похожи на документы оппонента/суда -- оформить через `add-opponent` сейчас?»
- **Да** → доведи клиентскую часть (Фаза 3: свои файлы → зеркала/индекс → «На удаление/»), затем передай управление `add-opponent`, ограниченному этими файлами (список файлов как область).
- **Нет** → оставь их во «Входящие» (**не** трогай оригиналы, **не** заводи записи) + сообщи «оформите через `/vassal-litigator:add-opponent`».

### Фаза 3 -- Apply

10. Создай подпапки (если нужны новые).
11. Скопируй файлы с новыми именами в целевые папки.
12. Создай md-зеркала в `.vassal/mirrors/` (делегируй Haiku-субагентам, model: "haiku").
    - **Пометка правовых ссылок в документе-рассуждении (F.8).** Если документ сам рассуждает о праве (претензия, чужой иск, аналитическая справка, досье, заключение) и содержит ссылки на нормы — строка в EXTRACTION NOTES: «⚠ Правовые ссылки — гипотезы автора, сверить содержание с текстом закона перед использованием». Правило и границы — [shared/conventions.md](../../shared/conventions.md) → verify-before-assert, правило 6; подробный разбор — [intake/SKILL.md](../intake/SKILL.md), фаза 2.
13. Обнови `.vassal/index.yaml`:
    - Добавь записи с `source: client`
    - Заполни `origin` (исходное имя, дата, пакет `evidence-{дата}`)
    - Поля качества (`seal`/`signature`/`completeness`/`quality`/`needs_manual_review`) — как в [intake/SKILL.md](../intake/SKILL.md) → «Поля качества документа»; для решающих документов — `decisive`/`decisive_reason`/`verified_fields` (F.18)
    - Обнови `next_id`
14. Добавь запись в `.vassal/history.md`.
15. **Очистка «Входящие документы/»** -- перемести обработанные файлы в «На удаление/» через `mv` (не `cp`+обнуление; см. `shared/conventions.md` → «Cowork-first robustness»):
    ```bash
    mv "Входящие документы/файл.pdf" "На удаление/файл.pdf"
    ```

## Формат имени файла

```
ГГГГ-ММ-ДД Отправитель Описание.расширение
```

См. `shared/conventions.md` для полных правил.

## Идемпотентность

Перед обработкой проверь по `content_hash` в `index.yaml`, не обработан ли файл ранее (надёжный ключ; см. `shared/conventions.md` → «Дедупликация по content_hash»). Если обработан -- пропусти.

## Граничные случаи

- Те же, что в intake (пустой архив, нулевой размер, поврежденная кодировка, большой файл).
- **Сбой извлечения по `error_class` (E.14)** — как в intake: `not_materialized`/`retryable: true` → ретрай с паузой (сначала Read материализует файл), это **не** «битый»; `corrupt` → оставь во «Входящие», «перезалейте»; `empty` → пропуск. См. `shared/ocr.md` §9 и `intake/SKILL.md` → «Граничные случаи».
- Документ дублирует уже имеющийся (по содержимому) -> сообщи в preview, спроси Сюзерена.
- **Документы оппонента/суда во «Входящие»** (триаж, E.5) → `add-evidence` их **не обрабатывает** (не помечает `source: client`, не двигает оригинал); предлагает `add-opponent` (offer-handoff, Фаза 2).
- **Документ, похожий на «из другого дела»** (F.19) → флаг и вопрос, никогда молчаливый отсев; файл остаётся во «Входящие» до решения Сюзерена. Отсутствие реквизитов дела ≠ чужой документ.
- **Решающий документ, для которого не отработала вторая голова** (F.18) → индексируется штатно, `verified_fields` пуст, и это прямо сказано в отчёте: «критичные поля не прошли второе чтение — сверить по оригиналу».
