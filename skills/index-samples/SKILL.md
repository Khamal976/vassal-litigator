# index-samples -- Разовое наполнение каталога образцов

Служебный скилл. Строит **указатель** на уже написанные документы по всем делам Сюзерена, чтобы в новом деле можно было спросить «а не делали ли мы это раньше и где оно лежит».

**Родственник — `backfill-global`.** Тот переносит в глобальную память **наблюдения** (паттерны судьи и оппонента); этот заносит **адреса документов**. Механика обхода дел общая, отбор и цель — разные.

## Границы

- **Текст документов не читается и не переносится.** Нужны только метаданные из `index.yaml` и `case.yaml` плюс **перечень имён файлов** в корне дела (аналитика в индекс не заводится, иначе её не найти). Открывать сами документы и их зеркала — **никогда**: содержимое не нужно ни для одного поля записи.
- **Абсолютные пути в каталог не пишутся** — только номер дела и путь относительно корня дела (канон → «Каталог образцов»).
- Документы **оппонентов** в каталог не заводятся: их паттерны ведёт глобальный профиль оппонента.

## Предусловия

- `$VASSAL_GLOBAL_DIR` разрезолвлен **по правилу «Резолв переменной и онбординг (F.26)»** (в PowerShell — `$env:VASSAL_GLOBAL_DIR`; не задана → fallback `~/.vassal-global/` + разовое уведомление за сессию, не молча; в песочнице fallback эфемерен — предупредить на записи).
- Указан хотя бы один путь: корень с делами либо конкретные дела. **В режиме `--check` путь не требуется** — предметом там является сам каталог (см. одноимённый раздел).

## Алгоритм

### Фаза 0 -- Сбор корней дел

Правило то же, что в [backfill-global](../backfill-global/SKILL.md), фаза 0:

1. Путь содержит `.vassal/case.yaml` → это одно дело.
2. Не содержит → корень-родитель: рекурсивный поиск `**/.vassal/case.yaml` с **лимитом глубины 4** (защита от глубоких симлинков и архивов).
3. Несколько путей → обработать все. Пусто → спросить Сюзерена.
4. **Дедуп по `case_root`** (абсолютный путь), не по номеру дела.
5. ⚠️ **Два разных корня с одинаковым `case.number` — это НЕ дубль, обрабатывай оба.** Так выглядит стиль «папка на обособленный спор»: несколько папок одного банкротного дела несут один номер, но у каждой свои документы. В preview показать отдельной строкой: «Дел с общим номером {номер}: {N} папок».

**Skip-критерии — свои, не как у `backfill-global`:** пропускать дело, только если `case.yaml` невалиден **либо** в деле нет ни одного подходящего документа — то есть ни в `index.yaml`, ни **среди файлов корня дела**. ⚠️ Проверять обязательно оба места: аналитика (позиция, карта доводов, проекты решения, досье, предварительный анализ) по правилу F.12 в индекс **не заводится**, и дело с одной только позицией при проверке лишь по индексу ушло бы в skip — ровно тот класс дел, ради которого skip-критерии и переписывались. ⚠️ Критерии `backfill-global` («нет судьи», «нет аналитики оппонента») здесь **неприменимы** — они выбросят ровно те дела, которые каталогу нужнее всего: дело с готовыми документами и без разбора заседаний.

При тотальном skip — объяснить причину, а не рапортовать «обработано 0».

### Фаза 1 -- Чтение карточек

Для каждого корня прочитать **только два файла**:

- `.vassal/case.yaml` → `number`, `category` (шард), `qualification.relation_type`, `qualification.applicable_norms[]`, `status`, `appeal.result` / `cassation.result` (для `outcome`);
- `.vassal/index.yaml` → записи документов: `type`, `file`, `date`, `source`, `title`.

Плюс **перечень имён файлов в корне дела** — без чтения содержимого. Он нужен для аналитики: позиция, карта доводов, проекты решения, досье и предварительный анализ по правилу F.12 в `index.yaml` не заводятся, и найти их можно только по имени. **Открывать сами документы и зеркала не нужно ни при каких условиях.**

**Имя шарда — строго по таблице** канона → «Каталог образцов» → «Расположение и ключ». Общие «Правила слагов» на значениях категории неоднозначны (скобки), поэтому слаг задан закрытой таблицей; собирать его на глаз запрещено. Синоним `экономические споры` ведёт в тот же файл, что `исковое (АПК)`.

⚠️ **`case.category` пуст или вне таблицы** (старая карточка) — шард не определить. Не угадывать: показать дело в preview отдельной строкой «категория не заполнена, записи не заведены» и предложить проставить категорию в карточке. Молча в общий файл не сваливать.

⚠️ **Адресат-физлицо в имени файла.** У продуктов `draft-claim` адресат входит в имя (`{дата} Претензия {адресат}.md`). Если адресат — **физлицо**, в каталог идёт обезличенное имя `{дата} Претензия [физлицо].md` (правило в каноне → «Конфиденциальность»); сам файл в деле **не переименовывается**. Определяй по `case.parties[]`: есть `inn` длиной 10 знаков или `ogrn` — юрлицо, пишем как есть; ИНН 12 знаков либо реквизитов нет — считать физлицом и обезличивать. Не уверен — обезличивать.

### Фаза 2 -- Отбор

⚠️ **Отбирай по таблице артефактов F.12, а не по полю `source`.** Значение `source` у продуктов плагина **не унифицировано**: `settlement` прямо ставит своим подаваемым `source: client` («это наш документ»), `appeal` и `cassation` источник не задают вовсе, а `own-work` ставят только `prepare-hearing`, `analyze-hearing`, `draft-claim` и `enforcement-adjustment`. Фильтр по `source: own-work` потерял бы 6 продуктов из ~15 — включая обе жалобы и всё примирение. Признак принадлежности — **имя файла из закрытого списка F.12** и колонка «В индексе».

| Берём | Условие | `origin` |
|---|---|---|
| Подаваемое | имя файла совпадает со строкой таблицы артефактов F.12, у которой колонка «В индексе» = **да** (жалобы, отзыв/ходатайство к заседанию, замечания на протокол, мировое и сопутствующие, претензия и ответ на неё, заявления по ст. 324 АПК, частная жалоба) | `own` |
| Аналитика | файл в корне дела совпадает с продуктом-аналитикой из таблицы F.12: `* позиция.md`, `* Карта доводов.md`, `* Проект решения суда (в пользу клиента).md`, `* Проект решения суда (нейтральный прогноз).md`, `* Досье по доказательствам.md`, `* Предварительный анализ документов.md` | `own` |
| Судебные акты | `source: court` и `type` ∈ {`решение`, `определение`, `постановление`} | `court` |

**Не берём:** документы оппонента (`source: opponent`), договорные, платёжные, корпоративные и прочие материалы дела, `протокол-заседания`, сводку клиенту по заседанию, служебные файлы `.vassal/`.

**`doc_type`** — для подаваемого и судебных актов берётся из таксономии (то же значение, что в `index.yaml`). Для **аналитики** — из закрытого списка F.12 в слаг-форме: `позиция` · `карта-доводов` · `проект-решения-в-пользу-клиента` · `проект-решения-нейтральный-прогноз` · `досье-по-доказательствам` · `предварительный-анализ`. В таксономии этих значений нет, и подставлять `иной-документ` **нельзя** — потеряется различение, ради которого каталог и нужен.

⚠️ **Аналитика в `index.yaml` может отсутствовать** — по таблице F.12 позиция, карта доводов и проект решения в индекс не заводятся. Тогда бери их **прямым сопоставлением имён файлов в корне дела** с закрытым списком типов F.12, а `date` — из даты в имени файла. Это единственный случай, когда скилл смотрит на файловую систему дела, а не только в карточки; содержимое файлов всё равно не читается.

**`outcome`** — enum каталога `granted | partial | denied | null`; поля карточки в него **не отображаются напрямую**, у них свои словари. Таблица конверсии:

| Источник в карточке | Значение | `outcome` |
|---|---|---|
| `appeal.result` / `cassation.result` (для соответствующей жалобы) | `overturned` \| `modified` | `granted` |
| то же | `upheld` \| `dismissed` | `denied` |
| `enforcement.adjustment.result` (для заявлений по ст. 324) | `granted` \| `partial` \| `denied` | как есть |
| то же | `terminated` | `null` — это прекращение ранее данной отсрочки, а не исход самого заявления |
| `case.status` = `settled` (для продуктов `settlement`) | — | `granted` |
| `case.status` = `withdrawn` (для заявления об отказе от иска) | — | `granted` |

Во всех прочих случаях — **`null`**. Гадать по хронологии запрещено: пустой исход честнее выдуманного.

### Фаза 3 -- Preview

Показать Сюзерену **до записи**:

```
Каталог образцов -- предпросмотр

Обработано дел: {X} (пропущено {Y}: {причины})
Дел с общим номером: {если есть}

По категориям:
  банкротство ..................... +{N} записей (было {M})
  исковое (АПК) ................... +{N} записей (было {M})

Из них:
  подаваемых документов ........... {N}
  аналитики ....................... {N}
  судебных актов .................. {N}

Не заведено:
  {дело} — категория в карточке не заполнена
  {дело} — нет норм в qualification: запись будет искаться только по типу документа

Записать? [yes / показать список / нет]
```

**«Показать список»** — вывести записи целиком, чтобы Сюзерен видел, что именно уйдёт в глобальную память. Это единственная защита от «в каталог уехало лишнее»: содержимое проверяет человек.

### Фаза 4 -- Apply

1. **Backup** каждого затронутого шарда: `{путь}.bak.{timestamp}`. При успехе — удалить; при сбое — восстановить из него и **сохранить** (накапливаются только бэкапы сорвавшихся запусков, их ограничивает ротация 5 на файл).
2. Файла шарда нет — создать с корневым ключом `samples:`.
3. Записи **дописываются**; ключ идемпотентности — пара `case` + `file` (см. ниже).
4. **`.vassal/history.md` каждого обработанного дела** — строка:
   ```
   ГГГГ-ММ-ДД ЧЧ:ММ  index-samples
     в каталог образцов заведено N документов (категория: {категория})
   ```
   Если запись ушла в эфемерный fallback (`VASSAL_GLOBAL_DIR` не задана) — пометка `(резервный путь, вне синка)`, не рапортовать как о постоянном сохранении.
5. **Сводный итог:** обработано дел, пропущено с причинами, заведено записей по категориям, warning'и.

## Идемпотентность

**Ключ — пара `case` + `file`.** Повторный прогон на тех же делах записи не удваивает.

- Пара уже есть, поля совпадают → пропустить молча.
- Пара уже есть, изменился **`outcome`** → обновить. Это единственное поле каталога, допускающее правку: исход становится известен позже документа.
- Пара уже есть, изменилось что-то другое (тип, нормы, `relation_type`) → **не перезаписывать молча**, показать расхождение Сюзерену. Обычная причина — карточку дела уточнили после первого прогона; но это же выглядит и как ошибка отбора.
- Файл дела **переименован** → старая пара останется висеть с несуществующим путём. Скилл это **не чинит** и не удаляет: удаление записи — решение Сюзерена. Битые пути ловит проверка ниже.

**Проверка битых указателей** (по запросу, не автоматически): пройти записи шарда, для каждой резолвить корень дела и проверить существование файла; несуществующие показать списком с предложением снять. Молча не снимать — файл мог уехать в `Архив/`, а не пропасть.

## Граничные случаи

| Ситуация | Поведение |
|---|---|
| `case.category` не заполнена | Шард не определить — записи не заводить, показать в preview, предложить проставить категорию |
| `qualification.applicable_norms[]` пуст | Запись завести, `norms: []`. Матч при чтении пойдёт по `relation_type` + `doc_type` — грубее, но работает. Предупредить в preview |
| Дело заведено, документов ещё нет | Skip с причиной «нет подходящих документов», не ошибка |
| Два корня с одним номером дела | Обрабатывать оба; записи различаются полем `file`, а при совпадении и его — Сюзерену показывается расхождение (это разные обособленные споры) |
| Документ уехал в `Архив/` | Путь в записи обновить на архивный, запись **не удалять**: образец от архивации не перестаёт быть образцом |
| `$VASSAL_GLOBAL_DIR` недоступна | Не падать: сообщить причину, ничего не записывать, предложить повторить позже |
| Сюзерен просит занести документ оппонента | Отказать со ссылкой на канон и предложить `add-opponent` — паттерны противника ведёт глобальный профиль оппонента |

## Режим `--check` — проверка битых указателей

Отдельный ход, наполнение не выполняется. Запускается как `/vassal-litigator:index-samples --check` и **пути к делам не требует**: работать надо не с делами, а с каталогом.

1. Прочитай все шарды `samples/*.yaml` — здесь **перечисление папки уместно**, потому что предмет проверки и есть сама папка (при чтении по назначению перечисления по-прежнему нет, имя шарда собирается по таблице).
2. Для каждой записи резолви корень дела по номеру. ⚠️ Опоры на «родителя текущего дела» здесь нет — текущего дела в этом режиме не существует. Спроси у Сюзерена корень с делами (или возьми из аргументов) и ищи в нём рекурсивно, лимит глубины 4.
3. Проверь существование файла по `case` + `file`. Не нашёлся — **проверь `Архив/`** того же дела: чаще всего это архивация, а не пропажа.
4. Покажи списком: записи с несуществующим путём · записи, чей файл нашёлся в `Архив/` (предложить обновить `file`) · записи, чьё дело не найдено вовсе (папка перенесена или удалена).
5. **Молча ничего не снимать и не править.** Каждое действие — по подтверждению Сюзерена, по образцу Preview → Apply.

## Постусловия

- Каталог пополнен только по подтверждению Сюзерена (Preview → Apply); ни одна запись не заведена молча.
- **Ни в одной записи нет** текста документа, сумм, фактуры, **ФИО физлиц** и **абсолютного пути** — закрытый список полей соблюдён (канон → «Конфиденциальность»). Наименование юрлица-адресата в имени файла **допустимо**; обезличивается только адресат-физлицо.
- Записи не задвоены: пара `case` + `file` уникальна в пределах шарда.
- Дела с незаполненной категорией показаны отдельно, а не свалены в общий файл.
- `.vassal/history.md` каждого обработанного дела дополнен; при записи в эфемерный fallback — с явной пометкой.
- Бэкапы: при успехе удалены, при сбое сохранены и файл восстановлен.

## Связь с другими скиллами

- **`backfill-global`** — соседний служебный скилл: та же механика обхода дел, но переносит наблюдения по судьям и оппонентам. Прогонять их можно в любом порядке, они не пересекаются.
- **Читатели каталога** — `build-position`, `prepare-hearing`, `draft-claim`, `enforcement-adjustment`, `appeal`, `cassation`, `settlement`, `argument-map`.
- **Инкрементальное пополнение** идёт без этого скилла — в момент, когда производитель заводит свой продукт в `index.yaml`.
