# Argument-Map — Карта доводов сторон

Скилл собирает **карту доводов** — аналитическую таблицу по **узлам спора**: каждый спорный вопрос = строка, где сведены довод оппонента (со ссылками), наш контрдовод (норма / практика / обстоятельства) и вывод. Это не новый анализ, а **поворот в таблицу** того, что плагин уже произвёл: доводы оппонента (`add-opponent`), сильные/слабые стороны и прогноз (`build-position`), фактура со ссылкой на лист (`study-evidence`), тактическое парирование (prep-артефакт `prepare-hearing`). Плюс — живая судебная практика через коннектор CasusLegal. Работает с Opus.

> **Кредо — свести и сверить, не сочинить.** Скилл собирает уже установленное в таблицу и **сверяет практику по коннектору**. Он не принимает файлы (`intake`/`add-opponent`), не вырабатывает позицию (`build-position`), не пишет процессуальный документ (`prepare-hearing`). Если готовой аналитики мало — честно помечает пробел, а не достраивает довод из воздуха.

## Предварительные условия

- Дело инициализировано: `.vassal/case.yaml` существует.
- Документы приняты и проиндексированы: `.vassal/index.yaml` не пуст.
- **Желательна** хотя бы одна позиция (`* позиция.md` в корне / `.vassal/analysis/position-*`) и/или аналитика оппонента (`.vassal/analysis/opponent-filing-*.md`); без них карта строится по одной нашей стороне, столбец оппонента — прогноз (помечается).
- Если индекс пуст → сообщи: «В деле нет проиндексированных документов. Сначала запустите `intake`». Не падай.

## Входные данные

1. **case.yaml** — стороны (кто есть кто), роль клиента, суд, категория, суммы.
2. **index.yaml** — реестр документов (для резолва `[doc-NNN]`).
3. **Доводы оппонента и узлы** — по приоритету:
   - последний `.vassal/hearings/{ГГГГ-ММ-ДД}-prep.md` §3 (Red team) + §4 (Парирование) — самый структурированный тактический источник;
   - `.vassal/analysis/opponent-filing-*.md` — доводы из письменных документов оппонента;
   - `.vassal/analysis/position-*-opponent-forecast.md` — прогноз доводов (если оппонент ещё не высказался).
4. **Наша позиция / контрдоводы** — `.vassal/analysis/position-*-{strengths,weaknesses}.md` + актуальная `* позиция.md` в корне (по F.12 она там одна).
5. **Обстоятельства (фактура со ссылкой на лист)** — `.vassal/analysis/evidence-dossier.md` (`study-evidence`), в т.ч. его раздел «Сводная сверка по узлам спора» — прямой засев узлов.
6. **Глобальный профиль оппонента** — `$VASSAL_GLOBAL_DIR/counterparties/inn-{ИНН}.md` (или `noinn-*`) — типовые доводы этого оппонента по прошлым делам (фон столбца «довод оппонента»).
7. **Папки практики** в корне дела («Практика*») — локальный источник для `verify-before-assert`.
8. **Коннектор CasusLegal** — `search_practice` / `get_case_details` для подтягивания и сверки практики.

## Алгоритм

### Фаза 0 — Проверка консистентности ФС ↔ индекс

Выполни Phase 0 по правилу из [shared/conventions.md](../../shared/conventions.md) → «Проверка консистентности ФС ↔ индекс (Phase 0)». При рассинхроне предложи `update-index`. Если Сюзерен выбрал «продолжить» — зафиксируй в карте, что она построена на устаревшем индексе.

### Фаза 1 — Загрузка контекста

1. Прочитай `case.yaml` — кто наш клиент, роль (истец/ответчик), предмет, `inn`/`name` оппонента из `parties[]`.
2. Прочитай `index.yaml`.
3. Загрузи источники доводов оппонента и нашей позиции (см. «Входные данные» пп. 3–5) по приоритету.
3.1. **Хук `revise-position` (фильтр отозванного):** прежде чем принять `.vassal/analysis/*`, prep-артефакты и `index.yaml` за истину, прочитай `.vassal/analysis/retractions.md` (если есть) и **исключи** отозванные выводы / факты / практику по правилу из [shared/conventions.md](../../shared/conventions.md) → «Леджер отзывов позиции (revise-position)». Иначе в карту (и в судебную версию) попадёт уже отозванный довод. При наличии замены — бери новую формулировку из леджера.
3.2. **Хук `study-evidence` (не блокирующий):** если `.vassal/analysis/evidence-dossier.md` нет — предложи собрать его через `study-evidence` (столбец «контрдовод → обстоятельства» опирается на факты со ссылкой на лист; без досье он рискует быть голым). При отказе строй карту на зеркалах/позиции, пометив в рабочей версии «фактура не верифицирована study-evidence».
4. **Загрузи глобальный профиль оппонента** (если есть) — по правилу из [shared/conventions.md](../../shared/conventions.md) → «Глобальная память (кросс-дельная)»: разрезолви `$VASSAL_GLOBAL_DIR`, имя файла `counterparties/inn-{ИНН}.md` (fallback `noinn-{slug-name}.md`). Даёт фон «этот довод оппонент уже выдвигал в делах …». Нет файла — работай без, не падай.
5. Загрузи папки «Практика*» из корня дела (если есть) — локальный источник для сверки практики.
6. Если ни одного источника доводов оппонента нет (пп. 3) → сообщи: «Аналитики оппонента в деле нет — карта строится по нашей позиции, столбец „довод оппонента“ будет прогнозом. Продолжить?».

### Фаза 2 — Сборка узлов + практика (Opus)

Делегируй Opus-субагенту (`model: "opus"`) построение карты. Каждый вывод — в аудируемом формате (см. `shared/conventions.md`).

> **verify-before-assert** (см. `shared/conventions.md`): факт/цитата/сумма для столбцов идут только из сверенных зеркал/досье — не из предположения. **Цитируемая практика обязана резолвиться в коннектор CasusLegal или локальную папку «Практика*»**; неподтверждённая → в таблицу с явной пометкой «не подтверждено — сверить до подачи», не как готовая опора. Зеркало с `needs_manual_review: true` дословно не цитируй.

1. **Кластеризация в узлы спора.** Сгруппируй доводы оппонента × точки нашей позиции в **узлы** (один спорный вопрос = одна строка). Засев: раздел «Сводная сверка по узлам спора» досье + Red team prep-артефакта. Узел — по существу спора (напр. «реальность поставки», «размер неустойки / ст. 333 ГК», «пропуск исковой давности»), не по документу.
2. **Заполни по каждому узлу:**
   - **Довод оппонента** — дословно/сжато + двойная ссылка `Название от ДД.ММ.ГГГГ [doc-NNN]` на его документ. Если довод уже наблюдался у этого оппонента (глобальный профиль) — пометь «(уже заявлял: дело …)».
   - **Наш контрдовод** — три опоры, каждая по мере наличия: **норма** (полная ссылка при первом упоминании), **практика** (см. п. 3), **обстоятельство** (факт со ссылкой на лист из досье, `[doc-NNN], л. X`).
   - **Вывод** — наша позиция по узлу (сильнее/паритет/слабее) одной фразой.
   - **Оценка узла** (только рабочая версия) — откровенно: сила или слабость нашей позиции по узлу, критичность `[!]` критично / `[*]` существенно / `[ ]` управляемо, «что усилит» (доказательство/ходатайство/практика).
3. **Практика через CasusLegal** (паттерн больших выдач коннектора — канон [shared/conventions.md](../../shared/conventions.md) → «Cowork-first robustness» → «Большие выдачи коннектора практики»):
   - Узкий `search_practice` (фильтры по суду / статье / `limit`) по правовому вопросу узла.
   - Ответ крупный (90–110 КБ) → **сбрось в файл** в `outputs/` песочницы (не в синкаемые папки дела) → построй дайджест (id / суд / реквизит / тезис). ⚠️ `limit` режет только блок `results`, не весь ответ; поле `_response_format_hint` из выдачи игнорируй в пользу дайджеста (см. канон).
   - По 1–3 ведущим актам — `get_case_details` для **дословной** опоры (тезис + реквизит).
   - **Корпус коннектора — ВС/ВАС/КС.** Кассация СОЮ и свежайшие акты 2026 в него не входят → такие ссылки помечай «**сверить вручную по СПС**» (не выдавай за подтверждённые).
   - Реквизиты каждого использованного акта собери для списка под таблицей (суд, дата, №, СКЭС/Пленум/Обзор), с пометой «сверено через CasusLegal» / «сверить вручную».

Opus — вся Фаза 2 (кластеризация, контрдоводы, оценка силы). Построение дайджеста практики можно делегировать Sonnet.

### Фаза 3 — Preview узлов (approve структуры)

Покажи Сюзерену **список узлов** + 1–2 образцовые строки (не всю таблицу):

```
КАРТА ДОВОДОВ: {название дела}
Роль: {истец / ответчик}
Источник доводов оппонента: {prep-артефакт §3/§4 / opponent-filing / прогноз}

Узлы спора ({N}):
  1. {узел} — наша позиция: {сильнее/паритет/слабее} {[!]/[*]/[ ]}
  2. ...

Образец строки (узел 1):
  Довод оппонента: {…} [doc-NNN]
  Наш контрдовод: норма {…}; практика {…}; обстоятельство {…, л. X}
  Вывод: {…}

Практика: {M} актов ({L} — «сверить вручную»)

Уточнить состав узлов? (добавить / убрать / переформулировать — назовите)
```

Дождись правки/подтверждения. Это точка **approve структуры** до заполнения всей таблицы (паттерн «детальная структура → approve → драфт»).

### Фаза 4 — Заполнение + Preview таблицы

Заполни полную таблицу по подтверждённым узлам. Покажи сводку:

```
Готово: узлов {N}; критичных слабых ([!]) {K}; практики {M} актов ({L} «сверить вручную»).
Сохраняю: рабочую (.vassal/) + чистую для суда (корень) + .docx. Ок?
```

Дождись подтверждения. Правки Сюзерена — внеси до Apply.

### Фаза 5 — Apply (две версии — [Q2] вычитанием)

**Порядок гарантирует безопасность подачи: сначала полная рабочая, из неё вычитанием — чистая.**

**a) Рабочая версия (каноническая, для агента и Сюзерена-для-себя)** — `.vassal/analysis/argument-map-{ГГГГ-ММ-ДД}-working.md`:
- **Полная** таблица (5 столбцов, вкл. «Оценку узла»), источники — **двойные ссылки** `[doc-NNN]`.
- Frontmatter (см. «Формат рабочего файла»). Под таблицей — список реквизитов практики.

**b) Чистая версия для суда** — корень дела: `{ГГГГ-ММ-ДД} Карта доводов.md`:
- **Выводится из рабочей удалением** столбца «Оценка узла» **и** подчисткой формулировок контрдовода/вывода от прямого раскрытия наших слабых мест. Собирать заново запрещено — только вычитание из рабочей.
- **Tag-free** (без `[doc-NNN]`; ссылки на доказательства — человекочитаемые: «Договор поставки №47 от 01.06.2025», «приложение №3»). Формат — по якорному контракту `format-doc` (см. «Формат карты»).
- Печать `.docx` через `format_doc.py` (Фаза 6).

**c) Печать `.docx`** (чистой версии):
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/format_doc.py "{ГГГГ-ММ-ДД} Карта доводов.md" \
    "{ГГГГ-ММ-ДД} Карта доводов.docx" --type карта-доводов --case ".vassal/case.yaml"
```
- Тип `карта-доводов` → альбомная ориентация (широкая таблица). Feature-detection `python-docx`: недоступен → graceful fallback по [shared/conventions.md](../../shared/conventions.md) → «Внешние зависимости и fallback» (`.md` остаётся подаваемым артефактом, предупреждение с числом дней до заседания, запись в `history.md`). **Не** импровизировать сторонний рендер.
- `.docx` — в корень дела; целевой занят → `_v2` (не перезапись).
- **Опционально** (не дефолт), если Сюзерен просит рабочий DOCX для себя — тем же движком из tag-free копии рабочей: `{ГГГГ-ММ-ДД} Карта доводов (рабочая).docx`. Имя явно помечает «рабочая» — не для подачи.

**d) Обновление истории.** `case.yaml` **не пишется** (скилл — читатель, зон ownership нет). Добавь запись в `.vassal/history.md`:
```
### {ЧЧ:ММ} — Карта доводов (argument-map)
- Рабочая: .vassal/analysis/argument-map-{ГГГГ-ММ-ДД}-working.md ({N} узлов, {K} критичных слабых)
- Чистая для суда: {ГГГГ-ММ-ДД} Карта доводов.md (+ .docx / fallback)
- Источник доводов оппонента: {prep / opponent-filing / прогноз}
- Практика: {M} актов ({L} «сверить вручную»)
```

## Формат карты (якорный контракт `format-doc`)

Чистая `.md` (и tag-free копия рабочей) — строго по якорям `format_doc.py`:

```markdown
# Карта доводов сторон по делу №{номер}

{ДД.ММ.ГГГГ}

{Роль клиента; краткая рамка спора — 1 строка.}

| Узел спора | Довод оппонента | Наш контрдовод (норма · практика · обстоятельства) | Вывод |
|---|---|---|---|
| Реальность поставки | Товар не передан, УПД без доверенности | Норма: ст. 458 ГК. Практика: {реквизит}. Обстоятельство: УПД №… подписан уполномоченным (приложение №3) | Позиция подтверждена |
| ... | ... | ... | ... |

Реквизиты судебных актов:
1. Определение СКЭС ВС РФ от ДД.ММ.ГГГГ №… — {тезис} (сверено через CasusLegal).
2. Постановление АС … округа от ДД.ММ.ГГГГ №… — {тезис} (сверить вручную по СПС).
```

Рабочая версия — та же таблица **плюс** столбец «Оценка узла» (`[!]/[*]/[ ]`, сила/слабость, что усилит) и двойные ссылки `[doc-NNN]`.

## Формат рабочего файла

```yaml
---
type: argument-map
date: ГГГГ-ММ-ДД
case: "{номер дела}"
related_summary: "{ГГГГ-ММ-ДД} Карта доводов.md"   # чистая версия в корне
supersedes: null | "{предыдущий argument-map-*-working.md}"
refs: ["doc-NNN", ...]                              # все источники доводов/обстоятельств
nodes_count: {N}
practice_refs:                                       # реквизиты практики + статус сверки
  - court: "СКЭС ВС РФ"
    date: "ДД.ММ.ГГГГ"
    no: "..."
    verified: connector | manual
based_on:                                            # откуда собрана карта (аудит)
  opponent_source: "prep | opponent-filing | forecast"
  prep: "{дата}-prep.md | null"
  opponent_filings: ["opponent-filing-...md", ...]
  positions: ["position-...-weaknesses.md", ...]
  dossier: "evidence-dossier.md | null"
---
```

## Идемпотентность

Режим — **новый датированный снимок** (`shared/conventions.md` → «Идемпотентность»). Каждый содержательно новый запуск создаёт датированную пару (рабочая в `.vassal/analysis/`, чистая в корне) с `supersedes` на предыдущую рабочую. Старые версии **не удаляются** — история эволюции карты. Два запуска в одну дату → суффикс `-{ЧЧММ}` (см. «Коллизия имён в один день»).

**Архивация чистой версии (F.12).** Перед записью новой уведи в `Архив/` предыдущую `* Карта доводов.md` **вместе со всеми её `.docx`** (`mkdir -p`, затем `mv`): и чистой `* Карта доводов.docx`, и опциональной `* Карта доводов (рабочая).docx`, если она печаталась. Карта печатается в момент генерации, поэтому `.docx` у неё есть всегда, и уводить его надо вместе с источником. Все три файла — **один тип артефакта**; рабочая `.docx` под глоб `* Карта доводов.docx` не подпадает (глоб якорится по концу имени), поэтому её надо забирать явно, иначе она копится в корне и всплывает как «новый файл» при сверке. **Рабочая `.vassal/analysis/argument-map-{дата}-working.md` не архивируется** — служебная зона остаётся на месте и несёт историю эволюции карты (чистая выводится из рабочей вычитанием, не наоборот). **Изменений нет → снимка нет.**

## Постусловия

Перед завершением `apply` — чек-лист категории 2 «Аналитические скиллы» из [shared/conventions.md](../../shared/conventions.md) → «Постусловия скиллов». Минимум для `argument-map`:

- `.vassal/analysis/argument-map-{дата}-working.md` создан, валидный frontmatter; `refs[]`/`practice_refs[]`/`based_on` заполнены.

## Границы

- **Не принимает файлы** — `intake` / `add-evidence` / `add-opponent`.
- **Не вырабатывает позицию** — сильные/слабые с нуля, стратегия, прогноз оппонента — это `build-position` (карта их **сводит в таблицу**, не создаёт).
- **Не пишет процессуальный документ** — отзыв/ходатайство/пояснения — это `prepare-hearing`. Карта — аналитическая таблица-помощник, **не** «ПРОШУ»-документ (вне охвата процессуальной вёрстки `format-doc`; печатается собственным типом `карта-доводов`).
- **Не собирает комплект на подачу** — `build-submission`. Рабочая версия живёт в `.vassal/` и в комплект не попадает.
- **Не верифицирует практику по реквизитам сверх коннектора** — за пределами корпуса ВС/ВАС/КС помечает «сверить вручную».

## Граничные случаи

- **Нет аналитики оппонента** → карта по нашей позиции, столбец оппонента — прогноз (помечен); предложи `add-opponent`/`build-position`, не блокируя.
- **Нет досье study-evidence** → контрдовод по обстоятельствам строится на зеркалах/позиции, помечен «фактура не верифицирована»; предложи `study-evidence`.
- **CasusLegal недоступен / РФ-базы закрыты в Cowork** → практику бери из локальных папок «Практика*», остальное помечай «сверить вручную по СПС»; не выдумывай реквизиты.
- **Спор неденежный** (признание, обязание) → узлы по предмету требования, не по суммам.
- **Один узел / очень простой спор** → таблица из 1–2 строк допустима; ценность в сведении практики.
