# Update-Index — Обновление и верификация индекса

Сканирует файловую систему дела и приводит `index.yaml` в соответствие с реальным состоянием файлов. Находит новые файлы без записи в индексе, «осиротевшие» записи без файлов, устаревшие зеркала.

## Предварительные условия

- Существует `.vassal/index.yaml`
- Существует `.vassal/case.yaml`

## Алгоритм

### Шаг 1 — Сканирование

1. Прочитай `.vassal/index.yaml`.
2. Просканируй файловую систему дела — все файлы в:
   - `Материалы от клиента/` (рекурсивно)
   - Все процессуальные папки `{ГГГГ-ММ-ДД} *` (рекурсивно)
   - Корень папки дела (кроме `.vassal/` и служебных файлов)
3. Игнорируй: `.vassal/` (внутренности), `На удаление/`, `Входящие документы/`, `На подачу/`, `.DS_Store`, `Thumbs.db`, `Таблица документов.xlsx`.
3.1. **Собери пустые каталоги (F.16).** Тем же обходом ФС отметь каталоги, в которых **нет ни одного файла** (либо только системный мусор `.DS_Store` / `Thumbs.db` / `desktop.ini`). Область шире, чем у сканирования записей: сюда входят и подпапки `Входящие документы/`, которые опустели после `intake` (сам `intake` уводит в «На удаление/» только **файлы**, каталоги остаются — это и есть боевые «5 пустых папок из 19»).
   - **Не считаются кандидатами** (правило `shared/conventions.md` → «Уборка опустевших папок»): корень дела; штатные папки `init-case` («Входящие документы/», «На удаление/», «Материалы от клиента/» верхнего уровня); «На подачу/»; `Архив/`; всё внутри `.vassal/`.
   - Каталог с содержимым в кандидаты **не попадает никогда** — ни целиком, ни рекурсивно.

### Шаг 2 — Сравнение

4. Для каждого файла в файловой системе — проверь, есть ли запись в `index.yaml` (по полю `file`).
5. Для каждой записи в `index.yaml` — проверь, существует ли файл на диске.
6. Для каждого файла с записью — вычисли `content_hash` файла на диске и сравни с `content_hash` в индексе; несовпадение → зеркало устарело (содержимое изменилось). Признак устойчив к недостоверному mtime на OneDrive (`shared/conventions.md` → «Дедупликация по `content_hash`»; поле `mirror_stale` — `shared/index-schema.yaml`). `last_verified` — информационная дата последней сверки, **не** признак изменения.

Результат — пять списков:
- **Новые файлы** (есть на диске, нет в индексе)
- **Осиротевшие записи** (есть в индексе, нет на диске)
- **Устаревшие зеркала** (`content_hash` файла ≠ хэшу в индексе)
- **Зеркало заявлено, файла нет** (запись ссылается на `mirror:`, а файла зеркала на диске нет — E.8а)
- **Пустые каталоги** (F.16) — кандидаты на уборку; сами по себе индекс не меняют

### Шаг 3 — Preview

7. Покажи Сюзерену результат сканирования:

```
Результат проверки индекса:

Файлов в индексе: 15
Файлов на диске: 17
Зеркал актуальных: 14

Новые файлы (нет в индексе):
  - Материалы от клиента/Иное/заметка.txt
  - 2026-04-01 Истец - пояснения/пояснения.pdf

Осиротевшие записи (файл не найден):
  - doc-005: Материалы от клиента/Переписка/старое_письмо.pdf

Устаревшие зеркала:
  - doc-003: mirrors/doc-003.md (content_hash изменился)

Зеркало заявлено, файла нет (E.8а):
  - doc-031: mirrors/doc-031.md (запись ссылается, файла нет)

Пустые папки — убрать в «На удаление/»? (F.16, по одной отметьте нужные):
  - Входящие документы/от-клиента-март/   (опустела после intake)
  - Материалы от клиента/Экспертиза/       (создана заранее, документов пока нет)
```

8. Предложи действия:
   - Новые файлы → «Добавить в индекс и создать зеркала?»
   - Зеркало заявлено, файла нет → «Пересоздать зеркало по `shared/ocr.md`?» (или снять ссылку)
   - Осиротевшие → «Удалить из индекса или файл был перемещён? Подскажи.»
   - Устаревшие → «Пересоздать зеркала?»
   - **Пустые папки (F.16)** → «Убрать в „На удаление/"?» — **обязательно с подтверждением и по отдельности**. Пустая папка часто оказывается **заготовкой под будущие материалы** («Экспертиза/» заведена заранее): молча уносить нельзя. Если понятно, отчего папка опустела, скажи это в строке («опустела после intake» / «создана заранее») — Сюзерену так проще решить.

9. Дождись подтверждения. Если план пуст (0 новых, 0 осиротевших, 0 устаревших, 0 пустых папок) — early-exit без записи в индекс и без backup, сообщи «Индекс синхронизирован с ФС, изменения не требуются». Пустые папки **сами по себе** индекс не меняют: если это единственная находка — backup не нужен, но подтверждение всё равно спрашивается.

### Шаг 3.5 — Snapshot (backup перед apply)

Перед любой записью в `.vassal/index.yaml` снимается резервная копия. Этот шаг **обязателен** при непустом плане изменений (см. также раздел «Постусловия» категории 4 в [shared/conventions.md](../../shared/conventions.md)).

10. Скопируй текущий `.vassal/index.yaml` в `.vassal/index.yaml.bak.{ГГГГ-ММ-ДД-ЧЧММСС}` (через `cp`, не перемещение).

11. Ротация: после создания нового бэкапа оставь **5 самых свежих** `.vassal/index.yaml.bak.*`. Остальные перемести в `На удаление/` (не `rm`, см. `shared/conventions.md` -- «Папка „На удаление/"»).

12. В `.vassal/history.md` зафиксируй имя созданного бэкапа в формате:
    ```
    Backup перед apply: .vassal/index.yaml.bak.{timestamp}
    Откат: cp .vassal/index.yaml.bak.{timestamp} .vassal/index.yaml
    ```
    Это нужно, чтобы Сюзерен мог откатиться вручную, если post-apply верификация провалится или он передумает.

### Шаг 4 — Apply

13. **Новые файлы**: для каждого —
    - Присвой ID (`doc-{next_id}`)
    - Извлеки текст по протоколу `shared/ocr.md` (vision основной; кэш по `content_hash`)
    - Вычисли `content_hash` (SHA-256 по бинарному содержимому, см. `shared/conventions.md` → «Дедупликация по `content_hash`»)
    - Создай md-зеркало
    - Добавь запись в index.yaml
    - Определи тип, дату, стороны (делегируй Haiku при необходимости)
    - **Решающий документ (F.18):** если тип попал в закрытый список (`shared/conventions.md` → «Решающие документы: вторая голова»), критичные поля перечитывает вторая, независимая голова (`shared/ocr.md` §3.2) — проставь `decisive` / `decisive_reason: class` / `verified_fields`. Найденный вручную файл может быть решающим ровно так же, как принятый через `intake`

14. **Осиротевшие записи**: по указанию Сюзерена —
    - Удалить запись из индекса
    - Или обновить путь, если файл перемещён
    - Если запись удалена — переместить md-зеркало в `На удаление/` (не `rm`, см. `shared/conventions.md`)

15. **Устаревшие зеркала**: пересоздай md-зеркало по `shared/ocr.md` (делегируй Haiku-субагенту), обнови `content_hash`, **сбрось `mirror_stale: false`** и обнови `last_verified`. **Re-vision только при смене `content_hash`** (устаревшее зеркало = хэш изменился → содержимое другое); при неизменном хэше vision не перезапускается — переиспользуется кэш зеркала (`vision_done`, `shared/ocr.md` §4).
    - **Решающий документ (F.18):** если у записи `decisive: true`, а зеркало пересоздаётся из-за смены хэша — **прогони второе чтение критичных полей заново** (`shared/ocr.md` §3.2) и перезапиши `verified_fields`. Иначе перечень проверенных полей относился бы к прежнему содержимому файла и устарел бы молча.

15.1. **Пустые каталоги (F.16)** — только те, что Сюзерен отметил на шаге 8. Перенос через `mv`, не `rmdir` (код возврата на маунте недостоверен):
    ```bash
    mv "Материалы от клиента/Экспертиза" "На удаление/Экспертиза"
    ```
    - Перед переносом **перепроверь, что каталог всё ещё пуст** (между preview и apply файл мог появиться) — не пуст, пропусти и скажи об этом.
    - Совпало имя в «На удаление/» → суффикс `(2)`, `(3)`.
    - Индекс эта операция не трогает: пустой каталог записей не имеет.

16. Обнови `last_updated` (top-level) и `last_verified` для **всех** прошедших проверку записей (не только изменённых) в `index.yaml`.
17. Добавь запись в `.vassal/history.md` с итогом: добавлено/удалено/пересоздано/убрано пустых папок/имя бэкапа.

### Шаг 4.5 — Rollback при сбое apply

Если apply упал посередине (например, при добавлении 8-й из 15 записей), `index.yaml` остался в промежуточном состоянии:

18. Восстанови `.vassal/index.yaml` из последнего бэкапа: `cp .vassal/index.yaml.bak.{timestamp} .vassal/index.yaml`.
19. Зеркала, успевшие создаться частично — перемести в `На удаление/` (по списку из шага 13).
20. Сообщи Сюзерену: «Apply сломался на записи K из N. Индекс восстановлен из бэкапа `{timestamp}`. Рекомендую: разобрать причину сбоя и перезапустить.»

### Шаг 5 — Постусловия (верификация после apply)

Полный чек-лист — см. раздел «Постусловия скиллов» / «Категория 4: служебные» в [shared/conventions.md](../../shared/conventions.md). Кратко:

21. **Целостность индекса:**
    - `index.yaml` — валидный YAML, соответствует [shared/index-schema.yaml](../../shared/index-schema.yaml).
    - Нет дубликатов `id` и `file`.
    - `next_id` > max(существующих ID).

22. **Двусторонняя связь «запись ↔ зеркало»:**
    - Каждая запись в индексе имеет зеркало в `.vassal/mirrors/{id}.md`. **Проверь наличие файла зеркала (E.8а):** запись ссылается на `mirror:`, а файла на диске **нет** → классифицируй «зеркало заявлено, файла нет», предложи Сюзерену **пересоздать зеркало** (по `shared/ocr.md`, как устаревшее — шаг 15) либо снять ссылку. Ловит боевой дрейф, где `index.yaml` указывает на несуществующий `mirrors/doc-NNN.md`, а нижестоящий скилл, рассчитывающий на готовое зеркало, натыкается на отсутствующий файл.
    - **Каждое зеркало в `.vassal/mirrors/` имеет запись в индексе** (orphan mirrors → классифицировать как «зеркало без записи», предложить Сюзерену удалить или восстановить запись).
    - Каждое зеркало имеет валидный frontmatter (`id`, `source`, `type`).

23. **Backup существует:** `.vassal/index.yaml.bak.{timestamp}` создан до apply (см. шаг 10).

23.1. **Уборка пустых папок (F.16):** перенесены **только** отмеченные Сюзереном и **только** фактически пустые каталоги; штатные папки `init-case`, «На подачу/», `Архив/` и внутренности `.vassal/` не тронуты; перенос сделан через `mv` в «На удаление/», ничего не удалено.

24. **Если найдены проблемы** — предложить откат: `cp .vassal/index.yaml.bak.{timestamp} .vassal/index.yaml`.

## Идемпотентность

Повторный запуск безопасен:
- Если план изменений пуст (0 новых, 0 осиротевших, 0 устаревших, 0 пустых папок) — early-exit, бэкап не создаётся, `last_updated` не меняется (см. шаг 9).
- Уже убранная пустая папка во второй раз не предлагается — её на диске нет. Оставленная по решению Сюзерена предлагается снова (состояние «Сюзерен сказал оставить» нигде не хранится — см. «Граничные случаи»).
- Содержание уже синхронизированных файлов не пересоздаётся (`content_hash` сверяется до решения о пересоздании зеркала, см. шаг 13). Vision на неизменном содержимом не перезапускается — переиспользуется кэш зеркала (`vision_done`, `shared/ocr.md` §4).

## Граничные случаи

- **Файл переименован вручную** → старая запись «осиротеет», новое имя -- «новый файл». Если `content_hash` совпадает -- автоматически связать (обновить `file:` в существующей записи), без вопроса Сюзерену (см. `shared/conventions.md` → «Дедупликация по `content_hash`»). Если хэш не совпадает -- предложить связать вручную или подтвердить как разные документы.
- **Пустой индекс при существующих файлах на диске** -- это массовое «новые файлы без записи». Не запускай intake автоматически: предложи Сюзерену выбрать -- запустить intake (если файлы только пришли от клиента) или обработать через update-index (если структура папок дела перенесена с другого диска без `.vassal/`).
- **Пустой индекс при пустом диске** -- предложи запустить intake.
- **Файл в `.vassal/raw/` появился без обработки** -- это нормально, raw/ не индексируется.
- **Запись с `filing_status: submitted | filed`, файл не найден** -- **не предлагать удаление**. Сообщи Сюзерену: «документ подан в суд, но файл в локальной ФС не найден -- восстановить из `.vassal/raw/` или обновить путь?». Поданный документ юридически существует в материалах суда, удалять запись нельзя.
- **Дубликат `file:` в двух записях** -- остановиться, показать обе записи Сюзерену, дождаться решения (какую оставить, какую слить). Не разрешать автоматически.
- **Пустая папка — заготовка под будущие материалы** (F.16) → это норма, а не мусор: Сюзерен отвечает «оставить», папка не трогается. Повторный `update-index` предложит её снова — навязчивости тут меньше вреда, чем от молча унесённого слота. Если Сюзерен просит больше не спрашивать про конкретную папку, положи в неё файл-заглушку с пояснением (`.gitkeep`-подход) -- тогда она перестанет быть пустой.
- **Каталог с содержимым** никогда не попадает в кандидаты на уборку: одно `mv` папки с материалами унесло бы документы дела целиком и незаметно.
