# build-submission — Сборка комплекта «на подачу»

Берёт **готовый** процессуальный документ (продукт `prepare-hearing` / `appeal` / `cassation` / `settlement`), разбирает его просительную часть и перечень приложений, **сверяет «заявлено vs вложено»** (вбирает verify-before-assert, правило 5), собирает физический нумерованный комплект в `На подачу/{дата} {сторона} - {действие}/` с самоописывающими именами файлов (отдельный файл-опись не нужен — папка с такими именами и есть опись).

**Граница (что скилл НЕ делает):**
- Не пишет текст документа и не считает суммы требований / госпошлину — это `prepare-hearing` / `appeal` / `cassation` / `settlement`. Здесь только **сверка** того, что заявленное обеспечено вложенным.
- Не перепроверяет право.
- Не подаёт в суд (нет «Мой арбитр»); финальная подача — рукой Сюзерена.
- Не правит перечень приложений в самом документе — при расхождении **флагует** и возвращает в скилл-генератор.

## Предварительные условия

- Существуют `.vassal/case.yaml` и `.vassal/index.yaml` с записями.
- В деле есть **готовый** процессуальный документ (продукт в корне: `{ГГГГ-ММ-ДД} {тип}.md`/`.docx`). Если его нет — скилл сообщает и предлагает сначала `prepare-hearing` / `appeal` / `cassation`.
- Папка `На подачу/` — staging-зона (контейнер): каждая подача = отдельный датированный подкаталог. Создаётся скиллом лениво; в игнор-списках сканирования (`shared/conventions.md` → «Папка „На подачу/"»).

## Алгоритм

### Фаза 0 — Консистентность ФС ↔ индекс

Выполни общий пролог `shared/conventions.md` → «Проверка консистентности ФС ↔ индекс (Phase 0)». «На подачу/» в игнор-списке — ранее собранные комплекты не должны всплывать как новые файлы. При рассинхроне — предложить `update-index`, как описано в прологе.

### Фаза 1 — Целевой документ и загрузка контекста

1. Определи подаваемый документ:
   - путь в `$ARGUMENTS` → берём его;
   - иначе — автодетект последнего процессуального продукта в корне дела (по таблице «Продукты плагина» `shared/conventions.md`);
   - иначе (кандидатов несколько / нет) — покажи список и переспроси.
2. **Разрезолви корень дела в абсолютный путь (`CASE_ROOT`) — до первой операции с ФС (F.20).** Рабочая директория между вызовами bash не сохраняется (`shared/conventions.md` → «Cowork-first robustness», правило 4), а весь скилл оперировал относительными путями вида `На подачу/…`. Отсюда и берётся боевое «папка легла не туда» — не из отсутствия проверки, а из отсутствия якоря.
   ```bash
   CASE_ROOT="$(cd "$(dirname .vassal/case.yaml)/.." && pwd)"    # запусти из корня дела
   [ -n "$CASE_ROOT" ] && [ -f "$CASE_ROOT/.vassal/case.yaml" ] \
       || { echo "корень дела не определён — не собирать вслепую"; exit 1; }
   ```
   **Проверка обязательна:** при неудавшемся `cd` переменная останется пустой, и все дальнейшие пути (`"$CASE_ROOT/На подачу/…"`) станут абсолютными путями **от корня файловой системы** — то есть ровно тот сбой, который якорь и должен предотвратить, только громче. Если рабочая директория не корень дела — подставь известный путь к папке дела явно. Дальше **все** пути строятся от `$CASE_ROOT`: `"$CASE_ROOT/На подачу/…"`, `"$CASE_ROOT/.vassal/submissions/…"`. Относительные пути в этом скилле не используются.
   Затем прочитай `.vassal/case.yaml` (профиль, сторона-клиент, номер дела, суд) и `.vassal/index.yaml`.
3. Прочитай **две** версии документа:
   - **рабочую** — источник теггированного **«Рабочего перечня приложений»** (`[doc-NNN]` на каждом пункте) для точного резолва. По генератору:
     - `prepare-hearing` → `.vassal/hearings/{дата}-prep.md` §6;
     - `cassation` → `.vassal/analysis/cassation-prep-{дата}.md` §7;
     - `appeal` → `.vassal/analysis/appeal-prep-{дата}.md` (блок «Рабочий перечень приложений»);
     - `settlement` → `.vassal/analysis/settlement-{дата}-appendices.md`;
     - нет рабочего перечня (старый продукт / генератор его не персистил) → резолв уходит на эвристический фолбэк, и **каждый такой пункт помечается** (Фаза 2 шаг 5).
   - **подаваемую** (tag-free `.docx`/`.md`) — источник «что заявлено» (перечень приложений + просительная). Теги `[doc-NNN]` в подаваемом недопустимы (`shared/conventions.md` → «Двойные ссылки») — резолв идёт по рабочей версии.

**Сессионные правки состава приложений (E.4.7).** Если в этой сессии Сюзерен давал указания изменить состав приложений (убрать/добавить/заменить пункт) — в `$ARGUMENTS` или в диалоге до сборки — **зафиксируй их**. Сформируй **«текущий заявленный состав»** = перечень приложений документа ± сессионные правки. Указаний не было → текущий состав = перечень документа. Это вход для сверки в Фазе 3 (не собирать молча старый набор — риск подать удалённое приложение).

### Фаза 2 — Разбор перечня, маркеры черновика и резолв в `doc-NNN`

4. Из блока «Приложения» подаваемого документа извлеки структурированный список: для каждого пункта — `{ № п/п, наименование, дата, реквизиты (№ для платёжек), заявленное число экз./листов если указано }`.

**Маркеры черновика (E.4.1).** Грепни тело **финального подаваемого** документа (`.md`; если пришёл готовый `.docx` — его извлечённый текст) на паттерны незакрытого черновика: `[ПЛЕЙСХОЛДЕР]`, `[TODO]`, `[…]`/`[...]`, `XXX`, «указать (дату/номер/сумму/наименование)», `____` (пустые прочерки под заполнение). Любое совпадение → собери список мест (строка + цитата) для **🔴 флага** в Preview + `needs_manual_review: true` на манифесте. В суд не должен уйти документ с незаполненным местом; скилл раньше собирал комплект, но тело не грепал.

5. Реши каждый пункт перечня в `doc-NNN`:
   - **есть `[doc-NNN]`** в рабочем перечне приложений (Фаза 1 шаг 3) → берём напрямую;
   - пункт — **бандл / группа** (резолвится в несколько `doc-NNN`: `bundle_id`/`role_in_bundle` в индексе, либо «N шт.» с N совпадающими записями) → раскрыть в под-нумерацию `NN.01…NN.k` (E.4.3, см. «Наименование файлов в комплекте»);
   - **нет `[doc-NNN]`** → добор по индексу (Haiku-субагент, model `haiku`: совпадение по типу + дате + реквизитам/заголовку) → кандидат с пометкой **⚠ «привязано эвристически — проверьте привязку»**. Такие пункты Preview показывает **отдельным списком** и **требует явного подтверждения** привязки (не молча — риск прицепить не тот файл; E.4.2 [Q1]).
6. Из **просительной части** извлеки заявленные итоги и единицы (суммы; «N платёжных поручений на сумму X») — вход для сверки полноты (Фаза 3).

### Фаза 3 — Кросс-проверки полноты (реализация verify-before-assert, правило 5)

Реализует `shared/conventions.md` → «verify-before-assert» правило 5 («Сверка полноты») как конкретные шаги. Для каждого пункта перечня и для пакета в целом:

| Проверка | Что сверяется | Расхождение → |
|---|---|---|
| **Наличие файла** | каждый пункт перечня резолвится в `doc-NNN`, и **файл существует на диске** | ⚠ «приложение заявлено, файл не найден» |
| **Соответствие типа** | `type`/`title` зеркала соответствует наименованию пункта | ⚠ «тип не совпадает» |
| **Число единиц** | заявлено «N платёжек/единиц» — фактически N файлов/записей | ⚠ + точное расхождение («заявлено 10, вложено 9») |
| **Суммы (пересчёт)** | Σ реквизитов единиц (из зеркал) = заявленный итог в просительной | ⚠ «суммы не бьются: Σ единиц = A, заявлено B» |
| **Осиротевшие** | `[doc-NNN]`, упомянутые в теле, но **не** в перечне приложений; и наоборот | ⚠ «упомянут в тексте, нет в приложениях» |
| **Блокировка качества** | ни один участник не имеет `needs_manual_review: true` без OCR-сверки (verify-before-assert правило 4) | ⚠ «зеркало не сверено — не источник реквизитов для подачи» |
| **Маркеры черновика** (E.4.1) | тело слота `00` не содержит `[ПЛЕЙСХОЛДЕР]`/`[TODO]`/«указать …»/`XXX`/`[…]`/`____` | 🔴 «в документе незаполненные места — в суд уходит черновик» |
| **Состав ↔ сессия** (E.4.7) | перечень приложений документа = **текущему заявленному составу** (Фаза 1: ± сессионные правки) | 🔴 «состав расходится с указанием сессии — Preview спросит (3 варианта)» |

Реквизиты сверяй **по зеркалу/оригиналу**, не по памяти и не по тексту документа (verify-before-assert правило 1). Любое расхождение → флаг + `needs_manual_review` на комплекте.

### Фаза 4 — Preview

7. Покажи Сюзерену:
   - целевой документ + куда соберём (путь подкаталога в «На подачу/»);
   - таблицу комплекта: № · имя файла (как ляжет) · `doc-NNN` · статус сверки ✓/⚠;
   - **🔴 маркеры черновика** (E.4.1): список незаполненных мест в теле документа, если найдены;
   - **⚠ эвристически привязанные приложения** (E.4.2): отдельный список пунктов без `[doc-NNN]` — на подтверждение привязки;
   - раскрытие **бандлов** (E.4.3): пункт `NN` → файлы `NN.01…NN.k`;
   - (опц.) **конвертация офисных приложений в PDF** (E.4.4) для «Мой арбитр», если доступен `soffice` — на подтверждение;
   - **итог кросс-проверок**: сколько пройдено / флагов; результат сверки сумм; осиротевшие;
   - что запишем: манифест подачи + (опц.) `filing_status: draft` главному документу.
8. **Нет приложений** → собрать комплект из одного документа по подтверждению (не ошибка).
9. **При расхождении «заявлено vs вложено» комплект всё равно собирается.** Расхождения помечаются: `⚠` в отчёте Preview + у проблемного места (отсутствующий файл / несошедшаяся сумма) + `needs_manual_review: true` на манифесте. Отчёт Preview **явно перечисляет все флаги**, чтобы Сюзерен видел, что донести/поправить до подачи. Блокировки нет — решение за Сюзереном.

**Расхождение состава приложений с сессией (E.4.7 🔴).** Если перечень в документе не совпадает с **текущим заявленным составом** (Фаза 1: были сессионные правки — убрать/добавить/заменить приложение) — **не бери молча состав документа**. Подними 🔴 флаг и предложи выбор:
1. **Обновить документ через генератор** (`prepare-hearing` / `appeal` / `cassation` / `settlement`) — *рекомендуется*: документ, перечень и комплект останутся согласованы (build-submission перечень в документе не правит — это граница скилла);
2. **Собрать по текущему указанию** (без убранного / с добавленным) — комплект соберётся, но `заявлено(документ) ≠ вложено` пойдёт штатным флагом сверки «заявлено vs вложено»;
3. **Собрать как в документе** (проигнорировать сессионную правку).

Дождись выбора Сюзерена; зафиксируй его в манифесте (`session_appendix_override`) и в `history.md`. Молча старый набор не берётся.

### Фаза 5 — Apply

10. **Backup индекса** — только если включена запись `filing_status` (см. шаг 14). Техника — как `skills/update-index/SKILL.md` (Snapshot): `.vassal/index.yaml` → `.vassal/index.yaml.bak.{ГГГГ-ММ-ДД-ЧЧММСС}`, ротация 5 (старые → «На удаление/»). Без записи в индекс backup не нужен.
11. `df` перед массовым копированием (защита от молчаливого усечения на полном диске). Создай подкаталог **от якоря** (F.20):
    ```bash
    SUB="$CASE_ROOT/На подачу/{ГГГГ-ММ-ДД} {Сторона} - {действие}"
    mkdir -p "$SUB" && SUB_REAL="$(cd "$SUB" && pwd)"     # фактический путь, не задекларированный
    ```
    `$SUB_REAL` — это то, куда каталог **лёг на самом деле**; именно он идёт в постусловие Фазы 6 и в поле `folder` манифеста. **Идемпотентность:** если подкаталог уже есть — старую версию `mv` в «На удаление/» (не перезапись).
12. Собери файлы в подкаталог с **самоописывающими именами** `NN Наименование от ГГГГ-ММ-ДД Nл.ext` (раздел «Наименование файлов в комплекте» ниже):
    - **`00` — подаваемый документ; здесь печатается `.docx` (late-binding, `shared/conventions.md` → «Где печатается `.docx`»).** Это одна из двух точек, где `.docx` материализуется — **из финального подаваемого `.md`**, поэтому он не может отстать от правок. Порядок:
      - подаваемый документ уже есть как **`.docx`** (напр. оформлен на `prepare-hearing`) → `cp` → `00 {тип документа} {наш клиент} от {ГГГГ-ММ-ДД} {N}л.docx`;
      - подаваемый документ — **`.md`** (обычный случай для `appeal` / `cassation` / `settlement` / замечаний на протокол) → **напечатай `.docx` через `format-doc`** из финального `.md` (feature-detection `python-docx` по `shared/conventions.md` → «Внешние зависимости и fallback»):
        ```bash
        python3 ${CLAUDE_PLUGIN_ROOT}/scripts/format_doc.py "$CASE_ROOT/<подаваемый .md>" \
            "$SUB_REAL/00 {тип документа} {наш клиент} от {ГГГГ-ММ-ДД} {N}л.docx" --type <тип> --case "$CASE_ROOT/.vassal/case.yaml"
        ```
        `<тип>` — из типа документа (жалоба / отзыв / ходатайство / заявление / замечания-на-протокол; маппинг — `shared/conventions.md` → «Где печатается `.docx`» и `skills/format-doc/SKILL.md`);
      - **мировое соглашение** (двусторонний, ст. 140 АПК) — **вне охвата `format-doc`**: положи `.md` как `00 {тип} {наш клиент} от {ГГГГ-ММ-ДД} {N}л.md` + предупреждение «оформите как двусторонний документ вручную; не как процессуальную жалобу с шапкой» (arbitrum-docx опц.);
      - `python-docx` недоступен → положи `.md` как `00 {тип} {наш клиент} от {ГГГГ-ММ-ДД} {N}л.md` + предупреждение по шаблону conventions (**не** «сверстаю сам»).
      - **Листаж слота `00` (E.4.5, опц.).** У свеже-напечатанного `.docx` нет поля `pages`. Доступен `soffice` (feature-detection, `shared/conventions.md` → «Внешние зависимости») → посчитай листы: `soffice --headless --convert-to pdf "<00.docx>" --outdir <tmp-outputs>` → число страниц PDF (`pymupdf`: `len(fitz.open(pdf))`; `pdfinfo` не гарантирован) → подставь `Nл` в имя `00`. `soffice` недоступен → **`Nл` опусти** + пометь в манифесте «листаж слота 00 — уточнить вручную».
    - `01 …`, `02 …` — приложения **в порядке перечня** (файл `NN` ↔ приложение №NN документа); `cp` копия.
      - **Бандл (E.4.3):** пункт перечня из N документов → под-нумерация `NN.01 … NN.k` (по файлу на член бандла; порядок — как в `bundles.members` / по дате). Листаж каждого — из его зеркала (`pages`).
      - **Офисные форматы → PDF (E.4.4, опц.):** приложение в RTF/XLSX/DOC(X)/ODT и Сюзерен в Preview подтвердил конвертацию, а `soffice` доступен → `soffice --headless --convert-to pdf "<файл>" --outdir "$SUB_REAL"` → приложить PDF (имя с `.pdf`), исходник оставить в деле. `soffice` нет / не подтверждено → копировать как есть + ⚠ флаг «для „Мой арбитр“ — сконвертируйте {файл} в PDF вручную».
    - `cp`/рендер — начисто (без `truncate`); после каждого — **read-back** размера (на маунте Cowork запись может молча усекаться). Цель — новый файл в «На подачу/», не занят; занят (Word/OneDrive) → `_v2`, не перезапись. Если **исходный** продукт-`.docx` не читается — повтори чтение; при неустранимом печатай `00` из `.md` через `format-doc`, не молчаливый сбой.
13. Сохрани манифест `.vassal/submissions/{ГГГГ-ММ-ДД}-{действие}.md` (создай `.vassal/submissions/` лениво) — **источник истины о составе подачи**:
    ```yaml
    ---
    type: submission
    date: ГГГГ-ММ-ДД
    case: "{номер дела}"
    action: "{действие, напр. отзыв-на-иск}"
    main_doc: "{путь к подаваемому документу}"
    folder: "На подачу/{ГГГГ-ММ-ДД} {Сторона} - {действие}/"   # от ФАКТИЧЕСКОГО $SUB_REAL, после проверки Фазы 6
    refs: ["doc-NNN", ...]        # приложения комплекта (для бандла — все члены)
    checks: pass | flagged        # итог Фазы 3
    needs_manual_review: false | true
    draft_markers: []             # E.4.1: найденные маркеры черновика в теле слота 00 (пусто = чисто)
    session_appendix_override: null  # E.4.7: null | "as_document" | "per_session" | "regenerate" + краткое описание правки
    related_summary: "{путь к рабочему .md документа}"
    ---
    ```
    Тело — таблица комплекта (имена файлов + `doc-NNN`) + перечень флагов сверки (вкл. маркеры черновика E.4.1, эвристические привязки E.4.2, расхождение состава E.4.7). **Опционально** (см. таблицу schema, поле `filing_status`): если подаваемый документ есть в индексе — проставь ему `filing_status: draft` и `filing_folder` (приложения **не** помечаем — одно приложение входит в много подач, членство держим в манифесте).
14. Запись в `.vassal/history.md`: дата, действие, путь комплекта, число приложений, итог сверки; при выборе по E.4.7 — что решено с составом приложений (обновить документ / собрать по сессии / как в документе); при находке маркеров черновика E.4.1 — отметить.

### Фаза 5.5 — Rollback при сбое apply

Если apply прервался: восстанови `index.yaml` из backup (если делался); частично собранный подкаталог (`$SUB_REAL`) `mv` в `"$CASE_ROOT/На удаление/"`; сообщи Сюзерену, что собрано не было. Пути — от якоря: при обрыве рабочая директория тем более не гарантирована.

### Фаза 6 — Постусловия (верификация после apply)

- Каждый пункт перечня приложений имеет файл в подкаталоге; нумерация сплошная (`00` = документ, далее `01..NN`; для бандла — `NN.01..NN.k`, E.4.3), без дыр.
- Слот `00` — `.docx`, напечатанный `format-doc` из финального `.md` (или скопированный готовый `.docx`); ИЛИ `.md` + предупреждение (нет `python-docx` / мировое соглашение). Read-back: файл на месте, размер > 0.
- **Тело слота `00` проверено на маркеры черновика** (E.4.1); найденные — в манифесте (`draft_markers`) и подняты 🔴 в Preview.
- **Состав приложений сверен с сессией** (E.4.7): при расхождении выбор Сюзерена зафиксирован (`session_appendix_override`), молча старый набор не взят.
- Имена файлов самоописывающие (`NN Наименование от ГГГГ-ММ-ДД Nл.ext`); где листаж неизвестен (вкл. слот `00` без `soffice`, E.4.5) — без `Nл` и помечено в манифесте.
- **Комплект лежит в контейнере — проверено по факту (F.20).** Возьми **фактический** путь собранного подкаталога (`$SUB_REAL` из шага 11) и убедись, что он начинается с `$CASE_ROOT/На подачу/` и что файлы комплекта лежат именно там (`ls "$SUB_REAL"`). Прежнее постусловие сверяло поле `folder` манифеста с самим собой: `folder` пишет этот же скилл по тому же шаблону, поэтому проверка была успешной **всегда** — в том числе когда папка ложилась не туда. `folder` в манифест записывается **после** этой проверки и **из** фактического пути — в виде, относительном к корню дела (как `file:` в `index.yaml`: путь должен пережить перенос папки дела на другую машину).
- Манифест `.vassal/submissions/{дата}-{действие}.md` создан; путь манифеста тоже построен от `$CASE_ROOT`.
- Если писали `filing_status` — `index.yaml` валидный YAML по `shared/index-schema.yaml`, без дублей; backup существует.
- **Категория постусловий.** `build-submission` отнесён к категории 4 «служебные и сборочные» (`shared/conventions.md` → «Постусловия скиллов») — раньше скилл, физически собирающий комплект на подачу, не входил ни в одну категорию и оставался вне общей рамки самопроверки.

## Наименование файлов в комплекте

Отдельный документ-опись **не создаётся** — комплект самоописывается именами файлов: папка с такими именами и есть опись.

Шаблон: **`NN Наименование от ГГГГ-ММ-ДД Nл.ext`**
- `NN` — порядковый номер: `00` = сам документ, `01..NN` = приложения **в порядке перечня «Приложения»** документа (для сверки 1:1).
- **Бандл** (один пункт перечня = N физических документов, E.4.3): под-нумерация `NN.01 … NN.k` — напр. приложение №5 «Платёжные поручения, 19 шт.» → `05.01 … 05.19`. Пункт перечня остаётся один (№5), но раскрыт в 19 файлов; папка с такими именами и есть опись бандла.
- `Наименование` — опознаёт документ (тип + № если есть): «Платёжное поручение №47», «Доверенность», «Акт сверки».
  - **Слот `00` называет сторону, от которой подаётся** (решение Сюзерена 2026-07-21): `{тип документа}` + **от кого он** — «Отзыв ООО Ромашка на иск», «Апелляционная жалоба ООО Ромашка», «Ходатайство ООО Ромашка о приобщении». Сторона берётся из `case.yaml` — `our_client` (`short_name`, если задан, иначе `name`; кавычки снимаются по общему правилу именования). В многосторонних делах это единственное, что отличает наш документ от одноимённого документа соседней стороны в архиве подач.
  - **Приложения (`01`…) сторону в имя не выносят** — их наименование обязано совпадать с перечнем «Приложения» внутри подаваемого документа, иначе рушится сверка 1:1, ради которой нумерация и существует.
- `от ГГГГ-ММ-ДД` — дата документа. **Формат ISO — единый для всего комплекта** (решение Сюзерена 2026-07-21: «единый формат дат, как у всего комплекта»), совпадает с общим правилом плагина (`shared/conventions.md` → «Именование»). Даты нет → опустить.
  - **Слот `00` дату несёт наравне с приложениями** — раньше она у него опускалась (пример был `00 Отзыв на иск 8л.docx`), из-за чего в архиве подач два отзыва по одному делу различались только содержимым. Дата — та, что стоит в самом документе (дата подписания/подачи); неизвестна → опустить и пометить в манифесте.
- `Nл` — число листов из поля `pages` зеркала. Неизвестно (структурное зеркало `extraction_method: structural` / нет зеркала / слот `00` без `soffice` — E.4.5) → `Nл` опустить и пометить в манифесте.

Пример (с бандлом-приложением №5 из 19 платёжек):
```
00 Отзыв ООО Ромашка на иск от 2026-05-08 8л.docx
01 Доверенность от 2026-01-12 1л.pdf
05.01 Платёжное поручение №47 от 2026-05-12 1л.pdf
05.02 Платёжное поручение №48 от 2026-05-13 1л.pdf
05.19 Платёжное поручение №65 от 2026-05-31 1л.pdf
12 Акт сверки от 2026-05-31 2л.pdf
```

Перечень приложений **внутри подаваемого документа** (только наименования, tag-free) формирует скилл-генератор (`prepare-hearing` / `appeal` / `cassation` / `settlement`) — build-submission его не трогает. Для точной привязки к файлам build-submission читает **рабочий** перечень приложений с `[doc-NNN]` (Фаза 1 шаг 3), который тот же генератор персистит в служебной зоне.

## Идемпотентность

Повторный запуск по тому же документу пересобирает **тот же** подкаталог `На подачу/{дата} {сторона} - {действие}/`: старая версия уходит в «На удаление/» (`mv`), новая собирается начисто — дублей нет. Разные документы → разные подкаталоги (контейнер «На подачу/» накапливает подачи хронологически). Манифест подачи перезаписывается для той же даты+действия.

## Граничные случаи

- **Документ без приложений** (напр. часть ходатайств) → собрать комплект из одного `00 {тип}` по подтверждению; не флаговать как ошибку.
- **Приложение заявлено, файла нет** → ⚠ в Preview и в отчёте; комплект собирается, место отсутствующего помечается. Это прямое следствие боевого случая (заявлено 10 платёжек, вложено 9).
- **Одно приложение в нескольких подачах** (общая доверенность/платёжка) — нормально: копируется в каждый подкаталог; членство — в манифестах, не в скалярном поле индекса.
- **Несколько кандидатов на целевой документ** → показать список с датами, переспросить (Фаза 1).
- **Подаваемый документ пришёл как `.md`** (обычный случай для `appeal` / `cassation` / `settlement` / замечаний на протокол — они не печатают `.docx` сами, `shared/conventions.md` → «Где печатается `.docx`») → build-submission **сам печатает `.docx`** через `format-doc` в слот `00` (Фаза 5, шаг 12). Нет `python-docx` → положить `.md` как `00 {тип}.md` + предупреждение (шаблон conventions). **Мировое соглашение** — вне охвата `format-doc`: `.md` + предупреждение о ручном оформлении двустороннего документа.
- **Зеркало участника `needs_manual_review: true`** → ⚠ пометка (реквизиты не сверены, проверка сумм по нему ненадёжна); предложить OCR-сверку до подачи (verify-before-assert правило 4). Сборку не блокирует.
- **Бандл-приложение** (один пункт перечня = N документов, E.4.3) → под-нумерация `NN.01…NN.k`; сумма/число единиц бандла участвуют в кросс-проверках «число единиц»/«суммы» (заявлено «19 платёжек на X» — фактически 19 файлов, Σ реквизитов = X).
- **Приложение в офисном формате** (RTF/XLSX/DOC(X)/ODT, E.4.4) → для «Мой арбитр» нужен PDF. Есть `soffice` + подтверждение в Preview → конвертировать; иначе копировать как есть + ⚠ флаг «сконвертируйте в PDF вручную». Тихо не пропускать.
- **Маркеры черновика в теле документа** (E.4.1) → 🔴 в Preview + `needs_manual_review`; комплект собирается (решение за Сюзереном), но незаполненные места подняты явно.
- **Состав приложений правился в сессии** (E.4.7) → расхождение «документ ↔ текущий заявленный состав» → 🔴 + выбор из 3 (Фаза 4 шаг 9). Молча состав документа не берётся.
- **Нет рабочего перечня приложений с `[doc-NNN]`** (старый продукт / генератор не персистил) → резолв по эвристике, каждый пункт помечен ⚠ «проверьте привязку»; Preview требует подтверждения (E.4.2).
- **Подкаталог лёг не под «На подачу/»** (F.20) → постусловие Фазы 6 это ловит по **фактическому** пути: перенеси собранное в правильный контейнер (`mv` от `$CASE_ROOT`), обнови `folder` манифеста и скажи Сюзерену, где комплект оказался. Корень причины — потерянная рабочая директория между вызовами bash, поэтому лечение — якорь `$CASE_ROOT` (Фаза 1 шаг 2), а не повторная попытка «вслепую».
