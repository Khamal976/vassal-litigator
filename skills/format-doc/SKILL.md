# Format-Doc — Headless-оформление процессуальных документов в .docx

Скилл берёт **готовый подаваемый текст** процессуального документа в `.md` и рендерит из него `.docx` по фирменному стандарту типографики — **детерминированно и идемпотентно**, headless (без Word-аддина), на уже вендоренном `python-docx`. Заменяет два неработающих в Cowork пути: отсутствующий `arbitrum-docx` (скиллы деградировали в «.md only») и `proc-doc-style` (написан только под Word-аддин, headless неисполним, без идемпотентности).

Полная декларативная спецификация стиля — [references/style-spec.md](references/style-spec.md) (портирована из внешнего `proc-doc-style`, движко-независимо). Физический рендер — детерминированная нога [scripts/format_doc.py](../../scripts/format_doc.py) на `python-docx`.

> **Кредо — только оформление.** Скилл не пишет и не правит содержание документа (это `prepare-hearing` / `appeal` / `cassation` / `settlement`), не досверяет практику / ставки (это `legal-review` / `build-position`), не собирает комплект на подачу (это `build-submission`). Он приводит готовый текст к стандарту вёрстки.

## Предварительные условия
- `python-docx` доступен (ставит `scripts/setup.sh`; проверка — Фаза 0). Нет → graceful fallback (.md остаётся, предупреждение).
- На входе — **готовый `.md`** процессуального документа: подаваемый, **tag-free** (без `[doc-NNN]`; см. [shared/conventions.md](../../shared/conventions.md) → «Двойные ссылки»).

## Вход
1. **`.md` документа** — продукт doc-producing скилла (корень дела) либо файл, указанный Сюзереном.
2. **Тип документа** — жалоба (апелляционная / кассационная / надзорная) · отзыв / ходатайство / заявление / возражение / пояснения / замечания-на-протокол · претензия · **`карта-доводов`** (аналитическая таблица `argument-map`, не процдокумент; включает альбомную ориентацию под широкую таблицу). Определяется из заголовка `.md`, из контекста запуска или аргументом. Тип задаёт структуру (см. `style-spec.md` §2: у жалобы «ПРОШУ:» вверху, у отзыва — внизу, у претензии адресат — контрагент, у замечаний на протокол — просительная «прошу внести исправления в протокол»).
3. **`.vassal/case.yaml`** — для сборки шапки (суд, стороны, № дела, представитель), если в `.md` готовой шапки нет.

## Markdown-контракт (как скилл читает `.md`)
Лёгкий **якорный** контракт + эвристический разбор тела. Скилл ищет предсказуемые секции:

| Секция | Якорь в `.md` |
|---|---|
| Шапка | блок до заголовка H1 (или собирается из `case.yaml`) |
| Заголовок типа документа | первый `# ` (H1) / строка-название |
| Дата подачи | строка `ДД.ММ.ГГГГ` сразу после заголовка |
| Довод | `## ` (H2) → Heading2; первый абзац под ним — тезис |
| Подраздел довода | «А.» / «Б.» / «В.» в начале строки → Normal 11pt bold |
| Списки | `1.`/`2.` → ListNumber (restart с 1 по блоку); `—`/`- ` → ListBullet (тире) |
| Цитата | `> ` → блок цитаты; строка сразу под ней — ссылка-источник (Right) |
| Просительная | маркер «ПРОШУ:» / «Требуем…» / «Ходатайства» |
| Приложения | маркер «Приложение:» |
| Подпись | «Представитель по доверенности … Фамилия И.О.» (последняя строка) |

Тело (абзацы, списки, цитаты, таблицы) парсится эвристически по markdown. **Якорь не найден** (напр. нет «ПРОШУ:») → флаг Сюзерену в preview, не угадывать вслепую. Doc-producing скиллы при интеграции (фаза 2) эмитят `.md` строго по этому контракту.

## Алгоритм

### Фаза 0 — Feature-detection движка
- `python3 -c "import docx"`. **Недоступен** → **fallback** по [shared/conventions.md](../../shared/conventions.md) → «Внешние зависимости и fallback»: `.docx` не создаём, `.md` остаётся, предупреждаем Сюзерена по шаблону, пишем в `history.md`. **Не импровизировать** другой формат.
- Проверь вход: `.md` существует, не пуст. Грепни `[doc-NNN]` — есть → это рабочая версия с тегами; предупреди «оформляю подаваемую версию, теги в .docx недопустимы» и вычисти теги (или попроси подаваемый `.md`).

### Фаза 1 — Разбор `.md` по контракту
1. Определи **тип документа** (заголовок / аргумент / контекст) → выбери структуру из `style-spec.md` §2.
2. Разложи `.md` на секции по якорям (шапка · заголовок · дата · тело · просительная · приложения · подпись).
3. Тело → доводы (H2), подразделы, списки, цитаты, таблицы.
4. Шапка: если в `.md` нет — собери из `case.yaml` по варианту типа (жалоба: «В [суд] / через [нижестоящий]»; отзыв: «В [суд]»; претензия: «Кому: [контрагент]»).
5. **Гигиена содержания** (не меняя смысла): суммы прописью в скобках → убрать (E.9); плейсхолдеры `[…]` / «указать дату/номер» → **флаг** Сюзерену (не оформлять вслепую).

### Фаза 2 — Preview
Покажи план до рендера:
```
ОФОРМЛЕНИЕ В .DOCX: {имя файла}
Тип: {жалоба / отзыв / ...}
Секции: шапка {есть/из case.yaml} · заголовок · дата · доводов {N} · приложений {M} · подпись {есть/нет}
Предупреждения:
  ⚠️ {нет якоря «ПРОШУ:» / плейсхолдеры [...] / теги [doc-NNN] / нет подписи}
Оформить?
```
Дождись подтверждения.

### Фаза 3 — Рендер (детерминированный)
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/format_doc.py "<in.md>" "<out.docx>" \
    --type <тип> [--case ".vassal/case.yaml"]
```
Нога применяет `style-spec.md` (§0 критический чек-лист · §1 типография · §2 структура по типу · §3 цитаты/таблицы · §4 микро-типографика · §6 обработка исходника) **детерминированно**: тот же `.md` → тот же `.docx` (фиксированные метаданные документа, без случайных id/времени). Рендер — **без модели**, чистый скрипт (снимает дефект proc-doc-style «повторный прогон = разное оформление»).

### Фаза 4 — Валидация выхода (`style-spec.md` §5)
Проверь получившийся `.docx` (нога + скилл) по чек-листу `style-spec.md` §5 (общие блоки А–Ж + тип-специфичные): шапка `leftIndent=210pt`; Heading1/2 стили и границы; нумерация доводов/списков непрерывна, начинается с 1 по блокам; нет пустых абзацев; типографика §4 (№ слитно, даты `ДД.ММ.ГГГГ`, суммы с NBSP, `%` слитно, **нет прописи**); интервал `spaceBefore=16pt` у абзацев после таблиц. Расхождения → **отчёт** по уровням (критические / предупреждения / информационные), а не молчаливый «успех». Блок Г (актуальность ставки/данных) — только флаг: сверка вне зоны оформления.

### Фаза 5 — Сохранение
- Имя `.docx` = имя исходного `.md` (то же, расширение `.docx`), в корне дела.
- Целевой файл занят (открыт в Word / OneDrive-лок) → `{имя} _v2.docx`, **не перезапись** (см. [shared/conventions.md](../../shared/conventions.md) → «Cowork-first robustness» → «.docx версионируется»).
- **Read-back**: файл создан, размер > 0, открывается `python-docx`.
- Запись в `.vassal/history.md`: чем оформлено (тип, имя `.docx`) или fallback.

## Идемпотентность / детерминизм
Один и тот же `.md` даёт байтово стабильный `.docx` (в пределах фиксированных метаданных). Рендер — единственный путь, без LLM в рендере. Повторный прогон не «дрейфует» оформлением.

## Fallback (движок недоступен)
`python-docx` не импортируется → `.docx` не создаём; `.md` остаётся как есть; предупреждение Сюзерену по шаблону conventions + запись в `history.md`. Не пробовать «через что-нибудь ещё».

## Постусловия
Перед завершением:
- `.docx` создан и открывается `python-docx` (read-back) **ИЛИ** fallback: `.md` цел + явное предупреждение + запись в `history.md`.
- Валидация `style-spec.md` §5 прогнана; расхождения — в отчёте по уровням (не проглочены).
- Имя `.docx` = имя `.md`; при заблокированном целевом — `_v2`, исходный не перезаписан.
- В выходном `.docx` **нет** тегов `[doc-NNN]` и **нет** сумм прописью (E.9).
- `.md` (источник) **не изменён** (скилл только читает вход).
- Запись в `.vassal/history.md` зафиксирована.

## Границы
- **Печатается в двух точках** (late-binding, [shared/conventions.md](../../shared/conventions.md) → «Где печатается `.docx`»): `prepare-hearing` (документ к заседанию) и `build-submission` (сборка на подачу). `appeal` / `cassation` / `settlement` / `analyze-hearing` выдают подаваемый `.md`; ручной запуск `/format-doc` по `.md` доступен всегда.
- Покрывает **документы стороны**: жалоба (апелляционная / кассационная / надзорная), отзыв / ходатайство / заявление / возражение / пояснения, замечания на протокол, досудебная претензия.
- **Аналитическая таблица `карта-доводов`** (тип от `argument-map`, E.11) — не документ стороны, а таблица-помощник по узлам спора; печатается **альбомно** (единственный тип, меняющий ориентацию страницы). Вызывается скиллом `argument-map` в момент генерации (не late-binding — в комплект на подачу не идёт). Тело — заголовок + markdown-таблица + список реквизитов практики (существующие блоки парсера).
- **НЕ покрывает** (иная структура — отдельные шаблоны, пока прежний путь / ручное оформление, флаг на будущее): **мировое соглашение** (двусторонняя сделка, подписи обеих сторон — не «ПРОШУ»-документ) и **проект судебного решения** (`draft-judgment` — судебный акт с вводной/описательной/мотивировочной/резолютивной, не документ стороны).
- Не генерирует содержание, не собирает комплект на подачу (`build-submission`), не верифицирует практику / ставки / реквизиты.

## Маршрутизация моделей
- **Sonnet**: разбор `.md` по контракту (Фаза 1), preview, оркестрация, отчёт валидации.
- **Рендер `.docx`** — детерминированная python-нога, **без модели**.
- Haiku / Opus не используются.
