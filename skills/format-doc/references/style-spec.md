# Спецификация стиля процессуальных документов (движко-независимая, полная)

**Назначение.** Полная декларативная спецификация фирменной типографики процессуальных документов для арбитражных судов — **целевое состояние `.docx`**, независимое от движка рендера. Портирована из внешнего скилла `proc-doc-style` (§0-7) целиком, кроме реализации под Word-аддин (Office.js) — она в headless неисполнима. Здесь только правила; применяет их детерминированная нога [`scripts/format_doc.py`](../../../scripts/format_doc.py) на `python-docx` (маппинг — §8).

**Область.** Документы стороны в арбитражный суд: **жалобы** (апелляционная / кассационная / надзорная), **отзыв / ходатайство / заявление / возражение / пояснения**, **досудебная претензия** (адресат — контрагент). **НЕ покрывает** (иная структура, отдельные шаблоны — §9): мировое соглашение (двусторонняя сделка), проект судебного решения (судебный акт).

**Преимущество headless над proc-doc-style.** В Word-аддине часть оформления (левые границы цитат, highlight, нижние границы Heading2) не ложилась на стиль и требовала ручных действий пользователя. В headless-рендере всё это ставится **программно через OOXML на конкретных абзацах** — ручных шагов не остаётся (кроме сверки актуальности данных, которая и так вне зоны оформления).

## §0. Критический чек-лист (самые часто пропускаемые правила)

Эти 14 пунктов дают визуально качественный результат; их пропуск сразу заметен. Нога обязана выполнить КАЖДЫЙ (неприменимый — помечается «неприменимо», не пропускается молча).

1. **Шапка — `leftIndent = 210pt`** на всех 3 абзацах (прижата к правому блоку страницы).
2. **Шапка — character spacing = 0** на всех runs (иначе «разрядка»: «о т  О О О» вместо «от ООО»).
3. **Шапка — `spaceAfter = 0`** на всех 3 абзацах + схлопнуть пустые абзацы, образовавшиеся на месте удалённых реквизитов.
4. **Heading1 — `spaceAfter = 0`**, дата `spaceBefore = 0` (заголовок и дата вплотную).
5. **Heading2 — автонумерация** через нумерованный список: в тексте заголовка номера НЕТ («Суд неверно применил…», не «1. Суд неверно применил…»); единый список, каждый Heading2 привязан к нему; Word проставляет «1.», «2.», «3.» сам.
6. **Маркированные списки → тире (em-dash U+2014), не буллет «•»**.
7. **Списки вплотную к вводной фразе**: у абзаца перед списком `spaceAfter = 0`, у первого элемента `spaceBefore = 0`.
8. **«Вывод» / «Заключение» довода — в НАЧАЛО, не в конец**: первый Normal-абзац под Heading2 и есть тезис-вывод; отдельного подзаголовка «Вывод:», «Тезис:», «Главное:» НЕ вставлять.
9. **Подразделы А, Б, В**: если внутри довода несколько коротких bold-подзаголовков без маркера — добавить «А.», «Б.», «В.»; вложенную нумерацию «1.1», «1.2» заменить на «А.», «Б.».
10. **Шрифт Garamond на ВСЕХ runs** (включая унаследованные Times New Roman из исходника).
11. **Highlight #D9D9D9 в КАЖДОМ Normal-абзаце довода**: одна ключевая фраза серым (модальные конструкции — «подлежит отмене», «не соответствует материалам дела», «вывод суда … не соответствует»). Исключения: цитаты, ссылки-источники, элементы списков.
12. **Подпись — Normal 11pt bold**, формат «роль[одна табуляция]ФИО».
13. **Приложения — БЕЗ** «на N л.», «в N экз.», «на N стр.» (только название и реквизиты).
14. **Интервал после таблицы — `spaceBefore = 16pt` + `lineSpacing = 13.8pt`** у абзаца сразу за КАЖДОЙ таблицей (не наследуется из стиля Normal — ставить явно).

## §1. Типография

### Шрифт и размер
- Основной текст: **Garamond 11pt**.
- Heading1 (тип документа, напр. «Кассационная жалоба»): **Garamond 16pt bold**, чёрный, без границ.
- Heading2 (доводы): **Garamond 14pt bold**, чёрный #000000, нижняя граница single 1pt.
- Элементы списков: Garamond 11pt.
- Таблицы: **Calibri 9pt** (намеренно отличается).
- «ПРОШУ:» / «Ходатайства» / «Требуем…»: Garamond **14pt bold**, стиль Normal (НЕ Heading2 — чтобы не наследовать нижнюю границу).
- Подзаголовки мини-разделов жалобы: Normal Garamond **12pt bold**.
- Подразделы А/Б/В внутри довода: Normal Garamond **11pt bold**.

### Интервалы (межстрочный 1.15 = 13.8pt на всех Normal-блоках; исключение — ячейки таблиц: single)

| Блок | spaceBefore | spaceAfter | lineSpacing |
|---|---|---|---|
| Основной текст | 0 | 8pt | 13.8pt |
| Шапка (3 абзаца) | 0 | **0** | 13.8pt |
| Heading1 | 24pt | **0** | 13.8pt |
| Дата подачи | 0 | 8pt | 13.8pt |
| Heading2 | 16pt | 8pt | 13.8pt |
| Элемент списка (внутр.) | 0 | 0 | 13.8pt |
| Элемент списка (последний) | 0 | 12pt | 13.8pt |
| Цитата | 0 | 8pt | 13.8pt |
| Подзаголовки А/Б/В | 0–8pt | 0 | 13.8pt |
| Абзац перед списком | — | **0** | 13.8pt |
| Абзац после таблицы | **16pt** | 8pt | **13.8pt** (явно) |
| «ПРОШУ:» / «Ходатайства» / «Требуем» | 16pt | 0 | 13.8pt |
| «Приложение:» | 8pt | — | 13.8pt |

### Выравнивание и отступы
- Основной текст, списки, Heading1/2: Left.
- **Шапка**: Left, `leftIndent = 210pt` (~7.4 см). НЕ alignment=Right.
- Цитата: `leftIndent = 35.4pt` (~1.25 см), Left, левая граница single 1pt.
- Ссылка под цитатой: `leftIndent = 35.4pt` (тот же), **Right**, граница продолжается.
- Списки: `leftIndent = 36pt`, `firstLineIndent = -18pt` (висячий).

### Heading1 (заголовок типа документа)
- Sentence case: «Кассационная жалоба», «Отзыв на исковое заявление», «Ходатайство об истребовании доказательств».
- Для апелляционных/кассационных жалоб допустимо «по делу №…»: «Апелляционная жалоба по делу №А40-228691/2024» (повтор номера в шапке и Heading1 — норма для жалоб).
- Без нижней или иной границы (отличие от Heading2).
- **Дата подачи — отдельный абзац Normal** (Garamond 11pt, не bold) сразу после Heading1, НЕ через soft return внутри заголовка (иначе дата унаследует 16pt bold).

### Heading2 (доводы)
- Нижняя граница single 1pt чёрная; `keepWithNext = true` (не отрывать от следующего абзаца).
- Короткие (1 строка, ≤60–70 символов); длиннее — предложить сокращение с сохранением сути и ссылки на норму.
- **Автонумерация** через нумерованный список (в тексте номера нет). При обработке существующего документа — удалить текстовый префикс «1. » и привязать к списку.

### «ПРОШУ:»
- Normal (НЕ Heading2), Left, Garamond 14pt bold; `spaceBefore = 16pt`, `spaceAfter = 0` (список сразу под ним). Normal — чтобы не наследовать нижнюю границу Heading2.

### Выделение
- Ключевые фразы — серый highlight #D9D9D9 (Gray 25%), по одной фразе на Normal-абзац довода. **Жирный в теле НЕ использовать** — только highlight. Жирный — только заголовки.

## §2. Структура документа

### Базовый каркас (все типы)
1. Шапка (3 абзаца, Left, leftIndent=210pt).
2. Заголовок Heading1 (sentence case).
3. Дата подачи (Normal, `ДД.ММ.ГГГГ`, отдельный абзац).
4. Вводная часть.
5. Сущностная часть (по типу).
6. Просительная часть (по типу).
7. Приложения.
8. Подпись.

Различия между типами — только в сущностной и просительной частях.

### Шапка — варианты
- **Жалоба** (soft return `\n` внутри блоков): «В [суд-адресат]⏎через [нижестоящий суд]» (оба суда в одном абзаце, без почтовых адресов) · «Дело №[номер]» · «от [заявитель]⏎[адрес]».
- **Отзыв / ходатайство / заявление / возражение** (без «через…»): «В [суд]» · «Дело №[номер]» · «от [заявитель]⏎[адрес]».
- **Претензия** (адресат — контрагент): «Кому: [контрагент]⏎[адрес]» · «От: [заявитель]⏎[адрес]» · «Исх. №[номер] от [дата]» (опустить, если нет регистра). Номера дела нет.
- Порядок для суда: **суд → «Дело №…» → заявитель** (номер сразу после суда). Во всех: без ИНН/ОГРН/тел./email в шапке (блок «Кому» — только претензия).

### Жалоба (апелляционная / кассационная / надзорная)
**Особенность:** «ПРОШУ:» — **вверху**, после мини-разделов и ДО доводов. Порядок: мини-разделы → ПРОШУ → доводы → (опц.) Ходатайства → приложения → подпись.
1. **Мини-разделы** (подзаголовок Normal 12pt bold + текст):
   - «Обжалуемые судебные акты» — наименование акта (дата, № дела, инстанция), краткая резолютивная часть.
   - «Суть спора» — предмет требований, суммы (одной фразой).
   - «Участники спора:» — стороны с реквизитами (ОГРН, ИНН, адрес); на сторону: строка «наименование + роль», отдельные строки ОГРН/ИНН и адреса.
2. **«ПРОШУ:»** (Normal 14pt bold).
3. **Доводы** — Heading2 (автонумерация). Сразу под Heading2 — Normal-абзац с ключевым тезисом; **отдельный подзаголовок «Вывод:»/«Тезис:» НЕ вставлять** (первый абзац и есть вывод; highlight — внутри него). Внутри довода — опц. подразделы А/Б/В (Normal 11pt bold).
4. (опц.) **«Ходатайства»** — после доводов, перед приложениями: заголовок стилем как «ПРОШУ:» (Normal 14pt bold, НЕ Heading2), содержание — ListNumber с 1. Самостоятельное ходатайство (отдельный файл) — по структуре отзыва/ходатайства.

**Просительная часть жалобы — два варианта:**
- **Простой** (один список): «ПРОШУ:» + ListNumber (напр. «отменить …; отказать в удовлетворении требований»).
- **Расширенный** (три списка): «ПРОШУ:» + ListNumber (отменить/изменить/направить) · «При новом рассмотрении дела Заявитель просит суд:» (Normal, НЕ list) + новый ListNumber (с 1). Каждый ListNumber-блок начинается с **1** (нумерация НЕ сквозная).

### Отзыв / ходатайство / заявление / возражение
- Сущностная: вводная (на что) + аргументация (сплошной текст или 1–3 Heading2, без обязательных А/Б/В).
- Просительная: **один** ListNumber-блок. Для отзыва — обычно «отказать в удовлетворении исковых требований». Блоков «При новом рассмотрении» и трёх списков нет.

### Претензия
Вводная (договор/правоотношение) → описание нарушения (пункты договора/нормы, доказательства) → расчёт требования (таблица/текст) → «Требуем…» (Normal 14pt bold, формулировка «Требуем оплатить … в течение M дней с момента получения») → срок ответа (в днях; по ч. 5 ст. 4 АПК обычно 30, уточнять) → последствия (абзац про обращение в суд) → приложения → подпись. Блока «ПРОШУ:» с тремя списками нет.

### Правила нумерации
- Доводы: арабские (1, 2, 3…).
- Подразделы внутри довода: русские заглавные (А, Б, В…) — НЕ 4.1/4.2. Стиль: Normal 11pt bold, Left, без границы.
- Просительная / ходатайства / приложения: автонумерованный список Word, каждый блок с 1 (НЕ сквозная).
- Перечисления: маркированный список с тире «—» (U+2014).

### Правила списков
- Только реальные list items (стили Word), НИКОГДА текстовые «1.», «—», «•».
- Маркер тире — em-dash (U+2014), шрифт Garamond.
- Отступы: `leftIndent = 36pt`, `firstLineIndent = -18pt`.
- Элементы: со строчной буквы, через «;», последний — точка.
- Интервалы: внутренние `spaceAfter = 0`, последний `spaceAfter = 12pt`.

### Приложения
- «Приложение:» — Normal bold, `spaceBefore = 8pt` (НЕ list item).
- Пункты — ListNumber с 1, со строчной, через «;», последний — точка.
- **БЕЗ** «на N л.», «в N экз.», «на N стр.» — только название и реквизиты.
- Расположение: после просительной (в претензии — после «Последствий»), перед подписью.

### Подпись
- Один абзац, весь текст bold (Normal 11pt bold).
- «Представитель по доверенности» + **одна табуляция** + «Фамилия И.О.».
- Без организации, даты доверенности, линии подписи.

## §3. Цитаты и таблицы

### Цитаты
- Normal Garamond 11pt, НЕ курсив, `leftIndent = 35.4pt`, левая граница single 1pt чёрная, `spaceAfter = 8pt`.
- Ссылка-источник под цитатой: тот же отступ, выравнивание **Right**, граница продолжается (визуально «подпись» цитатного блока), НЕ курсив.
- Несколько цитат подряд — каждая ссылка сразу после своей цитаты.

### Таблицы — база
- Calibri 9pt, стиль Table Grid, `bandedRows`, `firstCol`, заголовочная строка bold + заливка **#D9D9D9**, `headerRowCount = 1`, spaceAfter в ячейках 12pt.
- Данные для таблиц НЕ оставлять текстовыми абзацами — конвертировать в таблицу.
- **Абзац после таблицы: `spaceBefore = 16pt` + `lineSpacing = 13.8pt`** (явно).

### Таблицы — выравнивание
- Числовые (суммы, проценты, дни, даты): Right. Текстовые (наименования, периоды, основания): Left. Заголовки колонок: обычно Left, для числовых допустим Center.

### Таблицы — числа и заголовки
- Денежные суммы: NBSP-разделители тысяч (`1 250 000`), десятичный разделитель — запятая (`15 320,50`); знак валюты — в заголовке колонки («Сумма, руб.»), не в каждой ячейке.
- Заголовки колонок — краткие, в одну строку; для числовых — единица через запятую («Сумма, руб.», «Период, дн.», «Ставка, %»); bold (часть заголовочной строки).

### Таблицы — итоговая строка (обязательна для расчётных с суммами)
- Bold во всех ячейках; верхняя граница single 1pt; заливка **#F2F2F2** (светлее заголовка); первая ячейка «Итого:»/«Всего:»; числовые — Right; пустые — прочерк «—».

### Таблицы — технические
- Повторение заголовочной строки на каждой странице; `keepTogether` для логически связанных строк (период + расчёт).

### Таблицы — когда таблица, когда текст
- Расчёт ≤2 строки → текст в скобках («45 дн. × 0,1% × 1 250 000 руб. = 56 250 руб.»).
- Расчёт ≥3 строки ИЛИ разные ставки/периоды → всегда таблица.
- Типовые колонки расчёта неустойки: «№», «Период», «Дней», «Сумма долга, руб.», «Ставка, %», «Неустойка, руб.».
- **Сравнительная таблица** (позиция истца / ответчика): две колонки равной ширины, заголовок bold + #D9D9D9, без числового форматирования и итоговой строки, текст Left.

## §4. Типографические микро-правила
- **«№»** слитно: `№А40-228691`, `№47`. Не «№ А40».
- **Кавычки** — «ёлочки»: ООО «Ромашка»; вложенные — „лапки“.
- **Тире**: длинное «—» (U+2014) в тексте и перечислениях; короткое «–» (U+2013) в диапазонах без пробелов (`01.01.2024–31.12.2024`, `п. 1–3`); дефис «-» в составных словах.
- **Даты** — `ДД.ММ.ГГГГ` (`01.05.2026`). НЕ «1 мая 2026 г.», «1.5.2026», «01-05-2026».
- **Денежные суммы** — NBSP (U+00A0) разделитель тысяч (`1 000 000 руб.`), запятая для копеек. **Прописью в скобках НЕ писать** (E.9). Валюта — «руб.»/«коп.» или «RUB», одно на документ.
- **Проценты** — слитно (`10%`, `0,1%`). Не «10 %».
- **Неразрывный пробел** перед «г.», «д.», «стр.», «оф.», «л.», «п.», «ст.», «ч.». Без двойных пробелов.

## §5. Проверка документа (валидация выхода)
Два блока: общие (все типы) + тип-специфичные. Отчёт — по уровням.

### Общие блоки
- **А. Структура.** Шапка есть, leftIndent=210pt, формат по типу; заголовок — Heading1 sentence case; дата — отдельный Normal после Heading1 (`ДД.ММ.ГГГГ`); подпись — последний абзац «роль[таб]ФИО».
- **Б. Определённые термины.** Термины с заглавной (Договор, Заявка, Исполнитель) — единообразно; родовое использование («рамочный договор») — исключение.
- **В. Перекрёстные ссылки.** «Довод 5», «пункт 4.12 Договора» — целевой раздел/пункт существует.
- **Г. Актуальность данных.** Ключевая ставка ЦБ, арифметика расчётов, суммы. *(Вне зоны оформления — только флаг; сверяет `legal-review`/`build-position`.)*
- **Д. Нумерация и пустые абзацы.** Нет пропусков/дублей в нумерации; нет пустых абзацев.
- **Е. Типографика.** По §4 (даты, суммы NBSP, № слитно, % слитно, нет прописи, тире в диапазонах).
- **Ж. Таблицы.** У абзаца после каждой таблицы `spaceBefore=16pt` + `lineSpacing=13.8pt`; шрифт Calibri 9pt; заголовок bold+#D9D9D9; расчётные — с итоговой строкой. Нет таблиц → «неприменимо».

### Тип-специфичные
- **Жалоба:** в шапке блок «через [нижестоящий суд]»; мини-разделы перед ПРОШУ; **ПРОШУ вверху**; доводы через Heading2 после ПРОШУ; просительная — простой или расширенный вариант.
- **Отзыв/ходатайство/заявление/возражение:** в шапке нет «через…»; просительная — один ListNumber-блок; отзыв — «отказать в удовлетворении исковых требований».
- **Претензия:** шапка «Кому:» вместо «В [суд]»; номера дела нет; денежное требование — с расчётом; конкретный срок ответа; абзац о праве на обращение в суд.

### Уровни отчёта
- **Критические** — влияют на юридическую силу/формальные требования (нет «через…» в кассации, неверная ставка/суммы, пропущенные ссылки на нормы, нет срока в претензии).
- **Предупреждения** — устаревшие данные, незаполненные плейсхолдеры, нечёткие формулировки.
- **Информационные** — стили заголовков, длина заголовков, единообразие терминологии.

## §6. Активная обработка существующего текста
Если на вход пришёл документ с чужим форматированием — до применения стиля.

### 6.1. Очистка
- **Шапка:** удалить почтовые адреса судов, ИНН/ОГРН, телефоны/email, блок контрагента (кроме претензии). Шапка — ровно 3 абзаца подряд, без пустых разделителей (схлопнуть пустые ПОСЛЕ редактирования шапки).
- **Heading1:** пояснение через «о/об/на» → оставить тип документа, пояснение → во вводную (кроме «по делу №…» для жалоб).
- **Тело:** удалить пустые абзацы (не ≥2 подряд), двойные пробелы, ручные текстовые маркеры перед конвертацией.

### 6.2. Добавления
- Дата подачи, если её нет после Heading1 (спросить/сегодня, `ДД.ММ.ГГГГ`).
- Интервал после таблиц (`spaceBefore=16pt` + `lineSpacing=13.8pt`).
- Подзаголовки мини-разделов жалобы, если их нет (Normal 12pt bold).

### 6.3. Сброс чужих параметров (на Normal-абзацах, ДО применения стиля)
- `alignment → Left` (кроме ссылки под цитатой — Right).
- `leftIndent → 0` (кроме шапки 210, цитат 35.4, списков 36).
- `firstLineIndent → 0` (кроме списков −18).
- `lineSpacing → 13.8pt` (не оставлять single/default).

### 6.4. Конвертация текстовых маркеров в реальные списки

| Маркер в исходнике | Действие |
|---|---|
| «1. », «2. »… | удалить маркер; ListNumber; новый список (с 1) на каждый блок (просительная / ходатайства / приложения) |
| «I. », «II. »… (римские) | удалить; ListNumber (Word превратит в 1, 2, 3) |
| «А. », «Б. »… (русские заглавные) | НЕ list item — подраздел (Normal 11pt bold, без границы), буква остаётся в тексте |
| «— », «• », «* » | удалить; ListBullet с маркером em-dash (U+2014) |
| «1.1», «1.2», «4.12» (вложенная) | не для процессуальных — в подразделы А/Б/В или предупредить |

## §7. Приоритеты и решения Сюзерена
- **Суммы прописью НЕ писать** (OPEN-ITEMS E.9).
- Коллизия «чек-лист просительной ↔ типографика» → приоритет **типографики / решения Сюзерена** (E.9).
- Актуальность ставки ЦБ / реквизитов практики `format-doc` не досверяет — зона `legal-review` / `build-position` / стека верификации.
- Текстовое качество формулировок (канцелярит, слова-паразиты, «простыни») — **вне** format-doc; это отдельный слой (внешний скилл `legal-design:formulations` / `/restyle`). format-doc оформляет текст как есть, не переписывает.

## §8. Маппинг на python-docx (нога рендера)
Что нативно и что требует OOXML (`docx.oxml`, `qn`). Хрупкие места — валидировать на реальном `.docx` в Cowork первыми.

| Правило | python-docx |
|---|---|
| Шрифт/размер/bold/цвет | нативно; для кириллицы продублировать `w:eastAsia` в `rPr` |
| lineSpacing 13.8pt, spaceBefore/After | нативно (`paragraph_format`) |
| Выравнивание, leftIndent, hanging −18pt | нативно |
| Heading1/2 стили | базовые стили + правка; **нижняя граница Heading2 — OOXML `w:pBdr`** |
| **Автонумерация Heading2 / ListNumber с restart-1 по блокам** | **OOXML-heavy**: numbering-определения (`numbering.xml`: abstractNum/num) + `numPr` на абзацах; каждый блок — свой `num` с `startOverride=1`. **Главный риск-узел.** |
| Маркер списка em-dash | OOXML `lvlText` с U+2014, шрифт Garamond |
| Границы абзаца (цитата — левая; Heading2 — нижняя) | OOXML `w:pBdr` |
| Character spacing = 0 (шапка) | OOXML `w:spacing w:val="0"` в `rPr` |
| Highlight #D9D9D9 | точный цвет — OOXML `w:shd`/`w:highlight` (не палитра WD_COLOR) |
| Таблицы: Table Grid, заливки #D9D9D9/#F2F2F2, границы, итоговая строка | стиль нативно; заливки/границы ячеек — OOXML `w:shd`, `w:tcBorders` |
| soft return в абзаце шапки | `run.add_break(WD_BREAK.LINE)` |
| Табуляция в подписи | `\t` в run |
| Интервал после таблицы | нативно, но найти абзац — проход по `document.element.body` (таблица → следующий абзац) |

**Вывод:** ~70% правил — нативный python-docx; критичные ~30% (нумерация с restart, границы, highlight, заливки) — OOXML. Нога **обязательно** валидируется на одном реальном документе в Cowork до интеграции в скиллы-генераторы.

## §9. Границы охвата
Покрывает **документы стороны**: жалоба (апелляционная / кассационная / надзорная), отзыв / ходатайство / заявление / возражение / пояснения, досудебная претензия.

**НЕ покрывает** (иная структура — отдельные шаблоны, отдельная задача): **мировое соглашение** (двусторонняя сделка, подписи обеих сторон — не «ПРОШУ»-документ) и **проект судебного решения** (`draft-judgment` — судебный акт: вводная / описательная / мотивировочная / резолютивная). Для них — прежний путь / ручное оформление, до появления отдельных шаблонов.
