# Legal-Review — Первичный правовой анализ дела

Скилл выполняет комплексную правовую проверку дела и генерирует набор аналитических документов в `.vassal/analysis/`. Работает с Opus для глубокого анализа. Каждый вывод оформляется в аудируемом формате (см. `shared/conventions.md` → Аудируемость выводов).

## Предварительные условия

- Дело инициализировано: `.vassal/case.yaml` существует.
- Документы приняты: `index.yaml` содержит хотя бы 1 документ.
- **Рекомендуется:** перед запуском провести `catalog` (чтобы в index.yaml были summary).
- Установлены зависимости: `${CLAUDE_PLUGIN_ROOT}/scripts/setup.sh`.

## Входные данные

1. **case.yaml** — карточка дела (стороны, суть спора, суд, представитель).
2. **index.yaml** — полный реестр документов с summary.
3. **md-зеркала** ключевых документов (скилл сам определяет, какие загрузить).
4. **Вводная Сюзерена** (опционально) — конкретные вопросы, которые нужно разобрать. Может быть передана как аргумент команды или файл.

## Алгоритм

### Фаза 0 — Проверка консистентности ФС ↔ индекс

Перед загрузкой контекста выполни Phase 0 по правилу из [shared/conventions.md](../../shared/conventions.md) → раздел «Проверка консистентности ФС ↔ индекс (Phase 0)». При обнаружении рассинхрона предложи Сюзерену запустить `update-index`. Если Сюзерен выбрал «продолжить» -- зафиксируй в выходном артефакте, что анализ выполнен на устаревшем индексе.

### Фаза 1 — Загрузка контекста

1. Прочитай `.vassal/case.yaml` — получи стороны, предмет спора, суд, даты.
2. Прочитай `.vassal/index.yaml` — получи список документов.
3. Определи **ключевые документы** для анализа — те, которые нужно читать целиком:
   - Договор (основной) и все допсоглашения
   - Претензия / ответ на претензию
   - Исковое заявление (если есть)
   - Отзыв на иск (если есть)
   - Гарантийные письма, акты сверки — если есть
4. Загрузи md-зеркала ключевых документов из `.vassal/mirrors/`.
5. Для остальных документов достаточно summary из index.yaml.
5.1. **Хук `study-evidence`:** проверь `.vassal/analysis/evidence-dossier.md`. Если досье есть — загрузи его как приоритетный источник фактуры (факты со ссылкой на лист, кросс-сверка сумм / реквизитов). Если нет — предложи Сюзерену (**не блокируя**) собрать его через `study-evidence` до анализа; при отказе работай на зеркалах как прежде, отметив в выходном артефакте «фактура не верифицирована study-evidence».
6. Если Сюзерен передал вводную / вопросы — прочитай и зафиксируй. **Если вводная просит оценить перспективы / шансы / риски по требованию (E.15а) — пометь: это зона `build-position`, legal-review её не выполняет; офер запустить `build-position` дашь в Фазе 3.** Первичные вопросы клиенту (что запросить, где пробелы) собираются как обычно в блоке g.

### Фаза 1.5 — Определение профиля дела

Профиль задаёт маршрут всех нормоёмких блоков (сроки, досудебка, подсудность). Источник маршрута — [`shared/category-routing.md`](../../shared/category-routing.md). Выполни ДО анализа:

1. Прочитай `case.category`. **Нормализуй:** `"экономические споры"` → `"исковое (АПК)"`; `null` / неизвестно → дефолт `"исковое (АПК)"` + **warning** Сюзерену («категория дела не указана — анализ по профилю АПК-искового; уточни `case.category`, если это банкротство / СОЮ / КАС»). Не падать.
2. Если `category = банкротство` — прочитай `case.bankruptcy.procedure` (ключ банкротного под-роутера `category-routing.md §4`).
3. По `category-routing.md` определи: `competent_court`, секции справочников для блоков c/d/e, нормы-маркеры профиля. Если `case.jurisdiction.competent_court` ещё пуст — заполни (owner — `legal-review`).
4. Зафиксируй профиль в шапке анализа аудируемо: «Профиль дела: {category}{ / procedure — для банкротства}; competent_court = {...}; маршрут блоков — `category-routing.md`».

Блоки c/d/e Фазы 2 применяют секции и нормы **профиля**, а НЕ дефолт-АПК-искового.

### Фаза 2 — Анализ (Opus)

> **verify-before-assert** (см. `shared/conventions.md`): перед каждым выводом сверь опорные факты, цитаты и реквизиты по md-зеркалам/оригиналам. Непроверяемое по материалам → не вывод, а пометка «факт не проверен — сверить» (уверенность «низкая»). Зеркало с `needs_manual_review: true` не используй как источник дословных формулировок/реквизитов.
> **Дословная сверка Пленумов (E.7 п.2):** цитируя конкретный пункт ППВС / Обзора, сверь **дословный текст пункта** (не только номер — содержание могло перепутаться) по B.3-верифицированному reference / коннектору / web-whitelist; не сверено дословно → пометка «пункт {X} ППВС № {Y} не сверён дословно — проверить текст», не подавать как установленную позицию Пленума.

Выполни каждый блок анализа. **Каждый вывод** оформляй в аудируемом формате:

```
**Вывод:** [заключение]
**Фактическое основание:** [на чём основано — факты из документов]
**Правовое основание:** [нормы, статьи, пункты]
**Источники:** [названия документов с датами — НЕ doc-ID; человек читает названия, а не идентификаторы]
**Уверенность:** высокая | средняя | низкая
**Недостающие данные:** [чего не хватает для уверенного вывода]
```

#### a) Ответы на вопросы Сюзерена → `analysis/answers.md`

Если Сюзерен задал конкретные вопросы — ответь на каждый в аудируемом формате. Если вопросов не было — пропусти этот блок.

#### b) Квалификация правоотношений → `analysis/qualification.md`

- Тип правоотношений (поставка, подряд, услуги, аренда, заём и т.д.)
- Применимые нормы (глава ГК РФ, специальные законы)
- Существенные условия договора — соблюдены ли
- Есть ли основания для признания договора незаключённым / недействительным

#### c) Пресекательные сроки → `analysis/deadlines.md`

**Маршрут по профилю** (Фаза 1.5): открой секцию `references/deadlines-reference.md`, указанную в [`category-routing.md §3.1`](../../shared/category-routing.md) для текущего профиля, и применяй её нормы-маркеры. НЕ переноси сроки АПК-искового на иной профиль.

Для каждого выявленного срока — таблица:

| Срок | Тип | Начало | Истечение | Статус |
|------|-----|--------|-----------|--------|
| ... | материальный / процессуальный | дата | дата | действует / истёк / под вопросом |

Что проверить — по профилю:
- **Исковые (АПК / ГПК), корпоративный:** исковая давность (общая 3 года ст. 196 ГК + специальные; течение ст. 200; приостановление ст. 202 — претензия/мораторий; перерыв ст. 203 — признание долга) + процессуальные сроки обжалования профиля (АПК — апелляция 1 мес / кассация 2 мес, §2; ГПК — §4).
- **Трудовой спор:** специальные сроки обращения **ст. 392 ТК** (1 мес по увольнению / 3 мес общий / 1 год по зарплате) — это материальные сроки, НЕ исковая давность ГК (deadlines §6).
- **Административное (КАС / АПК гл. 24):** срок обращения (КАС — ст. 219; АПК — 3 мес) — deadlines §5.
- **Банкротство:** реестровые сроки и расчёт даты закрытия реестра — под-блок ниже (P0).

**Банкротство — расчёт даты закрытия реестра (P0) → `analysis/registry-deadlines.md`:**
По банкротному под-роутеру ([`category-routing.md §4`](../../shared/category-routing.md)) и `case.bankruptcy.{procedure, publication}` рассчитай дату закрытия реестра требований кредиторов (наблюдение — 30 дн с публикации, ст. 71; конкурс — 2 мес с публикации, ст. 142 — нормы из `deadlines-reference §3` как написано, не выводи свои). Запиши в `case.bankruptcy.registry_close_date` + `registry_close_basis` (норма + от какой публикации считал). Пропуск = зареестровое требование (потеря очерёдности) — вынеси как **критичный дедлайн**. При релевантности позиции клиента проверь также сроки оспаривания сделок (гл. III.1), субсидиарки (ст. 61.14) и **убытков (гл. III.2)**. Сохрани отдельным файлом `analysis/registry-deadlines.md`.

**⚠ Убытки — отдельный срок, а не разновидность субсидиарного.** Если по делу заявлено (или может быть заявлено) требование о возмещении убытков — по ст. 61.20, по ст. 61.13 либо с арбитражного управляющего по п. 4 ст. 20.4, — **не бери «3 + 3 + 10» из п. 5 ст. 61.14**: у убытков специального срока нет, он общий по ст. 196 ГК, а начало течения считается по п. 68 Постановления Пленума ВС № 53 (от появления у должника **реальной возможности узнать**, а не от нарушения). Правило зависит от **природы** убытков — их три. Разбор — [`deadlines-reference.md`](references/deadlines-reference.md) → «Срок по требованию о возмещении убытков (гл. III.2)»; дословные цитаты и отличия от субсидиарки — [`bankruptcy-damages.md` §8 и §8.7](../build-position/references/bankruptcy-damages.md) (роль **E**). Два хода, которые здесь чаще всего теряют: **ждать исхода жалобы по ст. 60 нельзя** — срок по убыткам всё это время течёт (п. 21 Обзора-2024), и **восстановление по убыткам, как правило, исключено**, потому что требование идёт от имени должника-юрлица.

**Нет даты публикации → `registry_close_date: null` (E.15б).** Если `bankruptcy.publication.date` пуст / неизвестен (зрелое дело, клиент пришёл поздно, публикация о процедуре не в материалах) — P0-поле **нерассчитываемо**. Это **валидный исход, не провал и не «падение»**: поставь `registry_close_date: null`, а `registry_close_basis` заполни объяснением — «публикация о {procedure} не найдена в материалах / не наступила — реестровый срок не рассчитан; получить дату публикации ЕФРСБ (fedresurs.ru) или Коммерсантъ (№ сообщения) и пересчитать». Вынеси запрос даты публикации в `questions-to-client.md` как **критичный [!]**, а в `registry-deadlines.md` отметь «P0 не рассчитан — нет даты публикации; риск пропуска реестрового срока не оценён». Остальной анализ (подсудность, полнота, квалификация, прочие сроки) выдаётся штатно — одно недостающее поле не блокирует заключение.

#### d) Досудебный порядок → `analysis/pretrial.md`

**Маршрут по профилю** (Фаза 1.5): открой секцию `references/pretrial-reference.md` по [`category-routing.md §3.2`](../../shared/category-routing.md). Досудебный порядок профиль-специфичен — НЕ применяй ч. 5 ст. 4 АПК к небанкротному / неисковому профилю по умолчанию.

- **Исковое (АПК), корпоративный:** обязательный претензионный порядок ч. 5 ст. 4 АПК (30 кал. дней) + договорный порядок; претензия направлена / получена / в срок? (pretrial §1–§4).
- **Банкротство:** классическая претензия НЕ требуется; вместо неё — предъявительский ценз кредитора (просуженность долга / уведомление на Федресурсе, ст. 7 п. 2.1) — проверь готовность кредиторского входа (pretrial §5).
- **Исковое (ГПК):** досудебка по ГПК — потребители / ОСАГО / ЖКХ (pretrial §6).
- **Трудовой спор:** досудебный порядок НЕ обязателен; КТС / ГИТ — альтернативы, не обязательный порядок (pretrial §9).
- **Административное:** налоговые — обязательное досудебное обжалование (ст. 138 НК, §7); иные ненорм. акты — §8.
- Вывод: соблюдён / не соблюдён / частично / **не требуется для профиля**.

**Развилка убытков — проверять всегда (B.20).** По п. 43 ППВС № 18 к денежным спорам абз. 1 ч. 5 ст. 4 АПК относятся **убытки по гл. 25 ГК (договорные)** — претензия обязательна. Убытки из причинения вреда (гл. 59 ГК) и регрессное требование изъяты (п. 44 ППВС № 18) — не нужна. Квалификация решает исход; при неоднозначности фиксируй развилку в `pretrial.md`, а не выбирай молча.

**Точка отсчёта срока (B.20).** По общей норме АПК срок течёт **со дня направления** претензии, а не получения. По специальным нормам иначе: транспорт — со дня получения (ст. 124 УЖТ, ст. 40 ФЗ № 259-ФЗ, ст. 163 КВВТ, ст. 407 КТМ), связь — со дня регистрации (п. 4 ст. 55 ФЗ № 126-ФЗ). Бери точку отсчёта из колонки «Точка отсчёта» таблицы `pretrial-reference.md`, не по умолчанию.

**Проверка отправления по трекеру (G.2) — штатный опциональный шаг.** Вывод о досудебном порядке стоит на дате направления, поэтому **здесь** трекер опрашивается автоматически (правило — [shared/conventions.md](../../shared/conventions.md) → «Проверка статуса почтового отправления (G.2)»):
- **Проба коннектора** `Post_Tracker` дешёвым `tracking_sources`. Нет ответа / сервер отсутствует → **тихий skip**, работаем по квитанциям, вывод делаем как раньше. Сервер локальный и отваливается в течение сессии — пробуй перед обращением.
- **Что опрашиваем:** записи `case.mailings[]` с `purpose: досудебный-порядок`, у которых есть `track` и не заполнен `delivered_date`. **Реестр пуст, а `pretrial.tracking` заполнен** (карточка до v9) — заведи запись `mailings[]` из того, что уже известно (`track`, `sent_date` = `pretrial.pretrial_date`, `to_address` = `pretrial.sent_to_address`, `address_basis`, `method` = `pretrial.sent_method`, `purpose: досудебный-порядок`), и работай с ней: иначе результат опроса записывать некуда и он теряется. Это и есть путь апгрейда карточки v8 → v9.
- **Что пишем:** `sent_date`, `delivered_date`, `delivery_status`, `source: tracker`, `source_checked_at`. ⚠️ Данные из **неофициального** эндпоинта: вывод, который на них опирается, помечай «⚠ дата из трекера, с квитанцией не сверена — проверить перед подачей». Квитанция (`source: document`) **старше** трекера; расходятся — верить документу и сказать о расхождении.
- ⚠️ **Возврат «за истечением срока хранения» — не провал направления, но и не автомат.** Риск ложится на адресата по ст. 165.1 ГК, **если письмо ушло по надлежащему адресу** (п. 63, 67–68 ППВС № 25: ЕГРЮЛ по п. 3 ст. 54 ГК либо адрес, названный самим адресатом). Смотри `address_basis` записи: основание надёжное → порядок соблюдён; адрес взят иначе или устарел → **флаг Сюзерену**, а не вывод в любую сторону.

**Хук на `draft-claim` (B.20).** Если по итогам вывод — **«не соблюдён»** или **«частично»**, а порядок обязателен (`pretrial.required = true`), предложи Сюзерену в Preview отдельной строкой:

> «Досудебный порядок обязателен ({норма}), претензия не направлена. Запустить `draft-claim` — подготовить претензию?»

Запиши `pretrial.required` / `required_source`; остальные поля блока `pretrial` заполняет `draft-claim` (см. `shared/case-schema.yaml` → ownership). Если пришла **входящая** претензия к нашему клиенту — тот же хук, но с `mode = reply`.

**Хук на `enforcement-adjustment` (F.21).** Если в материалах есть признаки **стадии исполнения** — исполнительный лист, постановление о возбуждении исполнительного производства, требование пристава, постановление о взыскании исполнительского сбора, — зафиксируй известное в `case.enforcement` (реквизиты ИЛ, номер ИП, пристав) и предложи Сюзерену в Preview отдельной строкой:

> «По делу идёт исполнительное производство ({реквизиты}). Если исполнение затруднено — `enforcement-adjustment` подготовит заявление об отсрочке, рассрочке или изменении способа и порядка исполнения (ст. 324 АПК / ст. 203, 434 ГПК / ст. 358 КАС). Если заявление подал оппонент — тот же скилл в режиме возражений.»

Правовой профиль — [references/enforcement-reference.md](references/enforcement-reference.md). **Три развилки, которые надо назвать сразу, а не после:**
- акт **обжалуется** → нужна не отсрочка, а приостановление исполнения, и его вправе дать только апелляция / кассация / надзор (п. 29 ППВС № 50 **от 17.11.2015**) → `appeal` / `cassation`;
- взыскатель **готов договориться** → дешевле мировое на стадии исполнения → `settlement` (`mode='agreement'`, `stage='enforcement'`);
- речь про отсрочку уплаты **госпошлины** → это ст. 333.41 НК, другой институт (`filing-fees.md` §4).

⚠️ В плагине два разных акта под номером 50: **ППВС № 50 от 17.11.2015** (исполнительное производство) и **ППВАС № 50 от 18.07.2014** (примирение). Всегда с датой и префиксом.

#### e) Подсудность → `analysis/jurisdiction.md`

**Шаг 0 (обязательный, до всего остального) — специальная норма о компетенции в профильном законе (F.6).**

Общие правила кодексов (субъектный критерий ст. 27 АПК → предметный → закрытый перечень ст. 33) применяются **только после** проверки профильного закона. Специальная норма о подведомственности бьёт общий критерий, и её отсутствие в кодексе ничего не доказывает — она живёт в отраслевом законе.

1. Определи, из каких отношений вырос спор и **какой отраслевой закон** их регулирует: банкротство и профессиональная деятельность арбитражного управляющего — ФЗ-127; страхование — ФЗ-4015-1 / ФЗ-40; корпоративные — ФЗ-14 / ФЗ-208; интеллектуальные права — ч. IV ГК; закупки — ФЗ-44 / ФЗ-223; деятельность СРО — профильный закон о соответствующей СРО.
2. **Открой этот закон** и проверь, есть ли в нём норма о том, каким судом рассматриваются споры этой категории. Не по памяти — по тексту (B.3-верифицированный reference / коннектор / web-whitelist).
3. Только после этого иди к субъектному и предметному критериям кодекса.

**Проверяемый след — обязателен в выводе:** строка «**Специальная норма:** {норма + где сверена} | не найдена (проверен {закон})». Вывод о компетенции без этой строки не выдаётся. Пустой результат — тоже результат: он показывает, что закон открывали.

⚠️ **Подтверждающая практика не заменяет шаг 0.** Боевой промах: компетенция выводилась от общего критерия, поиск практики дал ложную уверенность, а специальная норма (п. 12 ст. 20 ФЗ-127 — споры, связанные с профессиональной деятельностью АУ, включая возмещение убытков и отношения с СРО) осталась непрочитанной. Итог — иск переписывали в двух делах подряд с пересчётом пошлины. Практика подтверждает найденное в законе, а не заменяет его чтение.

Готовый разбор для споров с арбитражным управляющим вне рамок дела о банкротстве — `references/jurisdiction-reference.md §5`, подраздел «Споры с арбитражным управляющим вне рамок дела о банкротстве».

**Маршрут по профилю** (Фаза 1.5): открой секцию `references/jurisdiction-reference.md` по [`category-routing.md §3.3`](../../shared/category-routing.md).

- **Исковое (АПК), корпоративный:** компетенция (ст. 27/33; корп. — 225.1); территориальная — общая ст. 35 / договорная ст. 37 / исключительная ст. 38 АПК; пророгационная / дерогационная оговорка (§1–§4).
- **Банкротство:** по месту нахождения должника (ст. 33 ФЗ-127); обособленные споры (ст. 60); проверь «миграцию должника» перед банкротством (§5). **Убытки гл. III.2 — четыре маршрута, форум у каждого свой** (§5, таблица маршрутов): в идущем деле — обособленный спор (п. 1 ст. 61.20, п. 53 абз. 1 ППВАС № 35); при возврате заявления или прекращении производства **за отсутствием средств** — специальная норма **п. 5 ст. 61.20** (суд, возвративший заявление либо прекративший производство) — это норма для **Шага 0** выше; корпоративный иск участника — глава 28.1 АПК; после завершения конкурсного производства специального форума **нет**, общие ст. 35–38 АПК. Крайняя точка для требования к управляющему — **запись о ликвидации должника в ЕГРЮЛ**, а не завершение процедуры.
- **Банкротство, субсидиарная ответственность гл. III.2 — свои маршруты и своя специальная норма о форуме** (§5, таблица маршрутов субсидиарки). В идущем деле — обособленный спор: **п. 1 ст. 61.16** (заявления по основаниям главы III.2 рассматриваются «в рамках дела о банкротстве должника»). **Вне дела по ст. 61.11 — п. 2 ст. 61.19**: «рассматривается арбитражным судом, рассматривавшим дело о банкротстве». **Вне дела по ст. 61.12 — п. 5 ст. 61.19**: тот же суд (ранее рассматривавший дело и прекративший производство либо вернувший заявление уполномоченному органу). Это нормы профильного закона о форуме, то есть материал **Шага 0**, а не вывод из ст. 35–38 АПК.
  - ⚠ **Порядок для обоих маршрутов — глава 28.2 АПК**, хотя п. 5 говорит «по правилам искового производства»: п. 51 Постановления № 53 распространил групповой режим на заявления «как по основаниям ст. 61.11, так и по основаниям ст. 61.12» (аналогия закона, ч. 6 ст. 13 АПК). Буквальное чтение п. 5 лишает спор по ст. 61.12 публикации, присоединения и преклюзии.
  - ⚠ **Выход вне дела открывает не любое прекращение дела**, а завершение конкурсного производства либо прекращение **в связи с отсутствием средств, достаточных для возмещения судебных расходов** (п. 3 ст. 61.14, п. 31 Постановления № 53). Мировое, погашение долга, отказ заявителя маршрута не дают. **По ст. 61.13 внебанкротного маршрута нет вовсе** — право на подачу существует только в ходе процедуры (п. 1 ст. 61.14).
  - Проверь **п. 3 ст. 61.19**: производство прекращается, если аналогичное заявление по тому же основанию и к тому же лицу уже рассмотрено в деле о банкротстве (для любого внебанкротного заявления то же даёт п. 57 абз. 1).
  - Если клиент — **кредитор**, скажи ему о преклюзии сразу: не присоединившийся к чужому внебанкротному заявлению утрачивает право предъявить требование к тому же лицу по тем же основаниям (п. 57 абз. 2 Постановления № 53, ч. 7 ст. 225.16 АПК) — **кроме случаев объективной невозможности присоединения** (например, решение о его долге ещё не вступило в силу). Это не вопрос подсудности, но выясняется здесь же, при разборе форума.
  - ⚠ **Не путать с внебанкротной субсидиаркой по п. 3.1 ст. 3 Закона об ООО** (после исключения общества из ЕГРЮЛ): дела о банкротстве нет, специального форума нет, подсудность — общие ст. 35–38 АПК.
- **Исковое (ГПК):** ст. 28–32 ГПК (§7).
- **Трудовой спор:** ст. 24/28/29 ГПК; альтернатива по выбору работника; **договорная подсудность ИСКЛЮЧЕНА** (§10).
- **Административное:** КАС — §8; АПК (гл. 24/25) — разграничение §9.
- Если дело уже подано — проверь, в правильный ли суд.

**Машиночитаемый статус вывода (F.9).** Вывод о компетенции — единственный, который скиллы ниже по конвейеру принимают как данность, поэтому кроме аудируемого блока запиши его статус в карточку (зона ownership `legal-review`):

- `case.jurisdiction.confidence` — `высокая | средняя | низкая`, та же оценка, что в аудируемом выводе;
- `case.jurisdiction.special_norm_checked` — `true | false`: прогонялся ли шаг 0 (профильный закон открыт);
- `case.jurisdiction.special_norm` — найденная специальная норма или `null`.

Уверенность **ниже высокой** — не просто поле отчётности: по правилу [shared/conventions.md](../../shared/conventions.md) → «Статус вывода о компетенции (F.9)» это **блокирует первичную подачу** (иск / заявление по существу / заявление об обеспечительных мерах) до явного подтверждения Сюзерена. Скажи об этом прямо в сводке Фазы 3 — вопрос дешевле решить сейчас, чем на этапе подачи.

#### h) Госпошлина — детект потребности (F.7)

`legal-review` пошлину **не считает** (владелец расчёта — `build-position`, он владеет `case.amounts.court_fee`), но обязан заметить, что она потребуется, и не дать уйти в подачу с цифрой «на глаз».

1. **Потребуется ли пошлина** — по стадии и типу предстоящего обращения: первичный иск / заявление, заявление об обеспечительных мерах (оплачивается **отдельно от иска, за каждое**), апелляционная / кассационная жалоба, заявление о выдаче исполнительного листа. Если по делу ничего не подаётся (анализ для оценки) — блок пропускается.
2. **Какая секция справочника** — по [`category-routing.md §3.4`](../../shared/category-routing.md) → `references/filing-fees.md`. Назови секцию явно: «пошлина — `filing-fees.md` §{X}».

4. **Льготы** — проверь применимость (`filing-fees.md` §1.4 для АС / §2.4 для СОЮ; для трудовых споров работник освобождён).

#### i) Обеспечительные меры — детект и хук на `prepare-hearing`

**Выход:** отдельного файла нет — строка в сводке Фазы 3, **строка в `history.md`** и, при нехватке данных, вопрос в `questions-to-client.md`. **Детект (шаг 1) выполняется на любом профиле; проработанная развилка шага 2 — банкротная**: глава III.2 (там специальные нормы — расширенный объём ареста и трёхдневное заседание) **и требование к арбитражному управляющему по п. 4 ст. 20.4**, которое разбирается отдельным буллетом ровно потому, что эти специальные нормы к нему не применяются. На небанкротном профиле ограничься детектом, общей проверкой соразмерности (ч. 2 ст. 91 АПК / ст. 140 ГПК) и офером `prepare-hearing`.

1. **Детект по материалам.** Признаки принятых мер: определение об обеспечении иска / заявления, арест имущества или счетов, запрет регистрационных действий, постановление пристава, вынесенное во исполнение такого определения. Ищи по `index.yaml` и зеркалам. Ничего не найдено — запиши «по материалам меры не прослеживаются» и **задай прямой вопрос** Сюзерену (в `questions-to-client.md` — [*] важный): «Меры по делу заявлялись?». Значение **«не заявлены» ставится только по подтверждению Сюзерена либо по прямому указанию в материалах** (отказ в обеспечении, отсутствие мер в определении о принятии заявления); пустой поиск сам по себе такого вывода не даёт.
2. **Развилка по роли клиента — банкротный профиль, спор о привлечении к ответственности: глава III.2 либо п. 4 ст. 20.4** (третий буллет — про второе основание, и он нужен именно потому, что глава III.2 к нему не применяется).
   - **Клиент — ответчик по спору главы III.2** (субсидиарная ответственность **или** убытки по ст. 61.20 — независимо от того, признан ли он контролирующим лицом: п. 5 ст. 61.16 сформулирован родово, «по спору о привлечении к ответственности в соответствии с настоящей главой»). Проверь, разрешён ли при принятии мер вопрос о средствах, разумно необходимых для поддержания жизнедеятельности ответчика-физлица и его иждивенцев, и об оплате услуг представителей в разумных пределах (п. 36(1) Постановления № 53, новелла от 23.12.2025). **Не разрешён — это не обжалование определения целиком, а частичная отмена мер по ст. 97 АПК**, и заявляется она сразу.
   - **Клиент — заявитель (управляющий, кредитор, уполномоченный орган).** Если меры не заявлены — назови это дефицитом позиции, а не опцией: по абз. 2 п. 5 ст. 61.16 арест доступен и в отношении имущества **лиц, подконтрольных ответчику** по подп. 2 п. 4 ст. 61.10 (по общему правилу ч. 1 ст. 91 АПК чужое имущество арестовать нельзя — это специальная норма главы III.2 и **к спору об убытках не относится**: абзац второй сужен до «лица, привлекаемого к субсидиарной ответственности»). Меры сохраняют действие и на период приостановления рассмотрения заявления (п. 7 абз. 3 ст. 61.16), а приостановление длится годами.
   - **Клиент — ответчик-арбитражный управляющий** (требование по **п. 4 ст. 20.4**, а не по ст. 61.20). ⚠ **Обе ветки выше сюда не переносятся.** Спор идёт не по главе III.2, поэтому ст. 61.16 к нему не применяется: **п. 36(1) Постановления № 53 недоступен** (он привязан к п. 5 ст. 61.16), расширенного ареста имущества подконтрольных лиц тоже нет. Меры — по **общим ст. 90–93 АПК**, а отмена и **частичная отмена — по ст. 97 АПК**: ⚠ **недоступен не механизм, а готовый стандарт п. 36(1)**. Ст. 97 работает в любом деле (сам п. 36(1) её только называет), поэтому ходатайство подать можно — но обосновывать придётся **соразмерностью (ч. 2 ст. 91 АПК)** и по аналогии, а не ссылкой на п. 36(1) как на прямое основание. Не обещай клиенту, что вопрос решится автоматически, и не говори, что частичной отмены здесь нет вовсе — неверно и то, и другое.
   - **Срок рассмотрения — не «три дня» по умолчанию.** По общему правилу заявление рассматривается без извещения сторон не позднее следующего дня (ч. 1.1 ст. 93 АПК, п. 36 Постановления № 53). **Если** суду нужно заслушать объяснения, он вправе назначить заседание — и вот оно проводится «в срок, не превышающий трех рабочих дней» (п. 5 ст. 61.16). Обещать клиенту трёхдневный срок как норму — ошибка.
3. **Офер в Preview** — отдельной строкой, неблокирующий:

> «По делу приняты обеспечительные меры ({реквизиты определения}). {Вопрос о средствах на жизнь и на представителя не разрешён — доступна частичная отмена по ст. 97 АПК со ссылкой на п. 36(1) ППВС № 53. | Ответчик — арбитражный управляющий: п. 36(1) не применяется (спор вне главы III.2), но частичная отмена по ст. 97 АПК доступна — обосновывать соразмерностью по ч. 2 ст. 91 АПК. | Клиент на стороне атаки, меры не заявлены — доступен арест имущества подконтрольных ответчику лиц.} Запустить `prepare-hearing` — подготовить {ходатайство о частичной отмене мер | заявление об обеспечении}?»

**Куда идти за материалом.** По субсидиарной ответственности обе стороны вопроса закрывает **[`bankruptcy-subsidiary-liability.md` §10.5](../build-position/references/bankruptcy-subsidiary-liability.md)** (роль **C**): там и наступательный объём ареста, и п. 36(1) с готовым ходом по ст. 97 АПК. Роль **E** ([`bankruptcy-damages.md` §11.3, §12.9](../build-position/references/bankruptcy-damages.md)) открывают, **если требование квалифицировано как убытки**: правило п. 36(1) там то же, но обоснование другое — оно применяется напрямую через родовую формулировку п. 5 ст. 61.16, а не через отсылку п. 1 ст. 61.20, и расширенный арест по абзацу второму туда не переносится. **Ответчик — арбитражный управляющий:** [`bankruptcy-damages.md` §11](../build-position/references/bankruptcy-damages.md) (четвёртый маршрут — там сказано, что вся ст. 61.16 к этому спору не применяется, а меры идут по общим ст. 90–93 АПК), **§11.3** (последнее предложение абзаца о п. 36(1) — само изъятие) и **§12.12** (сводная таблица: какие инструменты §12.9 к спору с управляющим не применяются и почему). ⚠ **§12.9 для этого не подходит** — там общая строка про частичную отмену, написанная для спора об убытках по главе III.2, где п. 36(1) как раз применяется.

⚠️ **Заявление об обеспечительных мерах — первичная подача в смысле F.9.** Если вывод блока e о компетенции (та же оценка, которую ты запишешь в `case.jurisdiction.confidence`; на повторном прогоне — значение из карточки) **ниже высокой**, офер выдаётся с оговоркой: подача заблокирована до подтверждения форума Сюзереном (см. блок e и сводку Фазы 3). Пошлина по такому заявлению — **отдельная, за каждое** (блок h).

#### f) Качество и полнота документов → `analysis/completeness.md`

Для каждого документа из index.yaml оцени:
- Читаемость (по полю quality в индексе)
- Полнота (completeness): есть ли все страницы, подписи, печати
- Юридическая значимость (оригинал / копия / скан)

**Сверка полноты (заявлено vs вложено).** Если в описи вложения / расчёте / перечне приложений заявлено N единиц (платёжки, документы) — сверь N и их реквизиты с фактически извлечёнными из файла-доказательства; итоговые суммы проверь пересчётом (сумма единиц = заявленный итог). Расхождение → пометь документ `needs_manual_review: true` и вынеси явный флаг Сюзерену (риск недоказанной суммы / отсутствующего приложения). Не переноси заявленное число, не убедившись в фактическом.

Сформируй список:
- **Имеющиеся доказательства** — что есть и в каком состоянии
- **Отсутствующие документы** — что следует запросить у клиента
- **Документы, требующие дополнительных действий** — нотариальное заверение, апостиль, перевод, запрос оригинала

- Уточнения по позиции клиента (что хочет: взыскать, отбить, мировое?)

Каждый вопрос пометь приоритетом: [!] критичный | [*] важный | [ ] желательный.

**Банкротный профиль, если в деле есть или ожидается требование об убытках (гл. III.2)** — четыре вопроса идут **критичными [!]**, потому что без них не определяется ни право на подачу, ни форум, ни срок ([`bankruptcy-damages.md` §0.1, §6, §1.4](../build-position/references/bankruptcy-damages.md)):
- **Когда введена ПЕРВАЯ процедура** (определение о введении наблюдения, а не о принятии заявления) — от неё зависит форум: до первой процедуры это обычный корпоративный иск, после — только обособленный спор.
- **Статус заявителя** (управляющий / конкурсный кредитор / работник или бывший работник / уполномоченный орган / участник / руководитель) — круг по п. 2 ст. 61.20 шире, чем по п. 3, а по ст. 61.13 круг задаёт п. 1 ст. 61.14 и **руководителя с участником в нём нет**; по п. 27 Постановления № 53 кредитору может потребоваться **предварительное включение требования в реестр**.
- **Если производство прекращено — по какому основанию.** Маршрут «взыскать в свою пользу» (пп. 3–5 ст. 61.20) работает **только** при возврате заявления или прекращении «в связи с отсутствием средств, достаточных для возмещения судебных расходов». Прекращение по мировому, из-за погашения долга или отказа заявителя этого маршрута не даёт. ⚠ Если производство прекращено **до введения процедуры**, реестра не существует — и заявителя по убыткам не остаётся вовсе (для субсидиарки такой случай прямо покрыт п. 3 ст. 61.14, в ст. 61.20 такой оговорки нет).
- **Когда и кто узнал** о нарушении и о надлежащем ответчике; кто был директором или участником в этот момент и не связан ли он с нарушителем — от этого считается давность (п. 68 Постановления № 53).

**Банкротный профиль, если в деле есть или ожидается требование о привлечении к СУБСИДИАРНОЙ ответственности (глава III.2)** — вход в вопросы даёт чек-лист «первых пяти минут» [`bankruptcy-subsidiary-liability.md` §0.1](../build-position/references/bankruptcy-subsidiary-liability.md) (роль **C**): **восемь данных, и под каждым названо, где оно берётся**. То, что целиком закрывается публичными источниками (стадия дела и форум — по картотеке; статус заявителя и реестровое условие — по материалам дела), у клиента не спрашивают. Критичными [!] идут пять: те, которых нет нигде, кроме клиента, **и те, где публичный источник даёт лишь формальную сторону, а содержательную знает только клиент** (за записью ЕГРЮЛ — фактический контроль и выгодоприобретение; за строкой картотеки — что в том споре обсуждалось по существу):

- **Бухотчётность на обе даты** — до вменяемого воздействия и после него, плюс сама дата объективного банкротства. Без динамики показателей не решается развилка «субсидиарка или убытки» (тест существенности оценивается **по факту**, п. 20 абз. 1 и п. 16), а дата ОБ — обязательный элемент состава (§3.1, §3.4). Где брать, если у клиента нет: ГИР БО, анализ финансового состояния АУ, заключение о признаках преднамеренного банкротства.
- **Основание требования — ст. 61.11 · ст. 61.12 · ст. 61.13.** От него зависит **всё остальное**: круг заявителей, размер (весь реестр против «окна» обязательств), доступность приостановления по п. 7 ст. 61.16 (только по ст. 61.11) и адресат денег по п. 4 ст. 61.18 (§6, §7, §10.1, §11.6).
- **Кто ответчик и по какому признаку статуса** — руководитель · руководитель управляющей организации · **член исполнительного органа** · **ликвидатор** · член ликвидационной комиссии (подп. 1 п. 4 ст. 61.10) · мажоритарий · выгодоприобретатель · номинальный · фактический · соучастник по документации без статуса КДЛ. **Порог мажоритария различается по форме общества** (подп. 2 п. 4 ст. 61.10): АО — «пятьюдесятью и более процентами голосующих акций», ООО — «более чем половиной долей уставного капитала», либо более половины голосов в общем собрании, либо право назначать (избирать) руководителя — самостоятельно **либо совместно с заинтересованными лицами**. Участник ООО ровно с 50 % под презумпцию не подпадает: там нужен фактический контроль. Признак решает, какая презумпция статуса применима и доступно ли номиналу снижение либо освобождение (§4.3, §4.6, §4.7). Проверять по ЕГРЮЛ **на дату нарушения**, а не на сегодня.
- **Когда и кто узнал об основаниях — отдельно по каждому крупному кредитору.** Давность применяется **к части требования**: осведомлённость одного кредитора не рушит требование целиком, но снимает его долю (§9.1). Один вопрос «когда узнали» здесь недостаточен.
- **Что уже было по этому лицу** — параллельные и завершённые споры (субсидиарка, убытки, оспаривание сделок) и обсуждалась ли в них существенность воздействия. Тождественность считается **по фактическим обстоятельствам, а не по нормам** (§9.4); отсюда же преклюзия кредитора, не присоединившегося к внебанкротному иску (§10.9), и возможность второго захода по п. 20(1) (§2.4).

**Два режима распознать сразу, в первом же разговоре** (§0.1, врезка): приняты ли **обеспечительные меры** — если да, разрешён ли вопрос о средствах на жизнь ответчика-физлица и на оплату представителя (частичная отмена по ст. 97 АПК работает в первые дни; детект и офер — **блок i выше**); и **не собирается ли сам ответчик-физлицо в личное банкротство** — по п. 6 ст. 213.28 выигранная субсидиарка переживает освобождение гражданина от обязательств **безусловно**, а убытки сохраняются, только если причинены «умышленно или по грубой неосторожности». Это довод при выборе требования, а не деталь исполнения.

⚠ **Квалификация неочевидна → спрашивай по обоим спискам.** Граница C ↔ E проходит по тесту существенности воздействия, а не по факту банкротства, и суд квалифицирует требование самостоятельно, как бы его ни назвал заявитель. Пока развилка не решена, недостающий вопрос дешевле задать, чем потом досылать.

## Идемпотентность

**Детект повторного прогона.** Если в `.vassal/analysis/` уже есть файлы от прошлого `legal-review` — это повторный запуск. Сначала через Phase 0 выясни, появились ли новые документы с прошлого прогона. Затем предложи Сюзерену выбор:
- **полный** — переанализировать всё заново;
- **инкрементальный** — учесть только новые документы и обновить затронутые блоки.

**Версионирование, не перезапись.** Новые файлы анализа создаются с `supersedes`-ссылкой на предыдущие (см. `shared/conventions.md` → «Двухуровневое сохранение для аналитических скиллов»); старые **не удаляются** (история мысли по делу). В preview покажи diff (что изменилось с прошлого раза).

**Архивация сводного (F.12).** Перед записью нового `* Предварительный анализ документов.md` уведи предыдущий в `Архив/` (`mkdir -p`, затем `mv`) — в корне остаётся **ровно один**. Файлы в `.vassal/analysis/` (`qualification.md`, `deadlines.md`, `pretrial.md`, `jurisdiction.md`, `completeness.md`, `questions-to-client.md`, `answers.md`) **не архивируются**: служебная зона остаётся на месте, а `questions-to-client.md` / `answers.md` вообще аппенд-только. **Изменений нет → снимка нет:** инкрементальный прогон, не изменивший выводов, нового сводного файла не создаёт.

## Граничные случаи

- Нет ни одного документа в индексе → сообщи, что анализировать нечего, предложи intake.
- Нет договора → анализ возможен, но пометь: «Договор отсутствует, выводы по квалификации предварительные».
- Данных недостаточно для вывода → не додумывай, честно укажи «Недостающие данные» и уверенность «низкая».
- Противоречия между документами → зафиксируй в `completeness.md` и в `questions-to-client.md`.
- Нестандартный спор (не из ГК) → примени ту же структуру анализа, адаптируй нормативную базу.
