# Build-Position — Выработка правовой позиции

> **Операционный справочник:** [references/key-doctrines.md](references/key-doctrines.md) — ключевые доктринальные позиции ВС РФ для аргументации в 1 инст. (опирается прежде всего на ППВС № 46 от 23.12.2021 -- основное действующее разъяснение по АПК в 1 инст.; 8 разделов: правовая квалификация ≠ предмет/основание **+ её последствия для уже достигнутого титула** (F.11); запрет одновременного изменения; истребование у участников; обязательность практики Пленумов; недостоверность ≠ подложность; полномочия адвоката в АПК; злоупотребление правом по инициативе суда; связь с ППВС № 23 «О судебном решении»). Используется в фазе 2 этого скилла (блоки a, b, c, d, g).

Скилл анализирует материалы дела и формирует структурированную правовую позицию: основания требований/возражений, сильные и слабые стороны, оценку рисков, стратегию усиления. Работает с Opus. Каждый вывод — в аудируемом формате.

## Предварительные условия

- Дело инициализировано: `.vassal/case.yaml` существует.
- Документы приняты и проиндексированы.
- **Рекомендуется:** завершить `legal-review` (для наличия файлов в `.vassal/analysis/`).
- Если `legal-review` не выполнен — скилл работает, но предупредит: «Правовой анализ не проведён, рекомендуется запустить legal-review для более точной позиции».

## Входные данные

1. **case.yaml** — стороны, предмет, суд.
2. **index.yaml** — реестр документов.
3. **analysis/** — все файлы правового анализа (если есть).
4. **md-зеркала** — ключевые документы (договор, претензия, иск, отзыв, позиции сторон).
5. **Предыдущие позиции** — все файлы `*позиция.md` из корня дела (если есть, для обновления).
6. **Вводная Сюзерена** — за кого работаем (истец/ответчик), какие требования, акценты.

## Алгоритм

### Фаза 0 — Проверка консистентности ФС ↔ индекс

Перед загрузкой контекста выполни Phase 0 по правилу из [shared/conventions.md](../../shared/conventions.md) → раздел «Проверка консистентности ФС ↔ индекс (Phase 0)». При обнаружении рассинхрона предложи Сюзерену запустить `update-index`. Если Сюзерен выбрал «продолжить» -- зафиксируй в выходном артефакте, что позиция строится на устаревшем индексе.

### Фаза 1 — Загрузка контекста

1. Прочитай `.vassal/case.yaml` — определи: кто наш клиент, какая роль (истец/ответчик), предмет спора. Возьми `inn`/`name` оппонента из `parties[]` -- понадобится в шаге 4.1.
2. Прочитай `.vassal/index.yaml`.
3. Загрузи все файлы из `.vassal/analysis/` (если существуют).
3.1. **Хук `study-evidence`:** среди файлов `.vassal/analysis/` — фактологическое досье `evidence-dossier.md`. Если оно есть — используй как приоритетный источник фактуры (факты, суммы, роли со ссылкой на лист; кросс-сверка реквизитов) для блока b (доказательственная база) и блоков c/d (сильные/слабые стороны). Если досье нет — предложи Сюзерену (**не блокируя**) собрать его через `study-evidence`: позиция без прочитанной фактуры рискует быть «гладкой, но пустой». При отказе строй позицию на зеркалах как прежде, пометив «фактура не верифицирована study-evidence».
3.2. **Хук `revise-position` (фильтр отозванного):** ты только что загрузил **весь** `.vassal/analysis/` (п.3) -- прежде чем принять его за истину, прочитай `.vassal/analysis/retractions.md` (если есть) и **исключи** отозванные выводы / факты / практику по правилу из [shared/conventions.md](../../shared/conventions.md) → «Леджер отзывов позиции (revise-position)». Это не даёт воскресить исправленную ранее ошибку из осевшего в служебном слое старого вывода. При наличии замены -- бери новую формулировку из леджера.
4. Загрузи md-зеркала ключевых документов:
   - Договор + допсоглашения
   - Претензия / ответ на претензию
   - Акты, накладные, платёжные документы
   - Переписка сторон
   - Процессуальные документы обеих сторон (если дело уже в суде)
4.1. **Загрузи глобальный профиль оппонента** (если есть) -- по правилу из [shared/conventions.md](../../shared/conventions.md) → раздел «Глобальная память (кросс-дельная)»:
   - Разрезолви `$VASSAL_GLOBAL_DIR` (по умолчанию `~/.vassal-global/`).
   - Имя файла: `counterparties/inn-{ИНН}.md` (если ИНН есть в `case.yaml`); иначе fallback `counterparties/noinn-{slug-name}.md`.
   - Если файл существует -- загрузи. Это даёт фон для блока «Прогноз аргументов оппонента» (фаза 2 блок e): какие доводы этот оппонент уже выдвигал в твоих прошлых делах, какие шаблонные тактики использует. Без глобального профиля прогноз строится только по текущему делу.
   - Если файла нет -- работай без, не падай.
5. Загрузи предыдущие позиции из корня дела — все файлы по glob `{корень}/*позиция.md` (если есть — для обновления, а не создания с нуля). Сортируй по дате в имени, последняя — текущая. Папка `.vassal/positions/` **не используется** (исторический артефакт, в актуальной версии плагина все позиции живут только в корне дела).
6. Если Сюзерен дал вводную — прочитай и зафиксируй.

### Фаза 2 — Анализ (Opus)

Каждый вывод — в аудируемом формате (см. `shared/conventions.md`).

> **verify-before-assert** (см. `shared/conventions.md`): сверь содержание ключевых документов по md-зеркалам/оригиналам **до** формулирования оснований и сильных/слабых сторон — не строй довод на предположении о содержании (типичный провал: линия защиты на непрочитанном документе). Цитируемая практика обязана резолвиться в зеркало/индекс дела; неподтверждённую локально помечай «не подтверждено — сверить до подачи». Непроверяемое → флаг-задача, не вывод.
> **Дисциплина качества анализа (E.7, см. `shared/conventions.md`):** пункт Пленума/Обзора сверяй **дословно** (п.2 — номер верен ≠ содержание верно); цитата ВС/ВАС/КС из коннектора (CasusLegal/vasrf) — со **стабильным `case_id`** для сверки по id, а не тематическим перезапросом (п.5); процессуальные ходатайства, которых сторона не заявляла, — **гипотеза с флагом** (п.3, блок g); для профучастника — **повышенный стандарт осмотрительности** (п.4, блок d).

#### a) Предмет и основания требований

**Для истца:**
- Какие требования заявляем (основной долг, неустойка, проценты, убытки, иное)
- Фактическое основание каждого требования (какие факты подтверждают)
- Правовое основание (нормы ГК, специальных законов)
- Расчёт суммы требования (если возможно из документов)

⚠️ **При оценке правовой квалификации** -- свериться с [references/key-doctrines.md §1-2](references/key-doctrines.md): изменение правовой квалификации (например, со взыскания убытков на неосновательное обогащение) не считается изменением предмета/основания (п. 25 ППВС № 46); однако одновременное изменение предмета **и** основания **запрещено** (тот же п. 25). Если предлагается «дозаявить» новое требование с новой фактической базой -- это новый иск, а не уточнение текущего.

⚠️ **Последствия квалификации для уже достигнутого (F.11).** Проверка выше отвечает на вопрос «допустима ли переквалификация **процессуально**». Отдельно ответь на другой: **что эта квалификация ломает в уже полученном по делу.** Пройдись по списку достигнутого и по каждому пункту спроси, совместим ли он с предлагаемой квалификацией:

- полученный титул (решение, судебный приказ, исполнительный лист);
- процессуальная замена взыскателя / правопреемство (ст. 48 АПК);
- принятые обеспечительные меры;
- включённое в реестр требование; признанная оппонентом или судом часть требований;
- вступивший в силу акт по связанному спору (преюдиция).

**Боевой пример (дело Соколова, фаза 3).** Квалификация требования как **регресса** разрушила бы уже полученную процессуальную замену взыскателя: регресс — **новое** обязательство с самостоятельным основанием, а замена взыскателя предполагает переход **того же** требования. Процессуально переквалификация была допустима (п. 25 ППВС № 46) — по последствиям она обнуляла добытый титул. Плагин этого не поймал; поймал Сюзерен, пойдя в коннектор по своей инициативе. Чек-лист достигнутого и разбор теста «регресс — новое обязательство» — [references/key-doctrines.md §1](references/key-doctrines.md), подраздел «Обратная сторона: последствия квалификации для уже достигнутого».

Несовместимость найдена → это **не** стоп-сигнал, а **развилка для Сюзерена**: покажи обе ветки («квалификация A сохраняет {что}, но слабее по {чему}; квалификация B сильнее по существу, но обнуляет {что}») и вынеси в риски (блок f) с критичностью [!]. Молча выбрать «более сильную» квалификацию нельзя — цена решения выходит за рамки текущего требования.

**Госпошлина — расчёт и запись (F.7).** `build-position` — владелец поля `case.amounts.court_fee`, а значит и владелец расчёта (решение Сюзерена 2026-07-19). Не переноси цифру из старого судебного акта, чужого иска или по памяти — **открой справочник**:

1. Секция — по [`shared/category-routing.md §3.4`](../../shared/category-routing.md) → [`legal-review/references/filing-fees.md`](../legal-review/references/filing-fees.md); профиль берётся из `case.category`.
2. Считай **по каждому обращению отдельно**: иск (§1.1 по цене иска — шкала со ступенями, либо §1.2 для неимущественных и приравненных) **+** заявление об обеспечении иска (30 000 ₽ **за каждое**, пп. 17 п. 1 — отдельно, не в составе иска) **+** прочие заявления. Обособленные споры в банкротстве — 50 % от пошлины по пп. 1 (пп. 9 п. 1).
3. Проверь льготы (§1.4 для АС / §2.4 для СОЮ — работник по трудовому спору освобождён) и основания отсрочки / рассрочки / снижения (§4).
4. Запиши итог в `case.amounts.court_fee` и покажи **расчёт, а не только результат**: «{цена иска} → {секция справочника} → {формула} = {сумма}». Так ошибка видна Сюзерену на preview.
5. Цена иска не подтверждена материалами → **не выдумывай**: `court_fee` остаётся `null`, а в стратегию (блок g) уходит ACTION ITEM «уточнить цену иска и рассчитать пошлину до подачи».

⚠️ Боевой промах, который закрывает этот блок: справочник был актуален (ред. ФЗ-259 от 08.08.2024) и содержал нужную строку, но его никто не открыл — пошлину взяли «на глаз» из старого судебного акта и ошиблись в 3,9 раза (30 193 ₽ вместо 117 760 ₽).

**Для ответчика:**
- Какие требования предъявлены к нам
- Какие возражения можно заявить по каждому
- Встречные требования (если основания есть)

#### b) Доказательственная база

Для каждого факта, который нужно доказать:

| Факт | Бремя доказывания | Имеющиеся доказательства | Достаточность | Что усилит |
|------|-------------------|-------------------------|---------------|------------|
| Заключение договора | истец | Договор поставки №1045 от 28.11.2025 | достаточно | -- |
| Поставка товара | истец | УПД ЦБ-3823 + ТН ЦБ-574, УПД ЦБ-3848 + ТН ЦБ-577 | достаточно | акт сверки |
| Просрочка оплаты | истец | расчёт задолженности, гарантийное письмо | достаточно | акт сверки |

**ВАЖНО:** В источниках указывать названия документов с датами, а не doc-ID. Документ читает человек, а не агент.

#### c) Сильные стороны позиции

Для каждой:
- В чём сила аргумента
- На какие документы опирается
- Какую норму подкрепляет
- Судебная практика (если известна из контекста)

⚠️ **Обязательная проверка** ([references/key-doctrines.md §4](references/key-doctrines.md)): по каждому ключевому правовому вопросу проверить наличие разъяснения ППВС / Президиума ВС РФ / Обзора. Если есть -- цитировать с правильным форматом ([cassation/references/vs-rf-citation-format.md](../cassation/references/vs-rf-citation-format.md)). Игнорирование разъяснения 1 инст. -- автоматическое основание для апелляции. ППВС № 46 от 23.12.2021 прямо обязывает АС анализировать практику Пленумов и Президиума ВС РФ. **Дословно (E.7 п.2):** прежде чем сослаться на конкретный пункт, сверь его **дословный текст** (номер верен ≠ содержание верно -- боевой промах: п. 47 ППВС № 50 процитирован как про запрет выезда); источник -- B.3-reference / коннектор / web-whitelist; не сверено → «пункт не сверён дословно -- проверить».

#### d) Слабые стороны и уязвимости

Для каждой:
- В чём уязвимость
- Как может использовать оппонент
- Можно ли нейтрализовать (и как)
- Насколько критично ([!] критичная | [*] существенная | [ ] управляемая)

⚠️ **Повышенный стандарт осмотрительности (E.7 п.4).** Если наш клиент или оппонент -- **профессиональный участник** (профучастник торгов, лицо, для которого сделка -- обычная деятельность), оценивай уязвимости по **повышенному** стандарту: дефекты / основания недействительности, очевидные профессионалу при должной осмотрительности, могли быть известны ему **раньше** -- это сдвигает **начало течения давности** и оценку добросовестности. Не занижай довод о давности, презюмируя «обычную» осмотрительность там, где сторона -- профессионал (боевой промах: недооценён довод о давности для профучастника торгов).

#### e) Прогноз аргументов оппонента

- Какие возражения / требования вероятно заявит оппонент
- На чём они будут основаны
- Как на них отвечать (контраргументы)

**С учётом глобального профиля оппонента** (если загружен в фазе 1 шаг 4.1): отдельно отметь, какие из прогнозируемых доводов **уже наблюдались** у этого оппонента в прошлых твоих делах (с указанием номеров дел) -- это сильный сигнал, что они появятся снова. И наоборот, новые для него доводы -- помечать как «нетипично, проверить на блеф / реальная новая стратегия».

#### f) Оценка рисков

Для каждого требования / позиции:

| Требование | Вероятность удовлетворения | Обоснование | Ключевой риск |
|-----------|---------------------------|-------------|---------------|
| Основной долг | высокая (80%) | документы в порядке | пропуск давности |
| Неустойка | средняя (50%) | могут снизить по 333 ГК | несоразмерность |

Общая оценка: перспективы дела с позиции нашего клиента.

#### g) Стратегия усиления позиции

Конкретные рекомендации:
- Какие доказательства получить
- Какие аргументы развить
- Какие ходатайства заявить -- в т.ч. **ходатайство об истребовании у оппонента** ключевых документов по [references/key-doctrines.md §3](references/key-doctrines.md) (п. 38 ППВС № 46 -- истребование возможно у самих участников спора; конкретные реквизиты документа указывать не обязательно).
  - ⚠️ **Не достраивай неподанные ходатайства (E.7 п.3).** Ходатайство / процессуальный довод, которого сторона **не заявляла** и нет во вводной Сюзерена, -- это **гипотеза**, а не готовый довод: помечай «гипотеза -- подтвердить у Сюзерена». Опасные «резервные» (восстановление срока, зачёт, признание части) -- с явным предупреждением о риске: напр. заявить восстановление срока = **признать** пропуск (боевой промах: сгенерирован вредный «резервный» довод о восстановлении срока, которого сторона не просила). Стратегия вправе предлагать ходатайства -- в этом её ценность, -- но не выдавать выдуманное за решённое.
- Какие экспертизы / запросы инициировать
- При систематической недобросовестности оппонента (затягивание, формализм, заявления без оснований) -- **рассмотреть применение ст. 10 ГК + ст. 41 АПК** по [references/key-doctrines.md §7](references/key-doctrines.md) -- суд вправе по собственной инициативе признать поведение злоупотреблением правом.
- Стоит ли предлагать мировое (и на каких условиях)

### Фаза 3 — Preview

7. Покажи Сюзерену краткую сводку:

```
ПРАВОВАЯ ПОЗИЦИЯ: {название дела}
Роль: {истец / ответчик}

Требования:
  1. Основной долг — {сумма} (перспектива: {оценка})
  2. Неустойка — {сумма} (перспектива: {оценка})
  ...

Госпошлина (F.7): {сумма} — {цена иска} → filing-fees.md §{X} → {формула}
  {+ обеспечительные меры: 30 000 × {N} заявлений, пп. 17 п. 1 — отдельно от иска}
  {| не рассчитана: цена иска не подтверждена — ACTION ITEM в стратегии}

{Если квалификация меняется/уточняется — блок:}
⚠️ Последствия квалификации (F.11): квалификация как {A} затрагивает уже достигнутое —
   {что именно: титул / замена взыскателя / обеспечение / включённое требование}.
   Ветка A: {что сохраняем, чем жертвуем}. Ветка B: {то же наоборот}. Нужно твоё решение.

Сильные стороны: {N} аргументов
Слабые стороны: {M} уязвимостей ({X} критичных)

Общая оценка: {оценка перспектив}

Рекомендации: {K} пунктов по усилению

Сохранить?
```

8. Дождись подтверждения. Если Сюзерен корректирует — внеси правки.

**Хук `revise-position` (не блокирующий).** Если при корректировке (п.8) Сюзерен **отозвал вывод из прежней аналитики**, не относящийся к текущей регенерации (напр. ошибочный вывод в `qualification.md` от `legal-review`, устаревший довод в старой позиции) -- новые `position-*`-файлы его не содержат, но он остаётся в **других** analysis-файлах, и read-хук на леджер отфильтрует его, только если отзыв записан. Предложи, не блокируя сохранение:
> «Отозвано: {что}. Новая позиция это учла, но в других файлах памяти дела (`.vassal/analysis/`) вывод мог остаться. Записать отзыв в леджер через `/vassal-litigator:revise-position "{формулировка}"`, чтобы нижестоящие скиллы его не воскресили?»

Решение -- Сюзерена; факт фиксируй в `history.md`.

### Фаза 4 — Apply

**Два уровня сохранения** (паттерн из [shared/conventions.md](../../shared/conventions.md) → «Двухуровневое сохранение для аналитических скиллов»):

**a) Единый документ для Сюзерена** — case root folder: `{ГГГГ-ММ-ДД} {тип} позиция.md`

Файл с полной позицией (формат — см. ниже). Тип:
- `Начальная` — первичная позиция
- `Обновленная` — обновлённая после новых документов
- `Ответ` — ответ на конкретный документ оппонента

**b) Отдельные файлы для агента** — `.vassal/analysis/position-{ГГГГ-ММ-ДД}-{секция}.md`

Параллельно сохрани каждый аналитический блок отдельным файлом. Это нужно `prepare-hearing`, `appeal`, `cassation` для прямого чтения структурированных секций без парсинга «человечного» сводного `.md`. Состав файлов:

| Файл | Содержание (из фазы 2) |
|---|---|
| `position-{дата}-evidence-base.md` | Доказательственная база -- таблица «Факт / Бремя / Доказательства / Достаточность / Что усилит» (из блока b) |
| `position-{дата}-strengths.md` | Сильные стороны позиции (из блока c) |
| `position-{дата}-weaknesses.md` | Слабые стороны и уязвимости с критичностью (из блока d) |
| `position-{дата}-opponent-forecast.md` | Стратегический прогноз аргументов оппонента (из блока e) -- общерамочный, не привязан к конкретному заседанию (тактический -- зона `prepare-hearing`) |
| `position-{дата}-risks.md` | Оценка рисков по требованиям (из блока f) |
| `position-{дата}-strategy.md` | Стратегия усиления, ACTION ITEMS (из блока g) |

Каждый файл начинается с frontmatter:
```yaml
---
type: position-section
section: evidence-base | strengths | weaknesses | opponent-forecast | risks | strategy
date: ГГГГ-ММ-ДД
case: "{номер дела}"
position_summary: "{ГГГГ-ММ-ДД} {тип} позиция.md"
supersedes: null | "{предыдущий файл этой секции из .vassal/analysis/}"
refs: ["doc-NNN", "doc-MMM", ...]   # doc-id всех источников, упомянутых в файле
---
```

Дальше — содержимое блока в аудируемом формате (как в сводном). Источники указывать **в формате двойных ссылок** `Название документа от ДД.ММ.ГГГГ [doc-NNN]` (см. [shared/conventions.md](../../shared/conventions.md) → «Двойные ссылки»).

Если по позиции какой-то блок отсутствует (например, для ответчика без встречного иска -- `evidence-base.md` неприменим в полном виде) — файл всё равно создаётся, но с явной пометкой `not_applicable: <причина>` во frontmatter и одной строкой в теле, чтобы цепочка ссылок не ломалась.

**c) Обновление карточки и истории**

9. Обнови `case.yaml` — поля только в зоне ownership `build-position` (см. [shared/conventions.md](../../shared/conventions.md) → «Ownership полей case.yaml»: `case.qualification.applicable_norms`, `case.amounts.{claim, court_fee}`).
10. Добавь запись в `.vassal/history.md`:
    ```
    ### {ЧЧ:ММ} — Правовая позиция (build-position)
    - Тип: {initial / updated / response-to-...}
    - Сводный файл: {ГГГГ-ММ-ДД} {тип} позиция.md
    - Файлы для агента: position-{дата}-{evidence-base, strengths, weaknesses, opponent-forecast, risks, strategy}.md в .vassal/analysis/
    - Требования: {перечень с оценками}
    - Общая оценка: {перспективы}
    - Критичные риски: {перечень}
    - Рекомендации: {кол-во} пунктов
    ```

11. Спроси Сюзерена: «Сформировать .docx?» Если да — оформи через `arbitrum-docx` (опц.). Это **аналитический** документ (позиция), **вне охвата `format-doc`** (тот покрывает документы стороны в суд); основной формат аналитики — `.md`.

**Хук `argument-map` (не блокирующий).** После сохранения позиции предложи, не блокируя завершение:
> «Позиция готова. Собрать из неё **карту доводов** — таблицу по узлам спора (довод оппонента · наш контрдовод: норма/практика/обстоятельства · вывод) в двух версиях (чистая для суда + рабочая с откровенной оценкой узлов)? Запусти `/vassal-litigator:argument-map` — он возьмёт свежие `position-*-{strengths,weaknesses,opponent-forecast}` и подтянет практику через CasusLegal.»

Решение — Сюзерена; запуск не откладывает сохранение позиции.

## Обновление позиции

При повторном запуске (после новых документов или документов оппонента):

1. Загрузи предыдущую сводную позицию из case root folder + предыдущий комплект `.vassal/analysis/position-{предыдущая-дата}-*.md`.
2. Загрузи новые документы (по дате добавления в index.yaml).
3. **Покажи diff:** что изменилось в оценке по сравнению с предыдущей позицией -- по каждой секции (evidence-base, strengths, weaknesses, opponent-forecast, risks, strategy).
4. Сохрани новую версию:
   - Сводный `.md` в корне дела с `supersedes: "{путь к предыдущей сводной}"` в frontmatter (обновлённая дата в имени файла).
   - Комплект `.vassal/analysis/position-{новая-дата}-*.md` -- в каждом файле frontmatter `supersedes: "{путь к предыдущему файлу этой секции}"`.
5. Предыдущий комплект **не удаляется** -- это история эволюции позиции (см. «Идемпотентность»).

## Идемпотентность

Каждый запуск создаёт новый файл с датой. Предыдущие позиции не удаляются — это история развития позиции. Аналогично -- предыдущие комплекты `.vassal/analysis/position-{дата}-*.md` сохраняются, новые лишь ссылаются на них через `supersedes`.

## Постусловия

Перед завершением `apply` Opus-субагент сверяется с чек-листом из [shared/conventions.md](../../shared/conventions.md) → «Постусловия скиллов» категория 2 (аналитические). Минимум для `build-position`:

- Сводный `{ГГГГ-ММ-ДД} {тип} позиция.md` в корне дела создан, валидный YAML frontmatter.
- Все 6 файлов `position-{дата}-{секция}.md` созданы в `.vassal/analysis/` (или явно помечены `not_applicable: <причина>`).
- Сводный файл и детальные файлы согласованы: каждое утверждение в сводном имеет корреспондирующий блок в одном из детальных, и наоборот; источники в обоих местах -- двойные ссылки.
- `supersedes`-цепочка корректна: у первой позиции в деле -- `null`, у каждой последующей -- путь к файлу предшественника той же секции.
- `case.yaml` остался валидным; обновлены только поля в зоне ownership (см. фазу 4 п.9).
- **Госпошлина (F.7):** если по делу предстоит подача — `case.amounts.court_fee` рассчитан **по `filing-fees.md`** с показанным расчётом, либо явно оставлен `null` с причиной и ACTION ITEM. Цифра «из головы» или перенесённая из чужого документа — не проходит.
- **Последствия квалификации (F.11):** если позиция меняет или уточняет правовую квалификацию требования — в артефакте есть явный ответ, что она делает с уже достигнутым (титул, замена взыскателя, обеспечение, включённое требование); несовместимость вынесена как развилка Сюзерену, а не решена молча.
- Запись в `.vassal/history.md` зафиксирована.

## Граничные случаи

- Нет analysis/ → работай, но предупреди о рекомендации legal-review.
- Нет документов оппонента → строй позицию только на своих, пометь: «Позиция оппонента неизвестна».
- Спор неденежный (признание, обязание) → адаптируй структуру (вместо «сумма» — «предмет требования»).
- Множество требований → группируй и оценивай каждое отдельно.
- Встречный иск → включи анализ и требований, и встречных требований.

## Маршрутизация моделей

- **Opus**: весь анализ (фаза 2) — стратегическая юридическая работа.
- **Sonnet**: preview, форматирование, сохранение.
- **Haiku**: не используется.
