# Intake — Приём материалов клиента

Этот скилл обрабатывает пакет файлов от клиента: сохраняет оригиналы, извлекает текст, переименовывает, раскладывает по тематическим папкам, создаёт md-зеркала и обновляет индекс дела. Работает по принципу **preview → apply**: сначала показывает план, выполняет только после подтверждения Сюзерена (юриста).

## Предварительные условия

- Дело инициализировано: существует `.vassal/case.yaml`. Если нет — предложи запустить `/vassal-litigator:init-case`.
- Существует папка `Входящие документы/`. Если нет — создай.
- Установлены зависимости для OCR. Запусти `${CLAUDE_PLUGIN_ROOT}/scripts/setup.sh` если ещё не запускал в этой сессии.

## Алгоритм

### Фаза 1 — Сохранение оригиналов

1. Прочитай `.vassal/case.yaml` — тебе нужны стороны и предмет спора для контекста.
2. **Источник файлов — `Входящие документы/`** (основной). **Папка пуста** → отработай единую последовательность из [shared/conventions.md](../../shared/conventions.md) → «Папка „Входящие документы/"» → «Папка пуста — единое поведение трёх приёмников (F.15)»: посмотреть наружу (корень дела и принесённые папки) → посмотреть в `history.md` → предложить `update-index`, если дело разложено вручную → и только потом «положите файлы и запустите снова». Раньше каждый из трёх приёмников делал лишь свою треть этой последовательности.
   - **Область (опция, E.5):** если в `$ARGUMENTS` задана подпапка «Входящие документы/{…}/» или список файлов — бери только их (`shared/conventions.md` → «Маршрутизация приёма по источнику» → «Область»); без аргумента — вся папка + триаж (шаг 9-бис).
3. Для каждого файла во «Входящие документы/» вычисли `content_hash` (sha256 от содержимого). **Байтовую копию в `raw/` не делай** — это client-режим манифеста (оригиналы клиента сохраняются внешне: рабочая копия в «Материалы» + архив Сюзерена; см. `shared/conventions.md` → «Cowork-first robustness»). Оригиналы во «Входящие документы/» на этом этапе не трогаем (очистка — фаза 5, после подтверждения).
4. Зафиксируй **манифест** для каждого файла в записи индекса: `origin.name` (исходное имя), `origin.received` (дата получения), `origin.intake_batch = intake-{ГГГГ-ММ-ДД}`, `content_hash`, `source: client`, `raw_pristine: false`. Эта запись и есть сохранение оригинала (раньше делалась байтовая копия в `raw/`).

### Фаза 2 — Извлечение и анализ

5. **Рекурсивный обзор**: получи список всех файлов (включая вложенные папки).
6. **Распаковка архивов**: zip, rar, 7z, tar.gz — распакуй в подпапку с именем архива. Добавь содержимое в список обработки.
7. **Извлечение текста — по протоколу `shared/ocr.md`** (vision основной; кэш по `content_hash` — vision один раз; PDF с текстовым слоем → программно; скан / изображение / мусорный текстовый слой → vision по PNG из `outputs/`; длинный скан → структурный режим; критичные реквизиты с low confidence → `needs_manual_review` + флаг). Запусти `${CLAUDE_PLUGIN_ROOT}/scripts/extract_text.py <файл>` — он вернёт `text` / `needs_vision` / `vision_pages` / `content_hash`; при `needs_vision: true` прогони vision (рендер `--render` → Read PNG) по §3 протокола. Для каждого файла определи `extraction_method` и `confidence`.
   - **Сбой извлечения — по машинному сигналу `error_class` (E.14), не по догадке «похоже на битый».** `extract_text.py` различает причину отказа:
     - `retryable: true` (`error_class: not_materialized`) — файл **не синкнут** OneDrive (cloud-only заглушка). Сначала прочитай его через **Read** (материализует файл), затем **ретрай с паузой** (`shared/conventions.md` → «Cowork-first robustness» правило 2). Не поднялся после 1–2 попыток → оставь во «Входящие», сообщи «файл {имя} пока не читается — вероятно, не синхронизирован OneDrive; откройте его/дождитесь синка и запустите intake снова» и **продолжи с остальными** (пакет не блокируется). Это прямое лечение боевого ложного «битого PDF».
     - `error_class: corrupt` — PDF **реально повреждён** → ветка «битый файл» (см. «Граничные случаи»): не индексируй, оставь во «Входящие», сообщи «повреждён, перезалейте».
     - `error_class: empty` — 0-байт → пропусти (см. «Граничные случаи»).
   - **Дисциплина транскрипции (E.13, `shared/ocr.md` §3.1).** Зеркало — **дословный транскрипт**, не пересказ: реконструкция и домысливание норм запрещены (маркеры пересказа в речи субагента → заменить на `[Нечитаемо]` + `needs_manual_review`); роли сторон и ненапечатанные ссылки на нормы/практику субагент **не выдумывает** (боевые случаи: домысленные «ст. 269–272 АПК», путаница банкрота и АУ — сверку «кто есть кто» ведёт `study-evidence`, не приём).
   - **Детект составного пакета (E.6.2) — по машинному сигналу, не на глаз.** `extract_text.py` для многостраничного PDF возвращает `composite_suspected: true` + `composite_reasons` (повтор заголовка-якоря «ПЛАТЁЖНОЕ ПОРУЧЕНИЕ»/«ДОГОВОР»/«ОПРЕДЕЛЕНИЕ»/«СЧЁТ-ФАКТУРА» в шапке ≥2 страниц; множественные ИНН). **Если флаг взведён — обязательно** покажи в preview предложение split на отдельные `doc-NNN` (каждый со своим типом), с указанием причин из `composite_reasons`. Флаг ложный (иск с приложениями единым PDF, где split всё же уместен, — редко) — Сюзерен снимает в preview. Дополнительно, независимо от флага: если сам видишь склейку разного процессуального смысла (жалоба + проект мирового + заявление об утверждении) — тоже предложи split. **Не индексируй пакет как один `doc-NNN`, если его части имеют разный смысл** (иначе отдельная нить — напр. мировое, или чужой платёж — потеряется/прицепится). Разделённые части идут в триаж источника (см. ниже): часть «не наша» (чужой платёж на 2-й странице) отсеивается там.
8. **Анализ имён файлов** — используй подход file-renamer (три категории):
   - Полная информация из имени → сразу можно переименовать
   - Частичная → дочитать из содержимого начало документа (первая страница / 2000 символов)
   - Имя бесполезно → полный анализ начала через чтение
9. **Категоризация** — определи для каждого файла:
   - Тип документа (из таксономии: договор, претензия, платёжное-поручение и т.д. — см. `shared/conventions.md`)
   - Дату документа
   - Стороны (отправитель, адресат)
   - В какую подпапку `Материалы от клиента/` поместить

Делегируй Haiku-субагентам (model: "haiku") массовую обработку: извлечение текста, первичную категоризацию, переименование. Sonnet оставь себе для принятия решений о систематизации.

**Контрольная сумма в финальном ответе субагента (E.13, `shared/ocr.md` §3.1 п. 3).** Для документов с **разбивкой + итогом** (платёжное поручение, расчёт цены иска/неустойки, опись, смета, таблица платежей) Haiku-субагент сверяет «сумма единиц = заявленный итог» и **выносит результат сверки в финальный ответ**. Совпало → перенос как есть. Разошлось (боевой случай: сводка 2 305 200 при разбивке 3 390 000) → **оба числа переносятся как в документе** (не «сглаживать» в одно) + строка-флаг в EXTRACTION NOTES зеркала + `needs_manual_review: true`. Сверка **внутридокументная**; кросс-документная (∑ платёжек = цена иска) — зона `study-evidence`, не приёма.

**Триаж по источнику (E.5, перед Preview).** Примени `shared/conventions.md` → «Маршрутизация приёма по источнику»: классифицируй каждый файл (`client` / `opponent` / `court` / `unclear`), сверяя отправителя/подписанта с `case.yaml.parties[]` (отправитель уже определён в шаге 9). `intake` — владелец **`client`**. Файлы `opponent`/`court` **не обрабатывай** (иначе документ оппонента ляжет как клиентский, без пристинной копии — порча дела и chain of custody); `unclear` — уточни у Сюзерена. Если область задана аргументом (шаг 2) — триаж всё равно прогоняется, но файлы в заданной области по умолчанию считаются своими.

**Сверка принадлежности документа делу (F.19, вместе с триажем).** Триаж выше отвечает на вопрос «чей документ», а не «этого ли дела». Примени `shared/conventions.md` → «Маршрутизация приёма по источнику» → «Вторая ось: принадлежность документа делу»: сверь найденные в тексте **№ дела, ИНН/ОГРН, наименования сторон, суд** с `case.yaml`. Флаг поднимает **только положительное противоречие** (в документе есть реквизит другого дела). **Отсутствие реквизитов — не сигнал:** у памятки, справки, черновика их не бывает по природе (боевой случай: две аналитические справки выброшены как «чужие», а именно они вскрыли ошибку по подсудности). Найдено противоречие → **не отбраковывай и не двигай файл**: отдельный блок в Preview + вопрос Сюзерену (Фаза 3). Файлы `source: own-work` под сверку не попадают.
- **Замкни цепочку по `composite_suspected`:** после split (или отказа от него) **каждая часть** проходит сверку принадлежности отдельно — именно так всплывает чужой платёж на 2-й странице склеенного PDF.

**Решающие документы: второе чтение критичных полей (F.18).** Определи, есть ли в пакете решающие документы — по классу (закрытый список) или по пометке Сюзерена: `shared/conventions.md` → «Решающие документы: вторая голова». Для каждого такого документа критичные поля (доли, проценты, голоса, кворум, суммы, ИНН/ОГРН, даты, № дела) перечитывает **вторая, независимая голова** по протоколу `shared/ocr.md` §3.2:
- **Сначала посмотри, откуда взялась цифра.** Документ извлечён программно (`method ∈ {pdf-text, docx-parse, text-read}`) → вторая голова не нужна: сверяй **машинно** — значение в зеркале обязано буквально встречаться в `text` из `extract_text.py`. Вторая голова включается там, где реквизит прочитала модель (`vision` / `structural`); гибрид — постранично (`shared/ocr.md` §3.2);
- Opus-субагент (`model: "opus"`) получает **тот же PNG** и список полей, но **не получает транскрипцию Haiku** — иначе подтвердит прочитанное и петля самооценки просто удлинится;
- третья, немодельная нога — `--spot-check … --expect` (`shared/ocr.md` §6), вердикт выносит программа;
- **сверяешь ты**, сопоставлением значений; спрашивать модель «согласна ли ты со вторым чтением» запрещено;
- совпало → строка-след в EXTRACTION NOTES; разошлось → поле в `low_confidence_fields` + `needs_manual_review: true` + **оба** прочтения в зеркале (какое верное — решает Сюзерен по оригиналу) + строка в Preview; вторая нога недоступна → так и пиши, «не проверено» за «проверено» не выдавай.

Пометку Сюзерена принимай двумя путями: из `$ARGUMENTS` (`решающие: <файл>, <файл>`) и ответом на вопрос в Preview. Боевой случай, ради которого правило заведено: выписка из реестра акционеров прочитана как «100 %, единственный акционер» вместо 15 % — контрольной суммы «разбивка + итог» в таком документе нет, и прежние три ступени защиты молчали.

**Проверка платёжного документа: плательщик ≠ клиент (E.6.1).** Для файлов типа `платёжное-поручение` / `выписка` / `справка-из-банка` извлеки **плательщика** (поле 60 платёжки: наименование + ИНН/КПП; назначение платежа) и сверь с нашим клиентом (`case.yaml` — наш клиент + его ИНН). Если **плательщик ≠ клиент** (платёж внёс кто-то другой, как в бою — госпошлину за заявителя внесло третье лицо) — подними **флаг** в EXTRACTION NOTES зеркала и отдельной строкой в Preview: «⚠ платёж внесён третьим лицом ({плательщик}, ИНН {…}) — проверьте доверенность/назначение (п. 1 ст. 45 НК)». Если в деле уже есть документ типа `доверенность` с этим плательщиком — укажи связь («см. `doc-NNN`»). **Границы:** это флаг **физического расхождения реквизитов**, не правовая оценка допустимости (та — `legal-review`); `intake` не блокирует и не достраивает вывод, только поднимает на видимый уровень. Это **не** `needs_manual_review` (тот — про качество извлечения).

**Пометка правовых ссылок в документе-рассуждении (F.8).** Если документ **сам рассуждает о праве** — претензия, чужой иск / отзыв / жалоба, аналитическая справка, досье куратора, письмо с правовой позицией, заключение — и содержит ссылки на нормы (статьи, пункты законов, реквизиты судебных актов), добавь в EXTRACTION NOTES зеркала строку:

> ⚠ Правовые ссылки в этом документе — **гипотезы автора**, а не проверенный источник. Сверить **содержание** нормы с текстом закона перед использованием (`shared/conventions.md` → verify-before-assert, правило 6). Найдено: {перечень ссылок}.

**Границы.** Это пометка о **происхождении** ссылки, не правовая оценка и не проверка (проверяют `legal-review` / `build-position`). Приём нормы **не сверяет**, **не блокирует** и **не** ставит `needs_manual_review` (тот про качество извлечения) — по образцу флага платежа третьим лицом (E.6.1). Смысл: не дать ссылке выглядеть установленной только потому, что она напечатана в документе из материалов дела. Боевой случай — «п. 11 ст. 25.1» из документа клиента разошёлся по всем артефактам двух дел.

11. Дождись подтверждения. Если Сюзерен корректирует — внеси правки.

**Чужие файлы в Preview (E.5, offer-handoff).** Если триаж нашёл `opponent`/`court`-файлы — покажи их **отдельным блоком** и предложи: «N файлов похожи на документы оппонента/суда — оформить через `add-opponent` сейчас?»
- **Да** → доведи клиентскую часть (Фазы 4–5: свои файлы → зеркала/индекс → «На удаление/»), затем **передай управление** `add-opponent`, ограниченному этими файлами (список файлов как область). К моменту передачи во «Входящие» остаются только они.
- **Нет** → оставь их во «Входящие» (**не** копируй, **не** двигай оригиналы, **не** заводи записи) + сообщи «оформите через `/vassal-litigator:add-opponent`».

Вся пачка оказалась `opponent`/`court` (клиентских 0) → `intake` сам ничего не пишет, сразу предложение handoff. Это прямое предотвращение боевого случая «intake пометил отзыв ответчика как client».

**Файлы, возможно, из другого дела (F.19).** Показывай **отдельным блоком** с указанием конкретного противоречия («в тексте № А33-30539/2026, в карточке А33-30593/2026») и тремя вариантами: **обработать всё равно · оставить во «Входящие» · это документ другого дела**. Ответа нет (неинтерактивный прогон) → файл остаётся во «Входящие» с пометкой. **Молча не отбраковывай и в «На удаление/» не переноси ничего из этого блока** — правило существует ровно потому, что боевой прогон выбросил как «чужие» две ключевые справки.

**Решающие документы (F.18).** Показывай результат второго чтения по каждому критичному полю: совпало (✓) или расхождение (⚠ с обоими значениями). Тут же задавай вопрос о **ручной пометке**: «есть ли в пакете ещё документы, на цифрах которых держится позиция?» — названные Сюзереном получают `decisive_reason: manual` и проходят то же второе чтение до apply. Вторая нога не отработала (нет Opus-субагента, tesseract недоступен, таймаут) — скажи об этом прямо, а не пропускай строку.

### Фаза 4 — Apply (пофайловый commit, E.6.3)

**Модель: инкрементальный commit + рестарт-безопасность.** Индекс пишется **не одним блоком в конце**, а по каждому файлу сразу после его копии+зеркала. Тогда обрыв на N-м файле оставляет **согласованное** состояние (первые N−1 полностью в деле: файл + зеркало + запись), а повтор добирает остаток. Это прямое следствие боевого случая, где apply упал на 14-м из 24 и оставил 13 файлов «висеть» вне индекса.

12. **Рестарт-безопасность (в начале Apply).** Прежде чем писать — сверь по `content_hash`, что уже сделано прошлым (возможно, оборванным) прогоном: для каждого запланированного файла проверь, нет ли уже (а) записи в `index.yaml` с этим `content_hash`, (б) рабочей копии в «Материалы от клиента/», (в) зеркала в `.vassal/mirrors/`. Полностью готовые (все три) — **пропусти** (дубли не заводить, `next_id` не жечь). Частично готовые (например, файл скопирован и зеркало есть, а записи в индексе нет — след обрыва) — **доведи** (допиши недостающую запись индекса для уже лежащего файла, не копируя повторно). См. «Идемпотентность».
13. Создай подпапки в `Материалы от клиента/`.
14. **Обрабатывай файлы по одному** (порядок детерминирован). Для каждого файла — атомарная тройка «копия → зеркало → запись индекса»:
    - **a. Копия.** Скопируй файл в целевую папку с новым именем. Сопоставление имён — по **нормализованному** имени (E.6.5, `shared/conventions.md` → «Cowork-first robustness»: юникод-пробелы NBSP/thin/medium-math не должны ронять матч). Read-back размера > 0 (правило 1 «Cowork-first»).
    - **b. Зеркало.** Создай md-зеркало в `.vassal/mirrors/` (формат — `shared/mirror-template.md`; ID `doc-{NNN}` из текущего `next_id`; делегируй Haiku, `model: "haiku"`).
    - **c. Запись индекса — сразу.** Допиши запись этого файла в `.vassal/index.yaml` со всеми полями (`shared/index-schema.yaml`): `origin` (исходное имя, дата получения, пакет), `content_hash`, `source: client`, `mirror_stale: false`; **поля качества документа** `seal`/`signature`/`completeness`/`quality`/`needs_manual_review` (см. ниже «Поля качества документа» — юрисдикция `intake`; `catalog` их только читает); для решающих документов — `decisive`/`decisive_reason`/`verified_fields` (F.18; пустой `verified_fields` при `decisive: true` означает «второе чтение не состоялось», а не «состоялось и чисто»); инкрементируй `next_id`. Провалидируй YAML (`yaml.safe_load`, правило 5 «Cowork-first»). Только после успешной записи переходи к следующему файлу.
    - **Судебные акты — запись в каталог образцов (F.22).** Если принятый документ имеет `source: court` и тип `решение` / `определение` / `постановление`, занеси **указатель** в `$VASSAL_GLOBAL_DIR/samples/{файл по таблице категорий}.yaml` — правило, закрытый список полей и таблица имён шардов: [shared/conventions.md](../../shared/conventions.md) → «Глобальная память» → «Каталог образцов». Поля: номер дела · путь **относительно корня дела** · `doc_type` · дата · `origin: court` · `produced_by: null` · `relation_type` и `applicable_norms[]` из `case.qualification`. Судебные акты — самый ценный ориентир каталога: по ним видно, что суд принял, а что отклонил, и конфиденциальности клиента они не затрагивают (акты публикуются в КАД). **Документы оппонента (`source: opponent`) в каталог не заносятся** — их паттерны ведёт глобальный профиль оппонента. **Ни текста, ни сумм, ни абсолютного пути.** Категория не заполнена или вне таблицы → не заводить, сказать Сюзерену. Глобальная память недоступна → **не падать**: приём состоялся, факт отметить в `history.md`.

    - Флаг платежа третьим лицом (E.6.1), если был, — в EXTRACTION NOTES зеркала.
    - Расхождение двух чтений (F.18) — **оба** значения в теле зеркала + строка в EXTRACTION NOTES; «правильное» не выбирай.
    - Реквизиты другого дела (F.19), если Сюзерен велел обработать файл всё равно, — строка в EXTRACTION NOTES: «реквизиты другого дела: {что}; приобщено по решению Сюзерена от {дата}».
15. Если файл в тройке дал ошибку — **останови обработку этого файла**, оставь его во «Входящие» (Фаза 5 его не тронет), зафиксируй причину для отчёта и **продолжи** с остальными (уже закоммиченные не откатываются — они согласованы).
16. Добавь запись в `.vassal/history.md` (сколько обработано; если прогон был доводкой оборванного — отметь, что достроено по `content_hash`).

### Фаза 5 — Очистка «Входящие документы/»

17. Перемести из `Входящие документы/` все файлы, которые были успешно обработаны в фазе 4, в папку `На удаление/`.
    - **Используй `mv`, не `rm`** (`rm` на маунте недостоверен; `cp`+обнуление плодит 0-байтные пустышки — см. `shared/conventions.md` → «Cowork-first robustness» и «Папка „На удаление/"»):
      ```bash
      mv "Входящие документы/файл.pdf" "На удаление/файл.pdf"
      ```
    - Оригинал не теряется: байт-идентичная рабочая копия уже создана в «Материалы от клиента/» (фаза 4), плюс манифест (`origin` + `content_hash`) в индексе.
    - Если в `Входящие документы/` были вложенные папки — обрабатывай рекурсивно, но только обработанные файлы.
    - Если какой-то файл не был обработан (ошибка, пропущен) — **оставь его** во «Входящие документы/».
    - При совпадении имён в `На удаление/` — добавь суффикс `(2)`, `(3)`.
    - После очистки сообщи: «Обработанные файлы перемещены в На удаление/. Манифест в индексе сохранён.».

## Формат имени файла

```
ГГГГ-ММ-ДД Отправитель Описание.расширение
```

Примеры:
- `2025-06-01 ООО Ромашка Договор поставки №47.pdf`
- `2025-09-15 ООО Ромашка Претензия.pdf`
- `2025-06-05 ООО Лютик Платёжное поручение №123.pdf`

Убирай кавычки из названий: `ООО «Ромашка»` → `ООО Ромашка`. Расширение файла никогда не меняй.

## Поля качества документа

Эти поля заполняет `intake` (а также `add-evidence`, `add-opponent`) при создании записи в `index.yaml`. Они описывают **физическое качество документа**, а не его правовое содержание -- это юрисдикция `intake`, потому что только здесь есть полный текст зеркала и метаданные OCR.

| Поле | Тип | Как определить |
|------|-----|----------------|
| `seal` | `true` / `false` | `true`, если в зеркале есть маркер `[Изображение: печать]`, `[М.П.]`, `м.п.`, либо OCR-фрагмент с характерным круговым текстом организации. Иначе `false`. |
| `signature` | `true` / `false` | `true`, если в зеркале есть маркер `[Изображение: подпись]`, либо есть подпись-расшифровка («Иванов И.И.» в подписной зоне), либо реквизит «/подпись/». Иначе `false`. |
| `completeness` | `full` / `partial` / `fragment` | `full` -- весь документ извлечён (есть начало, тело, концовка с подписями/печатью). `partial` -- утеряна часть (нет последней страницы, обрыв в середине, отсутствует приложение, упомянутое в тексте). `fragment` -- только разрозненные куски (например, скан страницы 3 из 10 без 1-2 и 4-10). |
| `quality` | `high` / `medium` / `low` | Критерий по `shared/ocr.md` §7 (метод извлечения + число `[Нечитаемо]` + low-conf критичные поля): `high` -- метод `pdf-text`/`docx-parse`/`text-read` ИЛИ чистый vision без `[Нечитаемо]` и low-conf полей. `medium` -- единичные `[Нечитаемо]` ИЛИ 1–2 критичных поля на низком confidence. `low` -- множественные `[Нечитаемо]`, ≥3 low-conf полей, структурный режим или обрезанный рендер -- одновременно ставится `needs_manual_review: true`. |

Делегируй заполнение этих полей тому же Haiku-субагенту, который создаёт зеркало (он уже видит полный текст и не требует повторного чтения файла).

⚠ **Это самооценка — и её границы надо понимать (F.18).** Субагент оценивает качество **собственной** работы: если он прочитал цифру уверенно и неверно, `quality` останется `high`, а `needs_manual_review` — `false`. Дёшево и приемлемо для обычного документа. Единственный вход в цепочку, **не зависящий** от уверенности первого субагента, — второе чтение критичных полей решающего документа (`shared/ocr.md` §3.2). Поэтому поля качества и `verified_fields` заполняются **разными** головами и смешивать их нельзя.

**`needs_manual_review` — от машинного сигнала, не от догадки (E.6.4).** Если `extract_text.py` вернул `method ∈ {pdf-text, docx-parse, text-read}`, в `page_statuses` нет `scan`/`garbage` и `low_confidence_fields` пуст — документ извлечён программно без OCR, `needs_manual_review` **обязан быть `false`**. **Не помечай PDF с полноценным текстовым слоем «скан без сверки»** (боевой промах: doc-027/024/026 с текстовым слоем зря ушли в nmr — а nmr затем блокирует цитирование по `verify-before-assert` правилу 4). nmr ставится только по реальным основаниям `shared/ocr.md` §7: скан/мусор-слой, структурный режим, обрезанный рендер, low-conf критичное поле. Гибрид (`method: pdf-text+vision`) — nmr по скан-части, не на весь документ.

**Чего НЕ делать:** не определять качество правовой составляющей документа (наличие существенных условий, правомерность подписи, юридическую силу) -- это зона `legal-review`. Поля интейка фиксируют только что физически удалось извлечь и в каком виде.

## Идемпотентность

Если intake уже запускался (есть файлы в `Материалы от клиента/` и записи в `index.yaml`):
- Проверь, какие файлы из нового пакета уже обработаны — **по `content_hash`** (надёжный ключ: не зависит от имени/пакета; см. `shared/conventions.md` → «Дедупликация по content_hash»). `origin.name` + `intake_batch` — вспомогательно для отчёта.
- Обработай только новые
- Сообщи: «N файлов уже были обработаны ранее, пропускаю»

**Доводка оборванного apply (E.6.3).** Тот же `content_hash`-механизм делает apply рестарт-безопасным: если прошлый прогон оборвался на середине пакета (файлы/зеркала есть, записей индекса нет — «висящая» половина), повторный запуск в Фазе 4 шаг 12 распознаёт частично готовые файлы и **достраивает** недостающие записи индекса, не копируя повторно и не заводя дубли. Полностью готовые (файл + зеркало + запись) — пропускает.

## Граничные случаи

- Пустой архив → пропусти, сообщи
- Файл нулевого размера (`error_class: empty`) → пропусти, сообщи
- Файл с повреждённой кодировкой → пометь `needs_manual_review: true`, создай зеркало с тем, что удалось извлечь
- **Не материализован (cloud-only OneDrive)** (`error_class: not_materialized`, `retryable: true`) → это **не** «битый файл» (E.14а). Сначала прочитай через **Read** (материализует), затем ретрай с паузой (`shared/conventions.md` правило 2); не поднялся после 1–2 попыток → оставь во «Входящие документы/», сообщи «файл {имя} пока не читается — вероятно, не синхронизирован OneDrive; откройте его/дождитесь синка и повторите». Пакет не блокируется. Раньше такой файл ложно рапортовался «битым».
- **Реально битый / неоткрывающийся файл** (`error_class: corrupt`: `pymupdf` не открывает вовсе — PDF без EOF-маркера, повреждённое дерево страниц, мусорные байты; не берётся даже в режиме восстановления) → НЕ индексируй, оставь во «Входящие документы/», сообщи: «файл {имя} повреждён, не открывается — перезалейте рабочую версию». Иной случай, чем повреждённая кодировка текста (там зеркало всё же создаётся) и чем не-материализованный (тот ретраится, а не отбраковывается).
- Очень большой файл / длинный скан → структурный режим по `shared/ocr.md` §5 (полнотекст головы + подписной + структурный скелет; `extraction_method: structural`, `needs_manual_review: true`). Длинный **текстовый** PDF (>50 стр.) → первые 10 страниц, пометь `[... документ содержит N страниц, извлечены первые 10 ...]`. Опорные документы (договор/иск/решение) полнотекстятся целиком.
- Дубликат имени после переименования → добавь суффикс `(2)`, `(3)`
- **Юникод-пробелы в имени файла** (E.6.5) → имена из банк-клиентов/гос-выгрузок содержат экзотические пробелы (NBSP `U+00A0`, thin `U+2009`, medium-math `U+205F` и др.) вместо обычных; байтовое сопоставление «план ↔ файл на диске» на них падает (`AssertionError`, обрыв apply). **Матчь по нормализованному имени** (все пробельные → обычный пробел, схлопнуть, `strip`) — см. `shared/conventions.md` → «Cowork-first robustness». Целевое имя при копировании тоже нормализуй.
- **Документы оппонента/суда во «Входящие»** (триаж, E.5) → `intake` их **не обрабатывает** (не помечает `source: client`, не двигает оригинал); показывает отдельным блоком и предлагает `add-opponent` (offer-handoff, Фаза 3). При отказе — оставляет во «Входящие».
- **Документ, похожий на «из другого дела»** (F.19) → флаг и вопрос, **никогда** молчаливый отсев: файл остаётся на месте до решения Сюзерена. Противоречием считается только **найденный** реквизит другого дела; отсутствие реквизитов (памятка, справка, черновик, фото) — не противоречие.
- **Решающий документ, для которого не отработала вторая голова** (F.18) → документ индексируется штатно, но `verified_fields` остаётся пустым, и это **прямо сказано** в отчёте и в EXTRACTION NOTES («критичные поля не прошли второе чтение — сверить по оригиналу»). Не выдавай непроверенное за проверенное и не откладывай весь пакет из-за одной недоступной ноги.
